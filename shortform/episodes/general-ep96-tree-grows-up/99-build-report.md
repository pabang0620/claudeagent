## 방향(중력 기준 뿌리/줄기) 검증

78화 SunflowerTrackingDiagram이 줄기 기울기를 해의 위치에서 삼각함수로 직접 계산해 방향
오류를 구조적으로 차단한 방식을 그대로 따랐다. `GravitropismDiagram.tsx` 안에서:

- 화면 좌표계의 "true 아래"는 항상 `angleDeg=180`, "true 위"는 항상 `angleDeg=0`으로 상수
  고정(SunflowerIcon과 동일 각도 표기).
- `potTiltDeg`(씨앗이 처음에 놓인 방향)는 뿌리·줄기의 **초기** 방향만 정하고, **최종** 수렴
  각도(뿌리 180 / 줄기 0)에는 전혀 관여하지 않는다 - `lerpAngleShortest(초기각도, 180 또는 0,
  growT)`로 항상 같은 결과로 수렴하게 코드가 강제한다. 손으로 "이 방향이 아래"라고 지정하는
  코드가 없으므로, 방향을 잘못 지정할 여지 자체가 없다.

검증은 두 가지 방식으로 했다.

1. **s4에서 potTiltDeg=180(똑바로)/90(옆으로 눕힘)/0(뒤집힘) 세 가지를 동시에 렌더**해 화면에서
   바로 비교했다. 스틸(`s4_end`, growProgress≈1 시점)에서 세 패널 전부 뿌리(갈색)는 아래로
   완전히 수직, 줄기(초록)는 위로 완전히 수직으로 수렴하는 것을 육안으로 확인했다(세 패널이
   시각적으로 동일한 최종 형태 - 세로 직선 + 위쪽 잎/아래쪽 갈래).
2. **s8(tiltCorrectProgress)에서 potTiltDeg=60(기울어진 화분)으로 렌더**해 밑동은 기울어진
   채(뿌리 기저가 위쪽, 줄기 기저가 아래쪽 - 씨앗이 심긴 그대로) 남고 새 성장분만 true up/
   true down으로 재교정되는 것을 스틸(`s8_mid`, `s8_end`)에서 확인했다. `s8_end`(correctP≈0.9)
   시점에 줄기 끝이 거의 수직 위, 뿌리 끝이 거의 수직 아래에 도달함을 육안으로 확인했다.

두 검증 모두 렌더 전 `remotion still` 스틸 선점검 단계에서 수행했다(원칙 5 "렌더 전 스틸
선점검"). 코드 구조상 potTiltDeg 값과 무관하게 항상 같은 최종 방향으로 수렴하므로, 이 두
케이스에서 맞았다는 것은 다른 각도 값에서도 동일하게 성립함을 뜻한다(구조적 보장 - 각도별
개별 하드코딩이 아니라 하나의 수식이 모든 각도에 적용됨).

## TTS/립싱크

- s1(무성)을 제외한 s2~s8 전 구간. s3~s8은 프로필 기본값(`ko-KR-SunHiNeural`, rate+20%/
  pitch+30Hz), s2(리액션 "우와, ... 왜 다 이 방향으로만 자라는 거지?")만 rate+32%/pitch+55Hz로
  별도 합성했다(원칙 1, `script-ko.json`에 구간별 rate/pitch를 얹어 `tts.py` 1회 호출로 처리 -
  `tts.py`가 이미 세그먼트별 오버라이드를 지원해 스크립트를 새로 짜지 않았다).

  s3~s8은 다이어그램 중심 장면(사람 캐릭터 없음)이라 `rms_mouth.py`는 파이프라인 표준 절차대로
  실행해 `ko_mouth.json`을 생성했으나 s2 외에는 사용하지 않는다.
- 내레이션 실측 합계 41.040s (s2 5.760 / s3 4.728 / s4 5.064 / s5 7.152 / s6 5.664 /
  s7 6.816 / s8 5.856), 여기에 s1 무성 2.5s를 더한 본편 합계 45.367초, 대본 추정치(약 49초)
  보다 짧게 나왔으나 원칙 4에 따라 늘리지 않고 실측 그대로 냈다.
- s2->s3 전환에만 0.6초 확장 여백(원칙 4의 5번), 나머지는 프로필 기본 여백 0.2초.
