### 신규 제작 (REGISTRY.md 등록 완료)
- `CarWindowView` (`assets/props/CarWindowView.tsx`) - 차창 소품. 프레임은 고정, 안쪽 풍경(대각선 평행사변형 스피드라인)만 흐른다. REGISTRY에 자동차 실내·이동감 소품이 없어 신규 제작(대본이 "신규"로 표기).
- `SensoryConflictDiagram` (`assets/props/SensoryConflictDiagram.tsx`) - 눈·귀 두 신호가 충돌했다가 다시 맞아떨어지는 오버레이. HeadNerveDiagram·VoicePathDiagram과 같은 원칙(새 얼굴 안 그림, BustActor 위에 배지+신호선만 오버레이). REGISTRY 사전 조회 결과 "두 신호가 충돌/불일치" 구조를 갖는 기존 자산이 없어 신규 제작(대본이 "신규"로 표기).

신규 자산 2개 모두 `assets/props/index.ts`(끝에 추가), `assets/REGISTRY.md`(SneezeReflexDiagram 행 다음에 2행 추가)에 등록 완료. 기존 줄은 건드리지 않았다(끝에 덧붙이기만). REGISTRY에 이미 `general-ep41`의 `SneezeReflexDiagram` 항목이 등록돼 있었다 - 다른 세션에서 41화가 이미 준비된 것으로 보이며, 이 화 작업과는 무관하고 건드리지 않았다.

REGISTRY 사전 조회 결과: `HeadNerveDiagram`·`VoicePathDiagram`·`SneezeReflexDiagram`은 모두 "한 지점에서 나가는 신호"를 다루지만, "서로 다른 두 지점에서 시작한 신호가 충돌한다"는 이 화의 핵심 구조와는 달라 재사용하지 않고 신규 제작했다(대본이 이미 이렇게 판단해 승인됨).

## 검수 체크리스트 (관찰 기록)

`sceneStarts`로 계산한 각 구간의 시작 직후(+15프레임, 크로스페이드 fadeIn 8프레임을 피함) + 중간/정점 지점 위주로 18장(intro/title/s1~s8/outro)을 최종 `episode-ko.mp4`에서 ffmpeg로 추출해 확인했다(`out/frames-ko/`).

- **자막 화면이탈**: 추출한 18장 전체 확인. 가장 긴 줄("창밖 먼 곳을 보면 좀 나아지는 이유도 그래서예요")도 포함해 모든 자막이 좌우 여백을 두고 박스 안에 들어온다.
- **장면 전환 캐릭터 잔상**: 캐릭터가 등장하는 장면(s1/s2/s6/s7/s8)과 다이어그램만 있는 장면(s3/s4/s5)이 번갈아 나오는데, 각 전환 직후(+15프레임) 프레임에서 이전 장면 잔상 없음.
- **등장 전 요소가 점처럼 남음**: 1차 렌더에서 `S5BrainConfused`의 큰 브레인 아이콘과 `S8Screen`의 휴대폰 아이콘이 **완전히 안 보이는(점이 아니라 통째로 사라지는)** 결함을 f635/f706/f1155/f1238에서 발견 - 아이콘 앞에 그린 `position:'absolute'` 배경 div가 CSS 스태킹 규칙상 DOM 순서와 무관하게 static 배치된 형제(아이콘)보다 항상 나중에(위에) 페인트되어 아이콘을 완전히 가린 것이 원인이었다. 두 아이콘에 `style={{position:'relative'}}`를 추가해 재렌더 후 f635/f706/f1155/f1238에서 아이콘이 정상적으로 보이는 것을 확인했다.
- **라벨이 화면 밖에서 잘림**: 없음. 1차 렌더에서 s3의 "눈: 정지"/"귀: 움직임" 라벨과 눈 배지가 캐릭터 안테나(머리카락)와 겹치는 결함을 f330/f415에서 발견 - `SensoryConflictDiagram`의 `EYE_BADGE_RAW.y`를 300->318로, `BRAIN_RAW.y`를 180->100으로 내리고/올리고, 라벨 y오프셋을 -122/-96 -> -150/-160으로 늘려 재렌더 후 f415/f502/f567에서 겹침이 해소된 것을 확인했다.
- **요소끼리 겹침**: 1차 렌더에서 s8의 휴대폰 아이콘 배경 박스가 캐릭터 얼굴 오른쪽과 겹치는 결함을 f1155에서 발견 - 바스트 크기·위치와 화면 박스 위치를 재배치(캐릭터 좌측/화면 우측으로 명확히 분리)해 재렌더 후 f1155/f1238에서 겹침이 해소된 것을 확인했다.
- **화면 하단 여백 과다**: 1차 렌더에서 s6(전신 멀미 리액션)이 화면 상단에 큰 빈 공간을 남기고 캐릭터가 작게 아래쪽에 몰려 있는 것을 f829에서 발견 - 캐릭터 크기(760->900)와 바닥선(1560->1460)을 키우고 올려 화면을 더 채우도록 조정, 재렌더 후 f779/f829에서 개선을 확인했다. s3/s4/s7(다이어그램 장면)은 다이어그램이 화면 중상단~중앙에 위치하고 캡션까지 사이 공간이 남는 편이나, 다른 화의 다이어그램 장면과 비슷한 범위 안이라 별도 조정하지 않았다.
- **애니메이션 최대 상태에서 겹침**: s4 스파크 정점(f567, conflictProgress≈1)에서 눈·귀 배지와 스파크가 겹치지 않고 각자 자리를 유지하는 것을 확인. s7 체크 표시 완성 시점(f1134, resolveProgress≈1)에서 체크 배지·눈/귀 배지·"일치" 라벨이 서로 겹치지 않는 것을 확인.
- **팝인 중간 프레임**: `SensoryConflictDiagram`의 배지 팝인(scale 0.3->1, opacity 함께 증가)과 체크 배지 팝인 모두 중간 진행도에서 점 아티팩트 없이 부드럽게 커지는 것을 f415(badgePop 진행 중)에서 확인.
- **음량**: `ffmpeg -af loudnorm=print_format=summary` 실측 - Input Integrated -13.3 LUFS, Input True Peak -1.9 dBTP. 다른 화와 유사한 범위(내레이션 volume=1.6, SFX volume=0.75~0.8).
- **SFX 타이밍·레벨 (원칙 7 객관 지표)**: `realize_ding`(s2 로컬 6.4~6.8초 구간)과 `bubble_pop`(s4 로컬 18.85~19.15초 구간) 근처에서 astats Peak level이 주변 무음/발화 구간 대비 상승하는 것을 실측 확인(realize_ding 구간 Peak -12.8dB vs 직전 구간 -16.2dB, bubble_pop 구간 Peak -6.6dB). SFX 개별 소스 파일의 원본 피크(realize_ding -4.18dB, bubble_pop -1.68dB)에 Episode.tsx의 volume 배수(0.8/0.75, 각각 -1.94dB/-2.5dB 감쇠)를 적용한 유효 피크는 각각 약 -6.1dB/-4.2dB로, 내레이션 트랙의 유효 피크(ko_s4.mp3 원본 피크 -4.04dB에 volume=1.6 즉 +4.08dB를 더한 약 0dB, 전체 믹스 Peak level -1.94dB와 부합)보다 낮다 - SFX가 내레이션보다 작다는 원칙을 만족한다.
- **자막 스타일**: `assets/theme.ts`의 `CAPTION_STYLE`/`FS.caption`(50px)을 그대로 썼고, `wrapCounts`(ko 20자 상한)로 줄바꿈했다. `CAP_BOTTOM` 공용 상수 그대로 사용.
- **화면 문자열 언어별 분기**: 이 화는 한국어만 제작하므로 ko/en 대조는 해당 없음. 화면에 노출되는 모든 문자열("눈: 정지", "귀: 움직임", "일치", 제목, 다음 편 안내)은 컴포넌트에 하드코딩하지 않고 전부 `strings.ts`의 `STRINGS.ko`에서 읽는다(컴포넌트 안에 문자열 리터럴 없음).
- **캐릭터 윤곽선과 배경 명암비**: 모든 장면이 밝은 `PlainBg`(하늘색~흰색) 배경이라 어두운 배경용 글로우 처리는 필요하지 않았다(원칙 5 예방책 (a)는 밤하늘 등 어두운 배경 전용이며 이 화는 해당 없음).

### 이 화 전용 시각 주의사항 이행 확인
- 눈이 보는 것과 몸이 느끼는 것의 불일치: s1에서 정지한 캐릭터(화면 왼쪽) vs 빠르게 흐르는 창밖 풍경(화면 오른쪽 `CarWindowView`)의 좌우 대비로 표현(f138 확인). s3~s4에서는 눈 배지(고정)와 귀 배지(흔들림)의 움직임 차이로 같은 대비를 반복(f415/f567 확인).
- 귀 속 평형기관을 사실적 해부도로 그리지 않음: `SensoryConflictDiagram`은 실제 캐릭터 얼굴 위에 원형 배지 2개 + 신호선만 얹는 방식이라 해부학적 묘사가 전혀 없다(f415 확인).
- 속이 울렁거리는 것을 불쾌하게 그리지 않음: s2/s6 모두 표정(eyeOpen 축소, blush)과 팔 자세 변화로만 표현했고, 점 무리·구토 관련 사실적 묘사 없음(f243/f829 확인).
- 신호는 굵은 선 몇 가닥: `SensoryConflictDiagram`의 신호선은 각 배지->뇌까지 2가닥(눈·귀 각 1개)뿐이고 점 무리를 쓰지 않았다(f415/f567 확인).
