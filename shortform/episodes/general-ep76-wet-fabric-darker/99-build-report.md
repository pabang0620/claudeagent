## 1. 자산

### 기존 라이브러리 재사용 검토 (오케스트레이터 지시 - 22화 LightScatterDiagram, 30화 RainbowDiagram 우선 확인)

- `general-ep22-blue-sky`의 `LightScatterDiagram` - "빛이 매질을 통과하며 갈라지고 흩어진다"는
  화살(선+화살촉) 어휘를 그대로 계승했다(`Arrow` 헬퍼를 동일 레시피로 로컬 재구현 - 좌표계와
  gap 구조가 달라 그대로 import하지 않고 지역성 우선 원칙에 따라 새로 작성). 다만 이 컴포넌트
  자체는 "산란 지점에서 사방으로/한 점으로 화살이 튀는" 구조만 다루고, "섬유 틈이 공기->물로
  바뀌며 표면 반사가 내부 흡수로 전환된다"는 이 화의 핵심 구조(wetProgress로 매질 자체가
  바뀌는 것)는 다루지 않아 재사용하지 못하고 새로 만들었다.
- `general-ep30-petrichor`의 `RainbowDiagram` - 빛이 매질(물방울) 안에서 굴절·내부반사하는
  구조를 참고했으나, 그 화는 "각도"가 핵심이고 이 화는 "표면 반사 vs 내부 흡수"라는 전혀 다른
  대비가 핵심이라 재사용하지 못했다.
- 결론: 두 후보 모두 부분적 설계 원칙(독립 레이어, undefined면 안 그림, 화살 어휘)만 계승하고
  `props/WetFabricLightDiagram.tsx`를 새로 만들었다.

### 신규 제작 (REGISTRY.md "추록" 절에 등록 완료, `assets/props/index.ts`에 export 추가)

- `assets/props/WetFabricLightDiagram.tsx` - 이 화 핵심 다이어그램(s2/s3/s4 공용). 섬유 단면을
  물결치는 굵은 곡선 3가닥(fiber bundle)으로 표현하고, `wetProgress`(두 틈이 파랗게 차오르며
  잔물결선이 생김), `scatterProgress`(마른 표면 3지점에서 빛 화살이 위쪽 부채꼴로 흩어짐),
  `absorbProgress`(같은 입사점에서 안으로 꺾여 들어가 4번 꺾이는 지그재그 경로를 그리고, 깊어질수록
  화살 불투명도가 낮아지다 마지막에 pigmentColor 점으로 "흡수됨"을 표시)를 독립 진행도로 받는다.
  "빛이 매질 표면/내부에서 반사되거나 흡수된다"는 구조를 갖는 다른 소재(젖은 도로, 종이 등) 전반
  재사용 가능성을 명시해 등록했다.
- s1/s7의 `WetShirt`(티셔츠 실루엣 + clipPath로 셔츠 안에만 갇히는 진해지는 반점)와 s1/s6의
  `Droplet`(teardrop 물방울), s6의 도로·나무 패널(단순 rounded rect + 오버레이 불투명도로
  젖으며 짙어짐)은 참고 이미지 없는 이 화 전용 단순 도형이라(원칙 0-1 벡터화 대상 아님) 재사용
  가능성이 낮다고 판단해 라이브러리로 승격하지 않고 `episodes/general-ep76-wet-fabric-darker/src/scenes.tsx`에
  로컬로 뒀다.

## 3. 렌더 전 스틸 선점검(`npx remotion still`)에서 잡은 결함

절대 프레임 13장(제목카드 중간 1 + s1 물방울 낙하/착지/반점완성 3 + s2 산란 중간/끝 2 + s3 물참/흡수시작
2 + s4 흡수중간/끝 2 + s5 막대 1 + s6 몽타주 1 + s7 마름중간/끝 2)을 뽑아 확인했다.

1. **s5 CompareBars 막대가 화면 밖으로 삐져나감**: `S5_BARS_X = CX - 90 = 450`, `pxPerUnit = 7`,
   최댓값 `value=92`(마른 상태)로 계산한 막대 길이가 644px라 오른쪽 끝이 `450+644=1094px`로
   화면 폭(1080px)을 14px 넘어갔다. 최댓값 막대가 중앙 정렬되도록 `S5_BARS_X`를
   `(1080-644)/2 ≈ 220`으로 수정해 재확인 - 두 막대(마른 상태 644px, 젖은 상태 280px) 모두
   좌우 여백을 두고 화면 안에 들어옴을 확인했다.
2. 그 외 결함 없음. s2/s3/s4의 `WetFabricLightDiagram` 화살 방향(표면에서 바깥으로 튀는 산란
   vs 안으로 꺾여 들어가 흡수되는 지그재그)이 스틸에서 의도대로 나오는지 프레임별로 직접
   확인했다 - s2는 위쪽 부채꼴로 튀는 화살, s3은 진입+첫 꺾임까지만(absorbProgress를 0.4로
   캡), s4는 4번 꺾이며 옅어지다 마지막에 짙은 점(pigmentColor)으로 마무리되는 것을 확인.
3. s1(WetShirt)에서 droplet이 착지하는 프레임(`dropletProgress=1`)에 정확히 맞춰
   물방울이 사라지고(`dropOpacity` 공식상 착지 순간 자연스럽게 0) 반점이 그 자리에서
   자라나는 것을, 착지 직전 프레임(로컬 30)과 착지 프레임(로컬 51) 두 장을 나란히 놓고 확인했다.
4. s6(비 온 도로 vs 젖은 나무)은 젖는 정도가 시간에 따라 실제로 진해지는 방향인지 초반(로컬
   15프레임)과 후반(로컬 140프레임) 두 장을 나란히 놓고 확인했다 - 초반엔 밝은 회색/황토색,
   후반엔 뚜렷하게 어두운 슬레이트/짙은 갈색으로 진행 방향이 맞음을 확인(원칙 5의 "차오름·
   빠짐 등 방향성 애니메이션은 시작-끝을 나란히 볼 것" 반영).

수정 후 s5 막대 프레임을 다시 뽑아 재확인 완료(`s5_bars_fixed.png`).

## 5. 검수 체크리스트 (관찰 기록)

- **자막 화면이탈**: `wrapCounts`(한국어 20자 상한) 계산 결과 스틸·최종 mp4에서 확인한 모든
  자막 줄이 자막 배지 안에 좌우 여백을 두고 들어옴(s2/s3/s4/s5/s6/s7 각 프레임에서 직접 확인).
- **장면 전환 시 잔상**: 캐릭터(Actor)를 쓰지 않는 3인칭 설명 전용 화라 캐릭터 잔상은 해당 없음.
  최종 mp4 프레임248(s1->s2 크로스페이드 중간)을 확인한 결과 셔츠(옅게)와 섬유 다이어그램(옅게)이
  표준 6프레임 크로스페이드로 자연스럽게 겹쳐 보이고, 자막 박스는 이중으로 겹치지 않고 진입하는
  s2 자막 하나만 보임을 확인.
- **등장 전 요소가 점처럼 남는지**: `WetFabricLightDiagram`의 모든 화살·물 표시는 opacity 기반
  reveal(scale 0 방식 미사용)이라 등장 전 잔점이 생기지 않음. s1/s7의 반점 또한 `spotT<=0.01`이면
  아예 렌더하지 않아(조건부 렌더) 등장 전 점 잔상이 없음을 코드로 확인.
- **라벨이 화면 밖에서 잘리는지**: s2/s3/s4의 `Label`(마른 섬유/물이 채운 섬유/흡수 증가)은
  `CX` 중앙 정렬로 폭이 좁아(최대 4글자) 잘림 없음을 확인. s6의 "비 온 도로"/"젖은 나무" 라벨도
  각 패널 중앙에 여유 있게 들어감을 확인.
- **요소끼리 겹침**: s5 막대 결함(3절 1번) 수정 후 재확인 - 라벨과 막대, 두 행(마른/젖은 상태)
  사이 겹침 없음. s1/s7 셔츠의 반점은 `clipPath`로 셔츠 실루엣 밖으로 번지지 않음을 확인
  (`s1_spot_grown.png`, `s7_shrink_mid.png`에서 셔츠 윤곽 밖으로 반점이 삐져나오지 않음을 확인).
- **화면 아래쪽 여백 과다**: s2~s4 다이어그램(DIAG_Y=470, 높이 680 -> 하단 y=1150)과 s1/s7
  셔츠(하단 y=1160)가 화면 세로 중앙~하단(안전영역 안)까지 채움을 확인. s5 막대(y=720~1080대),
  s6 패널(y=420~880대)도 과도한 하단 여백 없이 캡션 영역 위까지 이어짐을 확인.
- **음량**: `ffmpeg loudnorm` 측정 결과 Input Integrated -13.6 LUFS, Input True Peak -1.7 dBTP -
  다른 화 대비 특별히 작지 않음.
- **효과음 대 내레이션 피크 비교(원칙 7)**: `water_splash.mp3`(volume=0.85) 원본 max_volume
  -3.3dB -> 적용 후 환산 peak ≈ -4.71dB. `ko_s1.mp3`(narration, volume=1.6) 원본 max_volume
  -2.8dB -> 적용 후 환산 peak ≈ +1.28dB(디지털 게인 특성상 0dBFS를 초과하는 수치이나, 이는
  이 채널의 전 화 공통 narration volume=1.6 설정에서 항상 나타나는 값이고 실제 인코딩된 최종
  mp4의 True Peak는 -1.7dBTP로 클리핑이 관측되지 않았다) - 어느 계산으로도 효과음이 내레이션보다
  크지 않음을 확인.
- **캐릭터 윤곽선 대비**: 이 화는 캐릭터가 등장하지 않아(3인칭 설명 전용) 해당 없음.
