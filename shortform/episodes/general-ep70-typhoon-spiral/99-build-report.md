## 3. 회전 방향 검증 (이 화의 핵심 리스크)

**검증 절차**
1. **계산 지점을 1곳으로 한정.** `TyphoonSpiralDiagram.tsx` 안에 소용돌이 팔을 그리는 함수(`spiralArmPoints`)를 단 하나만 두고, 북반구용/남반구용 path를 손으로 각각 그리지 않았다. 반구에 따라 바뀌는 값은 `curlSignFor(hemisphere)`가 반환하는 부호(`1 | -1`) 하나뿐이다.
2. **부호의 근거를 기하학적 사실 하나로 한정.** SVG 좌표계는 y축이 아래로 증가하므로 `polarPoint(cx,cy,r,angle)`에서 angle이 커질수록 점은 화면상 시계방향(3시->6시->9시->12시)으로 이동한다 - 이 사실 하나에서 "각도 증가=시계, 각도 감소=반시계"가 정해지고, `curlSignFor('north')=-1`(반시계) / `curlSignFor('south')=1`(시계)로 반영했다.
3. **hemisphere 자체도 위치에서 계산.** `hemisphereAt(localCy, equatorY)`가 "적도선 y좌표보다 위/아래"로 북반구·남반구를 판정한다 - 62화 `EarthOrbitDiagram`의 `earthOrbitNorthTiltDot`(문자열로 반구를 못박지 않고 벡터 내적으로 계산)과 같은 설계다. s5(`HemisphereCompare`)에서 이 함수로 북쪽 패널·남쪽 패널의 반구를 각각 계산해 넘긴다.
4. **렌더 결과를 실제로 육안 확인.** `npx remotion still`로 s5(반구 비교) 프레임을 뽑아 확인한 결과, 지구본 위쪽(북반구) 소용돌이는 반시계 방향, 아래쪽(남반구) 소용돌이는 시계 방향으로 그려졌다. 좌표를 수치로도 재확인했다 - 북반구 팔(`base=0, curlSign=-1, twist=145`)의 각도가 t=0(0도, 3시 방향) -> t=0.5(약 -72.5도, 12~1시 방향) -> t=1(약 -145도, 10~11시 방향)로 감소하며 이동해, 시계 방향 기준 "3시->12시->10시"는 역방향 진행 즉 반시계 방향임을 확인했다.
5. s1/s2/s3/s4(메인 소용돌이, `hemisphere="north"` 고정)와 s5의 북반구 패널이 같은 `curlSignFor('north')` 값을 공유하므로, 두 곳의 회전 모양이 시각적으로도 일치하는지 대조했다 - 실제로 동일한 "S자형" 곡선 형태로 일치했다.

## 4. 스틸 선점검에서 잡은 결함 (렌더 전)

- **s6(욕조 속설) 레이아웃 결함**: 최초 설계는 배수구 아이콘 위에 곧바로 X 마크를 겹쳐 그렸는데, 이는 "배수구 모양이 진짜 원인이다"라는 올바른 설명 위에 "틀렸다"는 X를 찍는 것이 되어 **의미가 정반대로 뒤집히는 결함**이었다. `npx remotion still`로 뽑은 스틸에서 발견해, 왼쪽에 "회전 방향 때문?"이라는 틀린 가설(중립적 회전 아이콘)에 X를, 오른쪽에 배수구 아이콘(진짜 원인)을 X 없이 나란히 배치하는 구조로 재설계했다. 또한 최초 배치는 드레인 아이콘이 욕조 물 표면 위 허공에 붕 뜬 것처럼 보여 어색했는데, 두 아이콘을 욕조 위 여백에 나란히 놓고 라벨을 붙이는 방식으로 정리했다.
- **s6 아이콘 크기 불일치**: 배수구 아이콘(`DrainIcon`, viewBox 900 기준 반지름 130)과 새로 만든 회전 아이콘(고정 60px 반지름)의 화면 표시 크기가 서로 달라 보이는 문제를 스틸에서 확인 - `TyphoonSpiralDiagram`의 `width`를 415로 역산해(130 * 415/900 ≈ 60) 두 아이콘의 화면상 반지름이 비슷해지도록 맞췄다.

## 6. 검수 체크리스트 (관찰 기록)

- **자막 화면이탈**: mp4에서 뽑은 15개 프레임(각 구간 시작+정점) 전체를 확인, 좌우 여백을 두고 화면 안에 들어옴. 가장 긴 자막(s6 "배수구 모양 같은 힘이 더 커서")도 잘리지 않음.
- **장면 전환 시 캐릭터 잔상**: 이 화는 캐릭터(Actor)를 쓰지 않는 3인칭 설명 전용 화라 해당 없음. 다이어그램끼리의 크로스페이드 잔상은 6프레임(0.2초)의 표준 겹침으로, 다른 화와 동일한 정도.
- **등장 전 요소가 점처럼 남음**: `TyphoonSpiralDiagram`의 모든 레이어는 `undefined`면 그리지 않는 방식(opacity 0 처리 포함)이라 scale 0 잔점 문제 없음. f04(프레임 262, s2 시작 직후)에서 s1 잔여 스피럴이 옅게 겹쳐 보이지만 이는 크로스페이드 자체이지 "등장 전 잔점" 결함이 아님.
- **라벨이 화면 밖에서 잘림**: s2~s5의 상단 라벨("저기압 중심으로 빨려듦" 등)과 s5의 "북반구: 반시계"/"남반구: 시계"/"적도" 라벨 모두 화면 안에 완전히 들어옴(프레임 f05, f09, f11 확인).
- **요소끼리 겹침**: s6에서 회전 아이콘·X마크·배수구 아이콘·라벨 4개가 서로 겹치지 않게 좌우로 분리 배치했음을 f12~f14에서 확인.
- **화면 아래쪽 여백 과다**: 각 다이어그램을 화면 상단~중단에 크게 배치하고 자막이 하단 23% 지점에 위치해, 세로 9:16 화면의 중앙~하단까지 시각 요소가 채워짐(전 프레임 공통).
- **음량**: ffmpeg loudnorm 측정 결과 Input Integrated -13.6 LUFS, Input True Peak -1.9 dBTP - 너무 작지 않은 수준.
- **자막 스타일**: `assets/theme.ts`의 `CAPTION_STYLE`/프로필 기본값(흰 글자+검은 외곽선, 하단 23% 지점)을 그대로 사용, 별도 override 없음.
- **영어판 로케일 누출**: 해당 없음(한국어판만 제작).
- **캐릭터 윤곽선 대비**: 이 화는 캐릭터를 쓰지 않아 해당 없음. 다만 s7(다크 배경) 다이어그램은 `armColor={C.cream}`, `stroke={C.cream}`으로 override해 어두운 배경(`C.night`/`C.nightMid`) 위에서도 선이 뚜렷이 보이도록 조정했다(f15에서 확인).

이 화는 프로필이 general(공통)이라 별도 "프로필별 추가 체크" 절이 없다.
