## 발견·수정한 결함

1. **`SavannaBg`에 `children`을 전달했으나 렌더되지 않음** - `SavannaBg`(공용 배경 컴포넌트)는 `children` prop을 애초에 받지 않는 컴포넌트다(`SavannaBgProps`에 없음). s1/s2에서 `<SavannaBg><Actor/></SavannaBg>` 형태로 캐릭터를 자식으로 넘겼더니 캐릭터·자막이 전부 사라지고 배경만 보였다. `ep06`의 `Sky` 래퍼 패턴(형제 요소로 배경과 캐릭터를 나란히 배치)을 따라 `<><SavannaBg /><Actor/></>` 구조로 고쳤다(1차 렌더 후 f002/f004 프레임에서 발견, 2차 렌더로 수정 확인). `SavannaBg` 컴포넌트 자체는 건드리지 않았다(다른 화들이 이미 이 형제 패턴으로 쓰고 있어 공용 컴포넌트의 결함이 아니라 이 화의 호출 실수였다).
2. **`LightScatterDiagram`의 화살·광선 색이 배경과 거의 구분되지 않음** - (a) 등장 시 불투명도가 `local * 1.5`(및 `r * 1.6`)로 완만하게 올라가 화면 대부분의 시간 동안 반투명한 파스텔로 보였다(4배속으로 상향해 초반부터 뚜렷하게 보이도록 수정). (b) "산란 전 빛"을 나타내는 색이 `#FFF6DE`(거의 흰색)라 `PlainBg`의 옅은 하늘색 배경과 대비가 거의 없었다 - 이미 팔레트에 있는 `C.gold`로 교체했다. 두 수정 모두 렌더 후 프레임 검수(f009=402, s3 mid)에서 발견했다.
3. **s4(대낮 산란)에서 경로가 자동으로 gold->red 그라데이션이 되어 노을(s7) 전용 "빨간빛만 남는다" 메시지를 앞질러 스포함** - s4는 `surviveColor={C.gold}`로 override해 경로 색이 시종 일관 골드로 유지되도록 고쳤다(s7만 기본값 `LIGHT_RED`를 그대로 써서 "노을에서만 빨강이 남는다"는 대비를 지킨다).

## 기술 검증 (관찰 기록, 한국어만)

렌더 명령은 전부 `scripts/render.mjs`로 실행했고 출력은 `episodes/general-ep22-blue-sky/out/`에만 생성됨을 확인했다(공용 루트 `shortform/out/`에는 쓰지 않음 - `precheck.mjs`의 `SHAREDOUT` 경고는 다른 화(2026-08-20 타임스탬프)가 남긴 기존 파일이었고, 이번 렌더로 새로 생긴 것이 아님을 타임스탬프로 확인했다). `precheck.mjs`는 에러 0(경고 1 - 위 무관한 SHAREDOUT)으로 렌더를 진행했다.

- **자막 화면이탈**: f004(s2 mid, "하늘은 왜 맨날 파란 색일까"), f009(s4 mid), f011(s5 mid), f017/f018(s7), f020~f022(s8) 등 캡션이 표시된 모든 검수 프레임에서 텍스트 박스가 좌우 안전영역(`CAP_SIDE=70`) 안에 들어오는 것을 직접 확인. 좌우로 잘리는 프레임 없음.
- **장면 전환 시 캐릭터/다이어그램 잔상**: 각 장면 경계 프레임(예: f008=456=s4 시작, f002=753=s6 시작, f004=1063=s8 시작)에서 직전 장면이 크로스페이드 중(0.2초, 6프레임) 겹쳐 보이는 것을 확인 - 이는 `SceneSwitcher`의 의도된 크로스페이드 동작이며 다음 프레임(예: s4 local frame 10 부근인 f009=531)에서 정상적으로 새 장면으로 전환됨을 확인.
- **등장 전 요소가 점처럼 남아있는지**: `LightScatterDiagram`의 화살·산란 지점 전부 `opacity`+길이(length) 성장으로만 등장하며(`scale(0)` 방식 미사용), `PopIn`(눈 아이콘)도 공용 안전 헬퍼를 그대로 사용 - 등장 전 잔점 없음을 f019(s8 시작, blueP=0이라 눈 아이콘 완전히 안 보임)에서 확인.
- **라벨이 화면 밖에서 잘리는지**: 이 화는 대본의 "화면 문자" 열이 전 구간 "(없음)"이라 캡션 외 별도 라벨이 없다 - 해당 없음.
- **요소끼리 겹치는지**: s8(f020~f022)에서 보라/파랑 두 다이어그램과 눈 아이콘이 서로 다른 x좌표(50/570)에 배치되어 겹치지 않음을 확인.
- **화면 하단 여백 과다 여부**: s1(f001, 캐릭터 중심 배치)·s3~s8(다이어그램이 화면 상~중단, 캡션이 하단을 채움) 모두 안전영역 안에서 세로 중앙~하단까지 콘텐츠가 채워짐을 확인.
- **음량**: `ffmpeg loudnorm=print_format=summary` 측정 결과 Input Integrated -13.6 LUFS / True Peak -1.9 dBTP - 정상 청취 가능한 수준(내레이션 볼륨 1.6배 적용).
- **자막 스타일**: 프로필(`general.md`) 기준 폰트 크기(`FS.caption=50`)·위치(`CAP_BOTTOM=300`)·글자수 상한(`wrapCounts` 20자)을 공용 `Caption` 컴포넌트 그대로 사용 - 별도 override 없음.
- **모든 화면 문자열이 한국어로만 노출되는지**: `strings.ts`에 `ko` 블록만 존재하고 `Root.tsx`도 `EpisodeKo` Composition 하나만 등록 - 영어 문자열이 섞일 여지 자체가 없음(영어 Composition 미등록).
- **캐릭터 윤곽선과 배경 대비**: s1/s2(`SavannaBg`, 밝은 하늘 배경)·s6(밝은 노을 배경) 전부 배경이 밝은 톤이라 기본 `C.ink` 스트로크로 충분히 구분됨을 f001/f002/f005/f014 프레임에서 확인 - 별도 글로우 처리 불필요.
- **팝인 중간 프레임 포함 확인**: s5(f011, 눈 아이콘 등장 전)·s8(f020~f022, 눈 아이콘이 0->완전 등장까지 진행)에서 `PopIn`이 중간값에서도 위치 어긋남(Δy 튐) 없이 중심 좌표에 고정된 채 스케일만 커지는 것을 확인.
- **팀 프로필 추가 체크(general.md)**: 전문용어 노출 없음(이 화는 "레일리 산란" 등 정식 용어를 쓰지 않고 대본 그대로 "흩어지다/산란" 수준의 쉬운 말만 사용), 자막 글자수 20자 상한 준수.
