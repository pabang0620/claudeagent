## 0. 과학 설명 설계 (가장 먼저, 그림보다 먼저)

그림을 먼저 짜고 설명을 끼워 넣으면 설명이 빠진다(c01 사례). **설명 사슬을 먼저 쓰고, 그 사슬의 각 고리에 그림을 붙인다.**

### 0-1. 설명 사슬 (`02-explain.md`)

1. **질문 1개**: 시청자가 가질 질문. 예: "얼음은 왜 물에 뜰까"
2. **의외성 1개**: 왜 당연하지 않은지. 예: "대부분의 물질은 고체가 되면 더 무거워져서 가라앉는다"(A등급일 때만)
3. **인과 고리 3~5개**: 한 고리 = 한 문장 = 한 개념. 앞 고리가 다음 고리의 이유가 되어야 한다. 고리 사이에 비약이 없는지 "그래서?"를 붙여 읽어 본다.
   - 예:
     1. 물이 얼 때 분자들이 서로 손을 잡고 육각형으로 줄을 선다
     2. 육각형 가운데는 비어 있다
     3. 그래서 같은 양이 더 큰 자리를 차지한다
     4. 같은 크기로 비교하면 얼음이 더 가볍다
     5. 가벼운 것은 뜬다
4. **답 1문장**: 사슬을 한 줄로 요약한 결론.
5. **각 고리마다 적을 것**:
   - **내레이션 문장(ko/en)**: 1~2문장. 이 문장이 그대로 TTS와 자막이 된다
   - 시청자가 **봐야 하는 그림**(그 그림 없이는 이해가 안 되는 것)
   - 피해야 할 오해
6. **내레이션 말투는 채널 프로필 3절을 그대로 따른다**(`shortform/profiles/general.md`):
   - 친근한 대화체("~거든요", "~예요")
   - 첫 문장은 사실이나 장면으로 시작하고, 질문형 훅은 쓰지 않는다
   - 전문용어는 그 자리에서 풀어 쓴다
   - 숫자는 읽지 않고 화면이 보여준다
   - 마지막 문장은 핵심 사실. 교훈을 붙이지 않는다
   - 한 문장에 한 가지만, 짧게 끊는다

### 0-2. 굼구미의 역할: 실험자이자 안내자

- 굼구미는 **실제 원인을 조작하는 실험자**다(온도를 내림, 빛을 켬, 컵을 기울임). 또 **보여주는 안내자**다(가리킴, 확대경을 댐, 비교판을 들고 옴).
- 굼구미가 **물리적 원인을 대신하면 안 된다.** 분자를 손으로 끼워 육각형을 만드는 식은 틀리다. 실제로는 온도가 내려가서 생긴다(c01 결함). 이렇게 쓴다: 굼구미가 냉동 다이얼을 돌린다 -> 분자들이 느려지며 스스로 육각형으로 맞물린다.
- 그래서 스토리보드의 원인 칸을 둘로 나눈다: **굼구미 행동**(무엇을 조작·안내하는가)과 **과학적 인과**(실제로 왜 그렇게 되는가).

### 0-3. 구성 틀

영상 전체 = **[브랜드 인트로] -> [제목카드] -> 본편 -> [브랜드 아웃트로]**.
- 인트로·제목카드·아웃트로는 채널에 원래 있는 Remotion 자산을 그대로 렌더해 붙인다(`engine/brand/render_brand.sh`). 새로 그리지 않는다.
- 합쳐서 약 6.8초다(인트로 2.3초 + 제목카드 1.8초 + 아웃트로 3.0초 기준, 실제 값은 엔진 README).
- **제목카드가 주제("~하는 이유")를 알려준다.** 그래서 본편 안에서 주제 자막을 다시 띄우지 않는다.
- 전체 60초 상한, 본편 권장 20~40초.

본편 구성 (각 구간 길이는 내레이션 길이가 정한다):

| 구간 | 템포 | 내용 |
|---|---|---|
| 훅 | A->E | **일상 장면을 먼저 보여준다(최소 2.5초).** 굼구미가 현상을 겪고 반응한다. 첫 내레이션은 장면을 말한다("얼음을 물에 넣으면 동동 떠요"). **설명·비교·도식을 넣지 않는다**(c02 "처음에 갑자기 설명 들어가서 헷갈림") |
| 의외성 | E | 대비 그림(예: 다른 물질의 고체는 가라앉음) + 그 내레이션 |
| 진입 | A | 스케일 전환(확대해 들어감). **스케일 표지**(예: "분자 크기로 확대"). 내레이션은 쉬거나 짧게 |
| 인과 고리 x2~5 | E | 고리마다 내레이션 1구간. 그림이 먼저 만들어지기 시작하고, 그 고리의 내레이션이 나오는 동안 그림이 완성·hold. 고리 사이 0.3~0.6초 A 리액션 |
| 복귀·연결 | E | 일상 장면으로 돌아와 방금 본 원리를 겹쳐 보여줌(예: 떠 있는 얼음 위에 격자 윤곽) |
| 답 + 반전 | A | 마지막 내레이션(핵심 사실) + 짧은 반전 한 방(굼구미가 일으킨다). 그 뒤 아웃트로 |

- 본편이 20초보다 짧으면 의외성과 복귀를 빼고 고리를 2개로 줄인다. **훅의 장면 설정은 빼지 않는다.**

## 1. 스토리보드 형식

샘플 `storyboard.md`의 **형식과 구체성**을 따르고, 열을 과학용으로 늘린다.

- **표 형식 고정**: `# | Time | 템포 | Picture | 굼구미 행동 | 과학적 인과 | 내레이션 | 라벨 | Sound`
  - `내레이션` 칸에는 내레이션 구간 id(`s1`, `s2`...)를 적는다. `라벨` 칸에는 `03-text.md`의 id(`L2`, `N1`)
- **시각은 내레이션 기준 앵커로 적는다.** 내레이션 길이는 TTS를 돌려봐야 알기 때문에 절대 초를 미리 박지 않는다.
  - 앵커 형식:
    - `s2.t0-0.40` (s2 시작 0.4초 전)
    - `s2.t1+0.30` (s2 끝 0.3초 뒤)
    - `s2@"빈틈"` (s2에서 "빈틈" 어절이 발음되는 순간)
  - 내레이션이 없는 비트(A 비트)는 길이를 초로 적는다(`+0.60`).
  - 각 비트에 예상 절대 초를 괄호로 덧붙인다(글자 수 x 0.13초 + 문장끝 0.7초로 추정). 검토용일 뿐이고, 애니메이터는 앵커를 쓴다.
- **템포**:
  - `A` 액션: 한 비트 0.3~1.4초. 훅, 진입, 전환, 반전에 쓴다.
  - `E` 설명: 내레이션 1구간과 짝을 이룬다. 개념 하나. 동작은 `easeInOut`으로 천천히. **그림은 내레이션보다 0.3~0.5초 먼저 그려지기 시작**하고, 핵심 어절(예: "빈틈")에 맞춰 완성된다. 그 뒤 내레이션이 끝날 때까지 hold. hold 중에도 선 떨림과 굼구미의 숨쉬기는 계속한다.
  - `E` 비트 합계가 전체 길이의 **55% 이상**이어야 한다.
  - `E` 비트 도중에는 카메라를 크게 움직이지 않는다. 카메라 이동은 `A` 비트에서.
- **Picture 칸에 구체물**: 위치(화면 %), 크기(px), 카메라, 팔레트 전환 시점, dim 대상.
- **머리말에 선언**: 팔레트 hex, 색 약속 표, 화풍 한 줄, 총 길이, 캔버스.
- 굼구미 색은 항상 흰 몸, 잉크 `#252E3A`, 코랄 볼 `#FC876E`이다. 흑백 연출 구간에서만 회색.

## 2. 시간 모델 (샘플 `lib/main.js`의 `animTime`)

- 출력은 30fps다. 그림은 기본적으로 **2프레임마다 바꾼다(on twos)**. `animTime(f)`가 짝수 프레임 시각으로 내림한다.
- 휙 지나가는 순간(whip, dive, 충돌)만 매 프레임 그린다(on ones).
- **선 떨림(line boil)**: 캐릭터와 선에 `seed = Math.floor(f / 2)`를 넘겨 2프레임마다 떨림 모양이 바뀌게 한다.
- **결정론**: `Math.random()`, `Date.now()`를 쓰지 않는다. 무작위는 `U.rng(seed)`, `U.hash()`만 쓴다. 모든 그림은 `t`와 `f`의 함수다.

## 3. 움직임 문법 (A 비트는 전부, E 비트는 절제해서)

| 기법 | 코드 방법 | 샘플 위치 |
|---|---|---|
| 예비동작 -> 동작 -> 후속동작 | 웅크림 0.1~0.2초 -> 발사(easeIn) -> 착지 스쿼시(`sy: 0.8, sx: 1.15`) | 비트 7, 착지 전부 |
| 테이크(놀람) | 눈 `eyeOpen` 1.3 이상 + 몸 세로로 늘림 + 입 벌림, 0.25초 안에 | 비트 3 |
| 오버슈트 | 등장·스냅은 `U.backOut` | 비트 2 프레임 스냅 |
| 스미어 | 빠른 이동 중 반투명 잔상 여러 장 | `scene_panels.js` 잔상 |
| 고무호스 팔 | `handL`/`handR`(리그 좌표)로 손을 물체에 붙여 늘린다. 옆·아래 방향으로 | 비트 5 |
| 화면 흔들림 | 충돌 프레임부터 0.2초 감쇠 흔들림 | 비트 7 |
| 장면 전환 | 이전 장면을 오프스크린 캔버스에 그려 조각으로 날린다 | `main.js` `tearPiece` |
| 카메라 | push-in, dutch close-up, zoom plunge | 비트 3, 9, 11 |

- `E` 비트에서는 과장을 예비동작 하나, 착지 스쿼시 하나 정도로 줄인다. 설명 중인 그림보다 굼구미가 더 눈에 띄면 안 된다.
- 캐릭터는 `G.draw(ctx, { x, y, h, pose: {...}, skin, seed, sx, sy, rot, alpha, boil, wobble, handL, handR })`로 그린다(`h`는 캐릭터 높이 px). 시그니처 SSOT는 엔진 `README.md`다.

## 4. 화면이 물리적으로 반응한다 (단, 과학을 거스르지 않게)

- 샘플의 강점은 매체를 만질 수 있다는 점이다: 글자를 잡아당기고 필름을 찢는다. 과학 편에서는 **도구와 도식을 만질 수 있다.** 확대경을 대면 확대된다, 비교판을 끌어오면 나란히 놓인다, 다이얼을 돌리면 온도가 내려간다.
- 현상 자체는 과학 법칙대로 움직인다(0-2). 효과(잉크 튐, 번, 속도선)는 `A` 비트의 굼구미 동작 순간에만.

## 5. 과학 정확성

- 비유는 메커니즘을 틀리게 보여주면 안 된다. 예: 산란을 "벽에 튕김"으로 그리면 반사로 오해한다.
- 굼구미가 물리적 원인을 대신하면 그 자체가 오해다(0-2).
- 화면 숫자는 `01-fact.md`의 A등급만. 애니메이터가 숫자를 새로 만들지 않는다.

## 6. 내레이션과 화면 글자

- **내레이션이 설명을 이끈다.** 원고는 `narration-ko.json`, `narration-en.json`(구간 `{id, text, gap_before}`)에 둔다. TTS 목소리는 채널 프리셋(shortform `scripts/tts.py`)을 그대로 쓴다.
- **자막 = 내레이션 문장.** `D.narrCaption`이 지금 말하는 구간 문장을 자막 띠(세로 66~76%)에 띄운다. 별도 설명 자막은 만들지 않는다.
- **내레이션 구간 길이**: 한 구간 한국어 30자 이내(자막 2줄 이내). 길면 구간을 쪼갠다.
- **구간 사이 간격**(`gap_before`): 고리 사이 0.4~0.8초, 장면 전환 A 비트가 끼면 그 길이만큼.

| 종류 | id | 길이 | 위치 | 규칙 |
|---|---|---|---|---|
| 내레이션 자막 | `s1..` | 한국어 30자 이내 | 자막 띠 | 내레이션과 동시에 자동 표시 |
| 라벨 | `L1..` | 6자 이내 | 대상 옆, 지시선 | 처음 등장 시 1.5초 이상. 내레이션이 그 대상을 말하는 순간 뜬다 |
| 숫자 | `N1..` | - | 대상 옆 | A등급만. 내레이션은 숫자를 읽지 않는다 |
| 스케일 표지 | `S1..` | 10자 이내 | 그림 무대 위쪽 | 확대·축소 진입 시 |

- **한 화면 동시 최대치**: 내레이션 자막 1개 + 라벨 2개.
- 라벨·표지·숫자는 ko/en `TEXT[LANG]` 한 곳에서만 꺼낸다.

## 7. 9:16 구도 (쇼츠·릴스 기본)

- 쇼츠 UI가 가리는 곳: 위 약 10%, 아래 약 20%, 오른쪽 약 15%. 핵심 동작은 가운데 띠(세로 12~78%, 가로 5~82%) 안에 둔다.
- **세로 배치 기본값**: 스케일 표지·여백(14~22%) / 그림 무대(24~64%) / 내레이션 자막(66~76%). 그림이 자막 띠를 침범하지 않게 한다.
- 캐릭터 크기는 화면 너비의 30~45%가 기본. 도식이 주인공인 `E` 비트에서는 굼구미를 20~30%로 줄여 한쪽에 둔다.

## 8. 소리

- 층은 셋이다: **내레이션**(가장 크게), 효과음, 음악.
- 음악은 내레이션 구간에서 자동으로 -12dB 덕킹된다(`audio_lib.py`).
- 스토리보드 Sound 칸이 효과음 큐시트다.
  - `A` 비트는 동작마다 효과음.
  - `E` 비트는 내레이션과 겹치므로 그림이 완성되는 순간의 작은 신호음(팅, 뽁) 하나만.
- 음악 성격을 바꾸는 건 `A` 전환 비트에서 한다.
- **굼구미 입**: 굼구미가 화면에 있으면 `pose.mouthOpen = D.mouthAt(f)`로 내레이션에 입을 맞춘다. 굼구미가 말하는 것처럼 보이게 한다.

## 9. 정지컷 점검 (최대 2회, 그 이상 돌리지 않는다)

렌더 전에 **각 비트의 hold 중간 프레임 + 자막이 떠 있는 프레임 + 전환 직후 프레임**을 `--list`로 뽑아 Read로 본다(**6~10장, 대량 배치 기준**. 비트 수가 많아 넘치면 새로 만든 소품이 나오는 프레임과 전환 프레임을 우선한다). 아래 표로만 판정한다.

**속도·토큰 절약 (2026-09-28, 111화 이후 배치 기준)**:
- **이전 편(직전 1~2개)의 `main.js`/`props.js`/`scene_*.js`를 템플릿으로 그대로 복사해 시작한다.** 타이밍 계산 패턴(`NARR.segments[i].t0/t1`, 어절 앵커), 훅/전환/아웃트로 구조, 카메라·자막 배치는 매번 새로 설계하지 않고 가장 비슷한 이전 편 것을 그대로 가져와 이번 화 도식·소품만 바꿔 끼운다.
- **1라운드 점검에서 결함이 없으면 2라운드는 생략한다.** "최대 2회"이지 "항상 2회"가 아니다.
- `--list`로 잘못된 자막이 보이면(위 알려진 결함 참고) 그것만 `--from N --to N`으로 다시 뽑고, 나머지 프레임을 의심해 전체를 다시 뽑지 않는다.

| 결함 | 실제 사례 | 고치는 법 |
|---|---|---|
| 캐릭터 형상 붕괴 | 늘린 팔이 더듬이처럼 보임(샘플) | 어깨각·팔 길이 되돌림 |
| 팔이 엉뚱한 방향으로 뻗음 | c01에서 `handL`에 화면 좌표를 넘김 | `handL/handR`는 리그 좌표. `G.toRig(o, pt)`로 변환 |
| 팔을 머리 위로 곧게 뻗음 | c01 주먹 뻗기가 더듬이처럼 보임 | 팔꿈치를 구부리거나 옆으로 |
| 효과가 핵심 동작을 가림 | 필름 번이 착지를 가림(샘플) | 효과 지속시간·위치 축소 |
| 요소가 틀 밖으로 삐져나옴 | 릴 왼쪽으로 필름 칸이 나옴(샘플) | clip 영역 지정 |
| 소품이 캐릭터 머리와 겹침 | 낙서가 머리 뒤에 겹침(샘플) | 소품 위치 이동 |
| **설명 그림이 안 읽힘** | c01 육각형 격자가 뭉친 덩어리로 보임 | 간격 확대, 빈 공간 색칠, 라벨 추가, dim으로 초점 |
| **내레이션과 그림이 어긋남** | - | 그림 완성을 핵심 어절 앵커(`s2@"빈틈"`)에 맞춤 |
| **말하는데 입이 안 움직임** | - | `mouthOpen = D.mouthAt(f)` 연결 |
| **자막이 그림을 가림 / 그림이 자막 띠 침범** | - | 7절 세로 배치로 되돌림 |
| 글자 깨짐 | - | 글꼴 로드 확인 |

점검 2회가 끝나면 남은 문제는 고치지 말고 보고서에 적는다.

**`--list`로 띄엄띄엄 뽑은 정지컷의 자막을 못 믿을 수 있다** (c07에서 실측, 원인 미특정). `render.js --list 5,200,450`처럼 연속되지 않은 프레임을 지정하면 가끔 인접 구간의 자막 텍스트가 잘못 나온다(`--workers 1`에서도 재현됨). 자막이 이상해 보이면 그 프레임만 `--from N --to N`으로 단독 렌더해 다시 확인한다. 최종 판단은 항상 이어붙인 mp4에서 프레임을 뽑아 한다.
