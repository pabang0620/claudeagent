# web-crawler 참조 - 결과 출력 형식

web-crawler 정의파일에서 옮긴 내용이다(2026-10-01 prompt-audit). 정의파일이 가리킬 때만 읽는다.

## 1. 결과 출력 형식과 Evidence 파일 저장

## 결과 출력 형식

**반환 예산**: 전체 1,500단어 이내. 인용은 1건당 2문장 이내. 원문 덤프 금지 - 추출한 사실만 남긴다.
(호출자의 컨텍스트로 그대로 들어가는 값이다. 페이지 본문은 여기서 죽고 사실만 나간다.)

```markdown
## 📋 크롤링 결과: [타겟] ([N]단계, coverage N/N)

### 체크리스트 충족 현황
| 항목 | 상태 | 근거ID |
|------|------|--------|
| 정체성 | 확인됨 | E-official-01 |
| 규모 | 확인 불가 (공식사이트·DART·원티드 3경로 확인, 미기재) | - |
| 지분구조 | 해당 없음 (개인사업자) | - |

### 핵심 사실·수치
| 근거ID | 내용 | 사실/수치 | 출처 | 날짜 |
|--------|------|----------|------|------|
| E-... | ... | ... | ... | ... |

### 출처별 정리
**[출처명/페이지 제목]**
- URL: [링크]
- 접근 방법: [최종 도달 레벨 - 예: L1 WebFetch / L2 r.jina.ai / L4 Playwright→XHR캡처]
- 핵심 내용: [2~3줄]

### 활용 포인트
[이 자료로 할 수 있는 것 - 슬라이드/비교표/의사결정 근거]

### 막힌 곳 (있으면)
[robots 차단 경로 / 로그인 벽 / 캡차 + 스크린샷 경로 + 대신 쓴 대체 소스]

### 추가 탐색 추천 (오케스트레이터에게 인계)
[범위 밖 미탐색 타겟 / deep-research로 넘길 주제형 근거]
```

- **근거ID**는 `E-[타겟슬러그]-[2자리]` 형식 (예: `E-official-01`). Evidence 파일 저장 여부와 무관하게 항상 부여한다.
- `확인 불가`는 **시도한 경로를 함께 적는다**. "못 찾았다"와 "찾아봤는데 없다"는 다른 정보다.

## 근거자료(Evidence) 파일 저장 - 조건부

다음 중 하나일 때만 실행한다:
- 사용자가 "근거자료로 저장", "evidence 파일로", "문서/PT에 쓸 수 있게 저장" 등을 명시적으로 요청
- 오케스트레이터가 doc-generator·proposal-pt-builder 연계 목적으로 호출

### 절차
1. 결과 표의 근거ID를 그대로 쓴다.
2. 저장 경로가 요청에 없으면 저장하지 않고 `추가 탐색 추천`에 "저장 경로 미지정"이라고 적는다.
3. 파일명은 `evidence_<주제슬러그>_<타겟슬러그>.md`. 같은 이름이 있으면 덮어쓰지 않고 `_2`를 붙여 보고한다.

### 스키마
```markdown
# Evidence: [주제] - [타겟]

| 근거ID | 핵심 내용/수치 | 출처 | 발행일 | 활용포인트 |
|--------|--------------|------|--------|----------|
| E-official-01 | ... | 기관명·문서명·URL | YYYY-MM | ... |
```
- **발행일**: YYYY 또는 YYYY-MM, 불명확하면 "확인불가"
- **출처**: 기관/매체명 · 문서명 · URL 병기
