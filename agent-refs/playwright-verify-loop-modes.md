# playwright-verify-loop 참조 - 대체 모드·보류 판단·산출물

playwright-verify-loop 정의파일에서 옮긴 내용이다(2026-10-01 prompt-audit). 정의파일이 가리킬 때만 읽는다.

## 1. 대체 모드 - 역할별 병렬 커버리지 감사

## 대체 모드 - 역할별 병렬 커버리지 감사

### 목적
RBAC(역할 기반 접근 제어)가 있는 앱에서, 역할마다 "접근 가능해야 할 기능이 실제로 열리는지"와 "접근 차단돼야 할 기능이 실제로 막히는지"를 엔드포인트 전수 기준으로 감사한다. 버그를 고치지 않는다 - 기본 모드(검증 루프)와 가장 크게 다른 지점이다.

### Step 0 - 프로젝트 정보 확인 (하드코딩 금지)
아래는 프로젝트마다 다르므로 **감사 시작 전 프로젝트에서 직접 확인**한다. 특정 프로젝트의 역할 목록·seed 계정·엔드포인트를 이 에이전트 정의에 고정하지 않는다.
1. 이 프로젝트의 역할(role) 목록 - 코드베이스의 인증/권한 미들웨어(`requireRole`, `requireAdmin` 등) 또는 스키마의 `user_type`/`role` ENUM에서 확인.
2. 역할별 로그인 가능한 seed 계정 - `.env`, seed 스크립트에서 찾는다. 없으면 필요한 계정 목록을 반환하고 종료한다.
3. dev 서버 기동 명령·포트 - 기본 모드 §입력과 동일하게 확인.

### Step 1 - 라우트 스캔 → 엔드포인트-UI 매핑 생성
1. 백엔드 라우트 파일을 전수 grep해 전체 엔드포인트 목록을 추출한다 (`router.get/post/put/patch/delete` 패턴, 프로젝트의 라우터 디렉토리 기준).
2. 각 엔드포인트에 다음을 매핑한다: 필요 인증 여부, 필요 역할(미들웨어 기준), 프론트엔드 진입 경로(페이지·버튼), 트리거 방법.
3. 매핑 결과를 감사 시작 전 표로 정리해 저장한다 (역할별 서브에이전트에게 그대로 전달할 근거자료).

### Step 2 - 역할 수만큼 서브에이전트 병렬 스폰
Step 0에서 확인한 **역할 수만큼**, 단일 메시지로 서브에이전트를 동시 소환한다. 각 서브에이전트에게 다음을 프롬프트로 명시한다:
- 자신이 맡은 역할의 seed 계정으로 로그인.
- Step 1 매핑표에서 "이 역할이 접근 가능해야 하는" 엔드포인트를 하나씩 UI로 호출 → 정상 동작 확인.
- 매핑표에서 "다른 역할 전용"으로 표시된 엔드포인트도 UI 또는 직접 호출로 시도 → 401/403 등으로 **차단되는지** 확인 (차단되지 않으면 CRITICAL 권한 누락).
- **수정 금지 - 발견·보고만.** 문제를 발견해도 코드를 고치지 않는다.
- 결과를 역할 전용 리포트 파일(예: `bugs_<role>.md`)에 정상/버그 항목 모두 기록 (커버리지 누락 방지를 위해 정상 동작도 한 줄로 남긴다).

### Step 3 - 리포트 취합
모든 서브에이전트 완료 후:
1. 역할별 리포트 파일을 모두 읽는다.
2. 심각도별로 통합 정렬한다 - 접근 차단 실패(다른 역할 기능이 열림)는 CRITICAL, 접근 가능해야 할 기능이 막힘은 HIGH, 그 외 UI 오작동은 MEDIUM/LOW.
3. 통합 리포트 파일로 산출한다 (요약 테이블 + 심각도별 상세 + 역할별 정상 동작 목록). 이 모드의 리포트는 기본 모드와 달리 **전부 open 상태**로 남는다 - 수정·재검증은 별도 요청(react-specialist/express-engineer 위임 등)으로 이어간다.

### 기본 모드와 절대 섞지 않을 것
- 이 모드 중 발견한 버그를 즉시 인라인 수정하지 않는다 (기본 모드의 "인라인 사소수정" 예외는 이 모드에는 적용되지 않는다).
- 이 모드는 §Phase 0~5 재검증 루프를 돌지 않는다 - 1회 전수 감사로 종료한다.
- 리포트 포맷은 위 §대체 모드에서 정의한 역할별 버그 리포트를 따르고, 기본 모드의 `report-<NNN>.md`/`state.json` 시그니처 추적 체계는 사용하지 않는다.

## 2. 동적 보류 판단·산출물·리포트 포맷

## 동적 보류 판단 (고정 횟수 아님)

각 오류에 **시그니처**를 부여한다: `(차단된 플로우/단계) + (정규화한 에러 메시지) + (스택 톱 프레임 or 실패 라우트)`. 사이클 간 시그니처를 `state.json`에 보관한다.

재검증 결과를 시그니처로 비교한다:
- **사라짐** → 해결 처리.
- **남았으나 시그니처가 바뀜** (다른 라인/다른 메시지/더 진행된 단계에서 실패) → **진전 있음**. no-progress 카운터 0으로, 다시 수정 시도.
- **시그니처 동일** → **진전 없음**. no-progress 카운터 +1.

`no-progress >= 2` (연속 2회 동일)면 해당 오류를 **보류**한다:
- `deferred.md`에 시그니처·시도 이력·마지막 가설·막힌 지점을 기록.
- 그 오류는 더 건드리지 않고 **다음 오류로 넘어간다**.

**안전장치**: 전체 사이클은 최대 6회. 도달하면 미해결 전부 보류 처리하고 종료한다. (무한루프 방지)

---

## 산출물 (`<project>/docs/playwright-verify/`)

- `report-<NNN>.md` - 사이클별 오류 리포트
- `deferred.md` - 보류된 오류 (진전 없음/시도 한계)
- `state.json` - 오류 시그니처·시도/진전 카운터. 인라인 수정으로 오류가 해소된 경우에도 해당 항목을 `status: inline-fixed`로 갱신한다.
- `server.log` - dev 서버 로그
- `screenshots/` - 단계별 스크린샷
- `final-report.md` - 종료 시 요약: 해결 N건 / 보류 M건 / 각 항목 상태·근거

### 리포트 항목 포맷
```md
## [E-001] <한 줄 증상>
- 상태: open | fixed | inline-fixed | deferred
- 판정: CONFIRMED(화면+API/DB 교차확인됨) | PLAUSIBLE(정적분석 또는 단일채널뿐)
- 발생 위치: <화면/플로우/단계>
- 증거: 콘솔=<...> / 네트워크=<상태코드 URL> / 서버로그=<라인> / 스크린샷에 실제로 보이는 값=<...>
- 원인 가설: <...>
- 관련 파일: path:line
- 시그니처: <플로우|메시지|스택톱>
- 처리: 위임=<agent> | inline | deferred
- 시도 이력: cycle1(no-progress) → cycle2(...)
```

## 3. Phase 0 서버 기동·헬스체크·개발자모드

   - 서버가 여러 개(frontend/backend 등)이면 각 디렉토리에서 별도로 기동한다:
     ```bash
     # 경로·명령은 사용자 입력으로 대체
     cd frontend && npm run dev >> docs/playwright-verify/server-fe.log 2>&1 &
     cd backend && node server.js >> docs/playwright-verify/server-be.log 2>&1 &
     ```
   - 기동 후 **포트 대기 (health check)**: 기동한 모든 포트 각각에 대해 `timeout`으로 30초 상한을 걸고 폴링한다 (서버가 영영 안 뜰 때 무한대기 방지).
     ```bash
     # 기동한 모든 포트 각각 대기 (포트 번호는 사용자 입력으로 대체)
     timeout 30 bash -c 'until curl -sf http://localhost:5173/ > /dev/null 2>&1; do sleep 1; done' || echo "FE_TIMEOUT"
     timeout 30 bash -c 'until curl -sf http://localhost:3000/ > /dev/null 2>&1; do sleep 1; done' || echo "BE_TIMEOUT"
     ```
   - **기동 실패 처리**: `timeout` 종료코드가 0이 아니거나 `*_TIMEOUT`이 출력되면 해당 server.log 마지막 부분을 보고에 붙이고 검증을 중단한다.
2. Playwright MCP로 브라우저를 열고 앱 URL로 `browser_navigate`.
3. 개발자모드 상태 확보:
   - `browser_console_messages`로 초기 콘솔 메시지를 수집한다 (이후 단계마다 반복).
   - `browser_network_requests`로 초기 네트워크 요청을 수집한다 (4xx/5xx 필터링).
   - 참고: Playwright MCP는 DevTools 패널을 별도로 열지 않아도 위 두 도구로 콘솔·네트워크를 캡처할 수 있다.
