# Flow(나노바나나) 대량 생성 방식

수십 장 이상을 한 번에 그릴 때의 방식이다. 웹툰 6천 컷 작업(novel-noon-shadow, 2026-10-19~22)에서 굳어졌다. 한두 장은 `flow-nanobanana` 스킬 본문의 수동 절차로 충분하다.

## 구조 (정본 구현: `skills/flow-nanobanana/helpers/bulk/`, 실사용본 `novel-noon-shadow/webtoon/tools/nb/`)

1. **계정 여러 개를 동시에 쓴다.** 계정마다 별도 프로필(`~/.flow_profiles/<계정>`)과 Flow 프로젝트 URL(`accounts.json`)을 둔다. 한 계정에 몰아 넣지 않는다
2. **작업 목록을 먼저 만든다**(`nb_jobs.py` 역할): 콘티·목록 → 컷마다 `{id, prompt, refs, ratio, final, prev}`를 JSON으로. 계정별 목록은 `--part k/N`으로 장면 단위로 나눈다(같은 장면은 한 계정이 이어서 그려야 앞 컷을 참조할 수 있다)
3. **생성기**(`nb_gen.mjs`)는 계정 하나가 목록을 위에서부터 한 장씩 그린다. 이미 파일이 있는 컷은 건너뛰므로 언제 다시 켜도 이어진다
4. **일꾼**(`nb_worker.sh`)이 계정마다 남은 일을 다시 계산해 돈다. 몫은 "지금 쉬지 않는 계정 수 N과 내 순번 k"로 정해서, 차단된 계정이 돌아오면 자동으로 몫을 되찾는다. `start_workers.sh`가 일꾼 3개를 띄우고 `stop_all.sh`가 전부 멈춘다
5. **차단 대응**: 차단 문구가 뜨면 그 계정만 멈추고(`active_accounts.py`가 1시간 제외, 뒤에 성공 기록이 있으면 복귀), 다른 계정은 계속한다. 우회하지 않는다
6. **생성만 먼저, 검토는 나중에**: 생성 중에는 결과를 눈으로 보지 않는다. 장 단위로 끝난 뒤 판독 에이전트(컷마다 직접 열어 확인)로 결함만 골라 해당 파일을 지우고 일꾼을 다시 켜면 빠진 컷만 다시 그린다

## 창 없이 백그라운드로 (헤드리스)
- 생성기는 기본이 `NB_HEADLESS=1`(창 없음). 사용자가 다른 작업을 하는 중에 브라우저 창이 계속 뜨지 않게 한다. 로그인 같은 수동 작업은 `NB_HEADLESS=0`(창 있음)
- 헤드리스에서는 사용자 에이전트에 "HeadlessChrome"이 남아 Flow가 알아볼 수 있으니 일반 크롬 문자열로 덮는다(`nb_gen.mjs`에 들어 있음). 2026-10-22 3계정 모두 정상 동작 확인
- 크롬 프로세스 확인: `pgrep -af chrome | grep -v -- --type=`에서 `--headless`가 있는 것이 실제 브라우저(crashpad_handler는 창이 아니다)

## 감시 (Monitor)
- 알림은 **차단, 20분째 새 컷 없음, 같은 컷 3회 실패, 장 완료, 일꾼 전부 끝**일 때만. 컷마다 알리지 않는다(토큰 절약)
- 알리겠다고 했으면 반드시 감시를 걸고, 확인하지 않고 "나왔어요"라고 하지 않는다. 30분마다 만료되니 다시 건다
- 진행 수치는 파일 수를 직접 센다(보고 문장 믿지 않기)

## 결과 검증 (생성기 안에서 자동)
Flow 화면은 가상 스크롤이라 **옛 그림이 새 결과처럼 잡히는 사고**가 난다(6천 컷 중 수백 컷이 다른 컷 그림으로 저장됐었다). 아래 4단계를 모두 넣는다.
1. 새 결과 판정은 **서명 URL의 쿼리를 뺀 경로**로 한다(같은 그림도 쿼리가 계속 바뀐다)
2. 저장 전에 **후처리(자르기)까지 한 결과**를 만든다
3. 그 결과를 **참조 이미지, 같은 장면 앞 컷, 같은 폴더의 저장된 모든 컷**과 해시(dhash, 해밍 거리 10 이하)로 비교한다(`is_dup.py`, 폴더의 `.dhash.json`에 캐시). 같으면 저장하지 않고 실패로 다시 그린다. 자르기 전 원본끼리 비교하면 새어 나간다
4. 정책 거부·"이미지를 생성할 수 없습니다" 타일이 새로 뜨면 4분을 기다리지 않고 바로 실패 처리
- 인물 없는 순수 풍경은 배경 시트를 거의 그대로 다시 그려 3번에 계속 걸린다. 그런 컷은 시트를 잘라 컷으로 쓴다
- 같은 구도가 연속된 컷(같은 장면의 비슷한 프롬프트)도 걸린다. 구도를 바꿔 쓴다

## 프롬프트 규칙 (실측)
- 모든 프롬프트 앞에 `Generate a single static IMAGE (not a video): `, 끝에 글자·말풍선·워터마크 금지 문장
- 참조 이미지는 컷당 최대 4장(인물 시트 우선, 장소·소품 시트, 앞 컷은 마지막). 시트를 붙여도 자꾸 틀리는 인물은 **핵심 외형 문장을 프롬프트에 한 번 더** 적는다(`IDENTITY_NOTES`: 머리 모양, 가면·후드, 안경, 복장)
- **그림 속 글자는 반드시 새는 항목이다.** 서류·화면·간판·벽은 "빈 줄만, 읽히는 글자 없음, 간판은 빈 판"으로 쓴다
- **Flow가 거부하는 것**: 미성년자에게 성적·폭력적으로 읽히는 문장, 아동 납치·폭행의 직접 묘사, 미성년 인물에 체형 강조 문장. 거부된 컷은 직접 묘사 대신 암시(신발 한 짝, 문틈의 손, 닫히는 문)로 바꾼다. 같은 프롬프트를 3번 반복하지 않는다
- 참조 첨부 뒤 4초 기다린 뒤 "생성 전" 타일 목록을 잡는다(안 기다리면 참조 업로드가 결과로 잡힌다)
- 제출 간격 10초(사용자 지시), 하루 상한 없음. 차단 문구가 뜨면 1시간 뒤 다시

## 정리
- 다시 그릴 컷은 파일을 지워서 일꾼이 다시 그리게 한다(`_old`로 옮겨 쌓지 않는다. 쌓으면 수 GB가 된다. 삭제는 사용자 승인 뒤)
- 생성 원본 사본(`raw/`)은 장이 끝나면 지운다
- 다 끝난 뒤 쓰지 않는 큐 스크립트·로그는 지운다(승인 뒤)

## 판독(검토) 쪽 토큰 절약
- 판독 에이전트 1개당 100컷 안팎으로 묶어 병렬(최대 5개). 컷마다 이미지를 직접 열어야 해서 컷당 1천~1.5천 토큰이 든다
- "컷마다 Read로 직접 열어 본다"를 스폰 프롬프트에 적는다(안 적으면 콘티만 보고 추정으로 적은 사례가 있었다)
- 결함 기준을 먼저 정한다: 인물·장소가 다름, 읽히는 글자, 시대 오류, 얼굴·손 붕괴, 중복. 달 모양 같은 사소한 차이는 note에만(끝없는 재생성 방지)
- 다시 그린 컷은 한 번 더 판독하되 2회로 끝낸다

## 정책 거부를 부르는 표현 (웹툰 실측 2026-10-23)
- 미성년 인물이 나오는 컷의 장면 설명·프롬프트에 화상·딱지·거즈·피·상처 목록, 손목·팔뚝 붕대, "맨 손목", 손목의 표식, 취조실, "숙청 다음 날" 같은 표현이 있으면 그림 내용과 상관없이 거부된다. 고친 뒤 거부율이 거의 0이 됐다
- 거부와 혼잡을 구분한다: 화면에 "정책을 위반"이 새로 뜨면 프롬프트 문제, "이미지를 생성할 수 없습니다"만 뜨면 일시 혼잡(1분 쉬고 다시)
- 로그 날짜는 로컬 시간으로 찍는다(UTC면 한국 오전 9시 전 차단이 하루 전으로 찍혀 계정을 쉬게 하지 못한다)
- 같은 날 다시 막힌 계정은 `rest_until.json`으로 다음 날 아침까지 쉬게 한다
