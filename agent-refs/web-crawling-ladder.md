# 웹 크롤링 승급 사다리 · 소스 카탈로그

`web-crawler` 에이전트와 `deep-research` 스킬이 공유하는 참조 파일. **막혔을 때만 읽는다.**
두 곳 다 이 파일을 가리키므로, 사다리·정지조건을 바꾸려면 여기만 고친다.

| 읽는 조건 | 읽을 섹션 |
|---|---|
| WebFetch 결과가 비었거나 봇월/403/429 | §1 승급 사다리 |
| 사이트 URL 목록을 확보해야 할 때 | §2 사이트맵 선조회 |
| 한국 기업·기관을 조사할 때 | §3 한국 소스 카탈로그 |
| 조사를 언제 멈출지 판단할 때 | §4 포화 판정 |

---

## §1 승급 사다리 (Escalation Ladder)

Crawlee `AdaptivePlaywrightCrawler`의 rendering-type detection을 에이전트용으로 옮긴 것.
**싼 경로부터 쓰고, 관찰 가능한 실패 신호가 나올 때만 한 칸 올린다.** 건너뛰기 금지, 되돌아가기 금지.

| L | 수단 | 승급 트리거 (다음 칸으로 올라가는 조건) |
|---|---|---|
| L0 | `WebSearch` | 후보 URL이 안 잡힘 → §2 사이트맵 선조회로 |
| L1 | `WebFetch <url>` | 본문 200자 미만 / "JavaScript를 활성화" 문구 / 메뉴만 있고 본문 없음 / HTTP 403·429·5xx |
| L2 | `WebFetch https://r.jina.ai/<url>` | 여기서도 본문 없음 / 422 (대상 도메인 부재 신호) / 렌더 후에도 빈 페이지 |
| L3 | `browser_navigate` → `browser_snapshot` | snapshot에 목표 정보 없음 / 클릭·검색·페이지네이션 조작이 필요 |
| L4 | `browser_click`·`browser_type`·`browser_fill_form`·`browser_wait_for` → `browser_network_requests` | 조작 후에도 안 나옴. **network_requests에서 내부 API(XHR/JSON)·PDF 실제 URL을 캡처했으면 그 URL로 L1(WebFetch) 재진입** |
| L5 | 웨이백 아카이브 (`web.archive.org`) | 현재 페이지가 죽었거나(404), 과거 시점 정보가 필요하거나, L1~L4가 전부 실패 |

### 실측 확인 사항 (2026-08-21)
- **L2 `r.jina.ai`는 WebFetch로 동작함.** 키 없이 20 RPM. `https://r.jina.ai/` 를 대상 URL 앞에 붙이면 본문만 마크다운으로 반환. 존재하지 않는 도메인이면 422를 반환하므로, 422는 "차단"이 아니라 **"도메인이 틀렸다"** 신호로 읽는다.
- **L5 웨이백은 WebFetch로 접근 불가.** `web.archive.org`는 하네스가 차단한다. 반드시 `browser_navigate`로 `https://web.archive.org/web/2026/<원본URL>` 을 연다. CDX 인덱스(`/cdx/search/cdx?url=...&output=json`)도 브라우저로만.

### 종료 규칙 (무한 재시도 차단)
- 한 URL은 **L1→L5 한 바퀴가 끝**이다. 한 바퀴 돌고 실패하면 그 URL은 `접근 불가`로 확정하고 **같은 URL을 다시 시도하지 않는다.**
- 확정 시 `browser_take_screenshot` 1장을 증빙으로 남기고 다음 URL로 넘어간다.
- 사다리를 올라간 사실은 결과의 `접근 방법` 칸에 최종 도달 레벨로 표기한다 (예: `L4 Playwright→XHR캡처`).

### 우회하지 않는 것 (사다리 밖)
로그인 벽, 캡차, robots.txt `Disallow`, 유료 페이월. 이건 사다리로 뚫는 대상이 **아니다.**
막힌 사실을 기록하고 §3의 대체 소스로 **경로를 바꾼다.**
(근거: 네이버 스마트스토어 건 - 반복 접속만으로 캡차가 뜨는 사이트를 크롤링 대상으로 잡았다가 거절한 사례)

## §2 사이트맵 선조회 (Firecrawl `/map` 패턴)

**타겟 도메인이 확정된 순간, 블라인드 WebSearch보다 이걸 먼저 한다.** 한 사이트의 URL 전수를 2~3회 fetch로 얻는다.

```
1. WebFetch https://<도메인>/robots.txt
   → Disallow 목록 확보 (여기 걸린 경로는 접근 금지 + 결과에 "robots 차단" 기록)
   → Sitemap: 지시자가 있으면 그 URL 사용
2. Sitemap 지시자가 없으면 관례 경로 순서대로 시도:
   /sitemap.xml → /sitemap_index.xml → /sitemap/sitemap.xml
3. 사이트맵도 없으면 메인 페이지를 L1으로 읽고 내비게이션 링크를 수확해 프론티어로 삼는다
4. 얻은 URL 목록을 정보요구 체크리스트(§4)에 매핑해 우선순위를 매긴다
   (about/company/회사소개 > 제품·서비스 > IR·보도자료 > 채용 > 블로그)
```

**실측 예시**: `kocca.kr/robots.txt` 는 `/*/FileDown.do` 를 Disallow 한다. 즉 KOCCA 보고서 PDF의 다운로드 경로는 robots 차단 대상이므로, 그 경로를 긁지 말고 게시물 상세 페이지 본문이나 공개 뷰어를 쓴다.

### 프론티어 위생 (Scrapy/Crawlee)
- 방문 전 URL을 정규화한다: 프로토콜 통일 → 후행 슬래시 제거 → `#앵커` 제거 → 추적 파라미터(`utm_*`, `fbclid`, `gclid`) 제거
- 정규화한 URL의 **seen 집합**을 유지하고, 이미 본 URL은 다시 열지 않는다
- 같은 도메인 안에서만 따라간다. 외부 도메인 링크는 따라가지 말고 `추가 탐색 추천`에 적는다

## §3 한국 소스 카탈로그

**공식 사이트가 빈약하거나 SNS·링크드인이 막혔을 때 갈아탈 경로.** 위에서부터 시도한다.
표기된 것들은 후보 경로이며, 실제 접근 성공 여부는 매번 확인해서 결과에 표기한다.

### 기업 실체·규모
| 소스 | 도메인 | 얻는 것 | 한계 |
|---|---|---|---|
| DART 전자공시 | dart.fss.or.kr | 사업보고서·감사보고서·재무·지분·임원 | 외부감사 대상만. 소규모 비상장은 없음 |
| 중소기업현황정보시스템 | sminfo.mss.go.kr | 기업 개요·업종·규모 | 기업 동의 기반이라 누락 있음 |
| 벤처확인 종합관리시스템 | smes.go.kr/venturein | 벤처인증 여부·분야 | 인증 기업만 |
| 국세청 사업자등록상태조회 | data.go.kr 공개API | 사업자번호 유효성·휴폐업 | 사업자번호를 이미 알아야 함 |

### 인력·기술·조직 (링크드인 대체)
| 소스 | 도메인 | 얻는 것 |
|---|---|---|
| 원티드 | wanted.co.kr | 채용공고 → 기술스택·팀 구성·성장단계 |
| 사람인 / 잡코리아 | saramin.co.kr / jobkorea.co.kr | 기업정보 탭에 사원수·매출·설립일 |

| 소스 | 도메인 | 얻는 것 |
|---|---|---|

| 키프리스 | kipris.or.kr | 특허·상표 → 실제 기술 영역과 출원 시기 |

### 공공·통계 (주제형 조사일 때)
KOCCA·통계청·문체부·KDI·KISDI·NIPA·NIA·KOTRA·data.go.kr·index.go.kr
→ **이 목록이 조사의 중심이 되는 요청이라면 web-crawler가 아니라 `deep-research` 스킬이 담당이다.** 여기서는 타겟 기업의 산업 맥락을 보강하는 보조 용도로만 쓴다.

### 금지 소스
- **네이버 계열(스마트스토어·카페·블로그·뉴스 댓글) 자동 수집 금지.** robots 전면 차단 + 반복 접속만으로 캡차 발동 + 실제 승소 판례 존재. 네이버 뉴스 링크를 만나면 언론사 원문 도메인으로 갈아탄다.
- 개인 이메일·연락처 대량 수집

## §4 포화 판정 (Crawl4AI Adaptive Crawling 패턴)

"몇 페이지를 볼 것인가"가 아니라 **"체크리스트가 채워졌는가"** 로 종료를 결정한다.

### 착수 시: 정보요구 체크리스트를 먼저 쓴다
조사 대상 유형에 맞춰 **3~7개 항목**을 확정하고 출력한다. 기업 조사 기본형:
```
[ ] 정체성   - 법인명 / 설립연도 / 대표 / 소재지
[ ] 사업영역 - 주력 제품·서비스와 고객군
[ ] 규모     - 인원 / 매출 / 투자 이력
[ ] 실적     - 대표 레퍼런스·수주 이력
[ ] 최근동향 - 최근 12개월 뉴스·공시·채용
```

### 매 라운드 후: 3개 지표를 갱신한다
- **coverage** = 채워진 항목 수 / 전체 항목 수
- **gain** = 이번 라운드에서 **새로** 채워진 항목 수
- **saturation** = gain이 0인 라운드가 연속 몇 번인가

### 종료 조건 (먼저 걸리는 것으로)
| 조건 | 처리 |
|---|---|
| coverage 100% | 즉시 종료. 남은 예산 쓰지 않는다 |
| gain 0이 연속 2라운드 (saturation) | 즉시 종료. 남은 항목은 `확인 불가`로 확정 보고 |
| 노력 상한 도달 (깊이별 상한 참조) | 종료. 미완 항목과 다음에 볼 URL을 인계 |

깊이 등급은 **노력 상한**일 뿐이며 종료 시점은 위 표가 정한다.

| 깊이 | WebSearch | 페이지 열람 | Playwright 세션 |
|---|---|---|---|
| 1단계 | 최대 2 | 최대 4 | 0 (원칙적으로 안 씀) |
| 2단계 | 최대 4 | 최대 10 | 최대 2 |
| 3단계 | 최대 8 | 최대 25 | 최대 5 |

### 항목별 3값 보고 (부재 증명)
체크리스트 각 항목은 반드시 셋 중 하나로 확정한다. 빈칸으로 두지 않는다.
- `확인됨` - 출처 URL 병기
- `확인 불가` - **시도한 경로를 함께 적는다** (예: `공식사이트·DART·원티드 3경로 확인, 미기재`)
- `해당 없음` - 대상 성격상 존재할 수 없음 (예: 개인사업자의 지분구조)

"못 찾았다"와 "찾아봤는데 없다"는 다른 정보다. 후자만 의사결정에 쓸 수 있다.
