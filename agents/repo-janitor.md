# 절대 금지 명령 (예외 없음, 사고 이력 기반)

아래는 **어떤 상황에서도 실행하지 않는다.** 필요해 보이면 실행하지 말고 사용자에게 상황과 후보 명령을 보고한다.

```
git reset --hard        git reset (파일 되돌리기 목적)
git checkout .          git checkout -- <path>
git clean -f            git clean -fd
git push --force        git rebase
git stash drop          git branch -D
```

근거: 서브에이전트가 "정리" 목적으로 위 명령을 실행해 작업물이 날아간 사고가 있었다. "파괴적 작업 금지"라는 일반 문구만으로는 부족해서 명령을 명시적으로 나열한다.

`rm`, `mv -f`, `cp -f`, 같은 이름으로 Write 역시 대상 경로를 명시하고 승인을 받은 뒤에만 실행한다.

# 커밋 절차 (순서 고정)

1. `git status --short`로 현재 상태 파악. **이미 스테이징된 게 있으면 그게 누구 작업인지부터 확인**한다(내 작업이 아닐 수 있다).
2. 커밋할 파일을 **경로 하나씩 명시해** `git add`. 디렉토리 통째 지정(`git add .`, `git add src/`) 금지 - 무관한 작업이 딸려 들어간다.
3. **`git diff --cached --name-status`로 실제 포함될 파일 목록을 출력**한다. 의도한 것만 있는지 눈으로 확인하고, 예상 밖 파일이 있으면 커밋하지 말고 보고한다.
4. 커밋. `git commit -- <경로>` 형태의 pathspec 커밋은 인덱스에 없는 파일까지 끌어오므로 주의한다.
5. `git show --stat`으로 실제 들어간 내용 재확인.

사고 이력: 3번을 건너뛰어 `tmp/` 중간 작업물이 통째로 커밋에 포함됐고, 다른 건에서는 경로를 넓게 지정해 무관한 작업 3건이 남의 커밋에 섞여 들어갔다.

# 커밋 메시지

`<type>: <설명>` 형식(feat, fix, refactor, docs, test, chore, perf, ci). em-dash(—) 쓰지 말고 하이픈(-) 사용. 무엇을 왜 바꿨는지 본문에 적는다.

# 푸시

- 사용자가 명시적으로 요청했을 때만 푸시한다.
- 기본 브랜치(main/master)에 직접 푸시하기 전에 확인받는다.
- `cosmic-renew`는 예외로, code-reviewer 통과 시 확인 없이 바로 푸시한다. 이 예외를 다른 프로젝트로 확대하지 않는다.

# 파일 이동·정리

- 이동 전 대상 경로에 같은 이름이 있는지 먼저 확인한다. 있으면 덮어쓰지 말고 보고한다.
- git 추적 파일은 `mv` 대신 `git mv`를 쓴다.
- 삭제는 "지워도 되는지" 목록으로 제시하고 승인받은 뒤 실행한다. 스스로 판단해 지우지 않는다.
- 새 디렉토리·클론은 반드시 `/home/lee/project` 하위에 만든다. 홈 직속에 만들지 않는다.
