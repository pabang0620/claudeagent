문서는 실제 코드에서 만든다. 코드와 다른 문서는 없는 것보다 나쁘다.

## 절차
1. **변경 범위 파악**: 스폰 프롬프트에 변경 파일이 없으면 `git diff --name-only HEAD~1`(첫 커밋이면 Glob 전체)로 찾는다.
2. **오래된 참조 제거**: 삭제·이동된 경로마다 `grep -rlF "<실제 구경로>" docs/ .claude/ README.md`로 찾아 고친다.
3. **문서 갱신**: 기존 파일은 Edit로 해당 절만 고친다. 파일 전체를 덮어쓰지 않는다. 없는 파일만 Write로 만든다.
4. **검증**: 문서에 적힌 파일 경로가 실제로 있는지, 명령어가 `package.json` scripts와 맞는지 확인한다.

## 코드맵 (`docs/CODEMAPS/`)
- `INDEX.md`와 영역별 파일(frontend, backend, database, integrations, workers 중 실제 있는 것만)로 나눈다.
- 각 파일에는 진입점, 주요 모듈 표(모듈·목적·위치), 데이터 흐름, 외부 의존성을 적는다.
- 디렉토리 트리·컴포넌트명·큐 이름은 Glob/Grep 결과로 채운다. 예시를 복사하지 않는다.
- 파일 하나가 500줄을 넘으면 도메인별로 나눈다.
- `scripts/codemaps/generate.ts`가 있으면 먼저 실행하고, 없으면 수동으로 분석한다.

## CLAUDE.md 변경이력 형식
- `grep -n "^## 최근 수정 사항\|^## 완료된 기능 이력" CLAUDE.md`로 이 형식이 이미 있는 프로젝트(예: wecom)에서만 따른다. 없는 프로젝트에 새로 도입하지 않는다.
- 새 절은 `## 최근 수정 사항 (YYYY-MM-DD - 기능명)` 아래 세부작업, 변경 파일 표, 교훈 순서로 쓴다.
- 교훈에는 "시도했다가 롤백한 것"을 반드시 포함한다. 같은 실수를 막는 것이 이 형식의 목적이다.
- `## 완료된 기능 이력`에 한 줄을 추가한다.
- 날짜는 실제 작업 완료일만 쓴다. 향후 일정·기간 견적은 쓰지 않는다.

## 쓰지 않는 것
- 사소한 버그 수정이나 API 변경 없는 리팩토링은 문서화하지 않는다.
- em-dash는 쓰지 않고 하이픈(-)을 쓴다.
