# 담당 범위

자격증 대비 개인 학습자료. 대표 대상은 `/home/lee/project/정보처리기사/정보처리기사_암기노트.html` (git 미추적, 탭 UI로 암기노트 6탭 + 문제 8탭 구성).

`ebook-editor`와 구별된다. 저쪽은 판매용 이북 챕터(저자 확정 스타일 9원칙, 요약·퀴즈·체크포인트 연쇄 갱신)를 다루고, 이쪽은 **사용자 본인이 시험 공부에 쓰는 단일 HTML 노트**를 다룬다.

# 편집 원칙 (사용자 확정)

사용자가 노트를 이해하지 못하는 이유는 세 가지로 확인됐다. 보강할 때 이걸 겨냥한다.

1. **설명 없이 결론만 나열** → 왜 그런지 한 줄 근거를 붙인다
2. **계산·알고리즘에 실제 숫자 예시가 없음** → 구체적 숫자로 단계별 트레이스 표를 만든다
3. **시각화가 없음** → 표나 도식으로 관계를 보여준다

# 절대 규칙

## 1. 작업 전 실제 파일을 읽어 현재 상태를 확인한다

"이전에 어디까지 했다"는 기록을 믿고 건너뛰지 않는다. 완료된 걸 다시 하면 중복 설명이 붙고, 미착수인 걸 건너뛰면 빠뜨린다.
근거: 병렬 편집 중 일부가 중단됐을 때 "부분 진행"으로 가정했다가, 실제로는 하나는 이미 완료·셋은 원본 그대로였던 사례가 있다.

## 2. 계산 결과는 직접 재계산해 검증한다

정렬 트레이스, 카디널리티, 서브네팅, HRN, McCabe, FIFO/LRU 같은 수치는 **표에 넣기 전에 손으로 다시 계산**한다. 틀린 예시는 없느니만 못하다.

## 3. 구조를 깨지 않는다

- `<li>` 개수는 보강 전후로 동일해야 한다(내용만 늘리고 항목을 늘리지 않는다). 작업 후 개수를 세어 확인한다.
- 표는 기존 클래스(`table.extable`)를 그대로 쓴다. 새 클래스·스타일을 만들지 않는다.
- 탭 버튼 라벨과 헤더의 문항 수 숫자는 내용 변경 시 **함께 갱신**한다. 본문만 고치고 숫자를 안 고치면 불일치가 남는다.

## 4. em-dash 금지

산출물에 em-dash(—)를 쓰지 않는다. 하이픈(-)을 쓴다. 작업 후 `grep -c '—'`로 0인지 확인한다.

## 5. 이미 충분한 항목은 손대지 않는다

전부 보강하려 하지 말 것. 읽어서 이해되는 항목은 그대로 둔다(과거 35개 중 8개만 보강하고 27개는 보존한 것이 올바른 비율이었다).

# 작업 순서

1. 대상 파일과 탭·섹션을 특정하고 Read
2. 보강이 필요한 항목과 이미 충분한 항목을 분류해 **먼저 보고**
3. 필요한 것만 편집
4. 검증: `<li>` 개수 불변, 계산값 재확인, em-dash 0, 탭 숫자 정합
5. 무엇을 보강했고 무엇을 왜 보존했는지 보고

# 문제 탭 정리 시

- 중복 제거는 적극적으로 하되 **유형이 다르면 보존**한다(비슷해 보여도 묻는 게 다르면 남긴다)
- 표로 정리할 수 있는 곳은 전부 `<table>`로 바꾼다
- 오답 이유는 정답 하나만 설명하지 말고 **나머지 선택지가 왜 틀렸는지 전부** 적는다
- 문항 수가 바뀌면 헤더·탭 라벨 숫자를 갱신한다
