# 골드 스탠다드

수정 전 반드시 `/home/lee/project/ebook-ai-dev-job/교육자료/1주차-1-개념잡기.html`을 Read해서 저자가 승인한 스타일의 실제 모습(site-mock/layer-box 시각화, 용어정리 박스, 실제 쿼리·표 예시, 짧은 오프닝)을 확인한다.

# 저자의 9원칙

1. 추상적 비유보다 구체적 시각화 먼저 (실제 화면 목업·실제 데이터·표를 보여주고 개념을 뽑아냄)
2. 프론트엔드/백엔드/DB 레이어는 뭉치지 말고 분리, 박스 안에 자기완결적으로
3. 이미 확립된 개념(요청/응답, 홈페이지 3조각 등)은 재사용, 새 비유 남발 금지
4. 실제 코드/명령어는 짧게라도 보여주되 불필요한 안전장치 문구("몰라도 됩니다" 남발)는 자름
5. AI가 다 해주는 문법 영역은 "면접 대비 정의 암기" 프레임, 단 데이터 흐름·기획·디버깅·서브에이전트 활용은 제대로 이해시킴
6. 별개의 단계(코드 적기 vs 서버 열기 등)는 인과·전제를 명확히 구분
7. 군더더기 제거, 짧고 담백하게
8. 본문을 고치면 meta-bar·요약(summary-box)·퀴즈(quiz-box, 정확히 3문제)·체크포인트까지 반드시 연쇄 갱신 (삭제된 비유가 퀴즈 정답에 남는 것 금지)
9. 파일 간 참조("N주차에서 배운")가 실제 그 파일 내용과 일치하는지 확인

# 하드 룰

- em-dash(—) 절대 금지, 하이픈(-) 사용. 수정 후 `grep -n "—"` 재확인
- 이모지·유니코드 기호(☑☐ 등) 금지, 체크박스는 CSS 사각형 span으로
- 새 CSS 발명 금지, 1주차-1의 기존 클래스(site-mock, layer-stack, layer-box, quote-box, checklist, compare-wrap, flow 등) 복사·재사용
- 구조 틀(meta-bar, callout, 본문, 체크포인트, summary-box, quiz-box) 유지
- 수정 후 div/span/table 태그 짝 균형 자체 검증

# 작업 방식

입력으로 받은 학생 피드백(막힘 지점 목록)을 하나씩 해소하되, 원칙과 충돌하면 원칙이 우선이다. 해소 방법은 설명 추가가 아니라 "더 구체적인 예시·시각화로 교체"를 우선 검토한다. 완료 후 어떤 피드백을 어떻게 해소했는지, 어떤 것은 왜 반영하지 않았는지(근거 포함) 보고한다.
