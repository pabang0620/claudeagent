# 절대 규칙

**원본 파일을 덮어쓰지 않는다.** 항상 새 파일로 산출하고, 산출 후 원본과 대조해 의도한 차이만 있는지 확인한 뒤 보고한다. 사용자가 "직접 수정해"라고 해도 먼저 원본 사본을 남긴다.

산출 파일명은 원본과 구분되게 짓는다(예: `원본명_v2.xlsx`, `원본명_수정.xlsx`). 기존에 같은 이름이 있으면 덮어쓰지 말고 확인한다.

# 도구

`openpyxl`(서식·병합·수식 유지)을 기본으로 쓴다. 대량 데이터 변환만 필요하면 `pandas`도 가능하지만, **서식이 있는 파일에 pandas로 쓰면 서식이 전부 날아가므로** 읽기 전용으로만 쓴다.

설치 확인:
```bash
python3 -c "import openpyxl; print(openpyxl.__version__)"
```
없으면 `pip install openpyxl --break-system-packages`로 설치한다.

# 작업 순서

1. 원본을 열어 **실제 구조를 먼저 파악한다** - 시트 목록, 헤더 행 위치, 병합 셀, 데이터 시작 행. 구조를 추측하지 말고 실측한다.
2. 파악한 구조를 사용자에게 한 줄로 요약 보고한 뒤 작업한다(구조 오해로 인한 재작업 방지).
3. 새 파일로 산출한다.
4. 산출물을 다시 읽어 검증한다 - 행·열 개수, 샘플 셀 값, 병합 유지 여부.
5. 무엇이 바뀌었는지 원본 대비 diff 형태로 보고한다.

# 서식 다룰 때 주의

- 병합 셀(`merged_cells`)이 있으면 행·열 삽입 시 병합 범위가 깨진다. 삽입 전 병합 범위를 기록하고 이후 재설정한다.
- 구분선·굵은 테두리는 `openpyxl.styles.Border`로 지정한다. 그룹 경계마다 넣을 때는 경계 행 인덱스를 먼저 계산해두고 일괄 적용한다.
- 열 너비(`column_dimensions`)는 자동으로 안 잡히므로 명시적으로 설정한다.
- 한글 헤더는 그대로 쓴다. 영문으로 바꾸지 않는다.

# 업로드 템플릿 생성 시

실제 시스템이 요구하는 컬럼명·순서·필수 여부를 먼저 확인한다. 확인할 근거 파일(기존 템플릿, 스펙 문서)이 있으면 반드시 Read해서 실측하고, 없으면 추측하지 말고 사용자에게 묻는다.
