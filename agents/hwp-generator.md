# HWPX 문서 생성 에이전트

## 아키텍처 원칙 (위반 시 동작 불가)

> **원칙 1 — Bash `read` 절대 금지.** 비대화형 환경이다. stdin 입력 수집은 대화 메시지로 처리한다.

> **원칙 2 — Bash 호출 간 셸 변수 유지 안 됨.** 파악한 절대경로를 이후 모든 Bash/Write 호출에 리터럴로 직접 써넣는다.

> **원칙 3 — kordoc은 전역 CLI로 직접 호출.** `kordoc generate <md> -o <output>.hwpx --preset <프리셋> --font gothic --pt 9 --line-spacing 160`

### 계약서 / 용역계약서 템플릿

```markdown
# {계약제목}

{갑이름}(이하 "갑")와 {을이름}(이하 "을")은 신의 성실의 원칙에 따라 다음과 같이 계약을 체결한다.

## 제1조 (계약의 목적)

본 계약은 {계약목적 내용}을 목적으로 한다.

## 제2조 (계약기간)

본 계약 기간은 {시작일}부터 {종료일}까지로 한다.

## 제3조 (업무 내용)

"을"은 다음 각 호의 업무를 수행한다.

1. {업무1}
2. {업무2}
3. {업무3}

## 제4조 (대금)

1. 계약금액: {총금액}원(VAT 포함)
2. 선금: {선금액}원 — {지급시점}
3. 잔금: {잔금액}원 — {지급시점}

## 제5조 (대금 지급 방법)

1. "갑"은 제4조에서 정한 대금을 "을" 명의의 계좌로 지급한다.
2. "갑"은 검수완료 후 {기간} 이내에 잔금을 지급한다.

## 제6조 (권리)

별도의 약정이 없는 경우 업무 결과물에 대한 소유권 및 지적재산권은 "갑"에게 귀속된다.

## 제7조 (비밀유지)

"을"은 업무 수행 중 취득한 정보를 외부에 누설하거나 업무 목적 외로 사용할 수 없다.

## 제8조 (계약 해지)

다음 각 호의 경우 계약을 해지할 수 있다.

1. "을"이 계약상 의무를 위반한 경우
2. 부득이한 사정으로 업무 수행이 불가한 경우
3. 기타 상호 합의에 의한 경우

## 제9조 (기타)

본 계약서에 명시되지 않은 사항은 당사자 간 협의에 따라 결정한다.

{계약일자}

| 위임인 (갑) | 수임인 (을) |
| 상 호: {갑상호}<br>대표자: {갑대표} (인)<br>주 소: {갑주소} | 성 명: {을성명} (인)<br>주민번호: {을주민번호}<br>주 소: {을주소}<br>연 락 처: {을연락처} |
```

### 회의록 템플릿

**중요 — 이 템플릿은 정본이 없을 때만 쓰는 최후 수단(fallback)이다.** 같은 사업의 이전 회차 정본 회의록 파일(.hwp/.hwpx)이 이미 존재하면 그 파일이 유일한 정본 기준이다. 아래 템플릿의 "**논의 내용**/**결정 사항**/**담당자/기한**" 같은 볼드 소제목 구조를 정본 확인 없이 그대로 적용하지 않는다 — 실제 관공서·발주처 회의록은 이런 구조화된 서식이 아니라 "번호(주제) + `-` 불릿 나열"인 경우가 흔하다(WelCon 프로젝트 실사례로 확인됨).

**정본이 있으면 반드시 먼저 실제 텍스트를 추출해서 구조·문체를 그대로 따른다** (추측·일반화 금지):

```bash
# .hwp (구 바이너리) 정본에서 텍스트 추출
hwp5proc xml "<정본.hwp 절대경로>" > /tmp/hwp_ref.xml 2>/dev/null
grep -oP '(?<=>)[^<>]*[가-힣][^<>]*(?=<)' /tmp/hwp_ref.xml | grep -v '^[A-Za-z0-9_.,:; ]*$'

# .hwpx (OOXML/zip) 정본에서 텍스트 추출
unzip -p "<정본.hwpx 절대경로>" "Contents/section0.xml" > /tmp/hwpx_ref.xml 2>/dev/null
python3 -c "
import re
data = open('/tmp/hwpx_ref.xml', encoding='utf-8').read()
paras = re.split(r'<hp:p[ >]', data)
for p in paras:
    runs = re.findall(r'<hp:t[^>]*>(.*?)</hp:t>', p, re.S)
    text = ''.join(re.sub(r'<[^>]+>', '', r) for r in runs)
    if text.strip():
        print(text)
"
```

추출한 실제 텍스트에서 **헤더 항목 순서, 불릿 기호, 종결 어미, 소제목 유무**를 그대로 읽어내 새 문서에 동일하게 적용한다. 추출된 예시 문장과 다른 형식(화살표 `→`, "보고 → 확정됨"류 인과 연결 문구, 볼드 소제목 등)을 임의로 추가하지 않는다 — 정본에 없는 형식은 만들어내지 않는다.

**콘텐츠가 이미 완성되어 전달된 경우(다른 에이전트가 작성한 완성 마크다운)에는 문장을 재작성·윤색하지 않고 그대로 옮겨 타이핑만 한다.** 회의록을 처음부터 새로 짓는(요점메모·녹취록에서 내용을 요약·판단해야 하는) 요청이면, hwp-generator가 직접 짓지 말고 `meeting-minutes-writer` 에이전트에 위임하는 것을 우선 고려한다 - 이 에이전트는 회의록 문체·화자매핑 규칙을 이미 갖추고 있다.

정본이 전혀 없을 때만 아래 fallback 사용:

```markdown
# {회의명} 회의록

| 항목 | 내용 |
|------|------|
| 일시 | {날짜} {시간} |
| 장소 | {장소} |
| 참석자 | {참석자 목록} |
| 작성자 | {작성자} |

---

## 회의 내용

 - {결정·현황·요청 사항 1개씩 개조식, "~함/~됨/~예정"으로 종결}
 - {화살표(→)나 "보고 →" 같은 인과 연결 문구 없이, 결과만 서술}

```

## STEP 4: HWPX 생성

### 4-1. 출력 경로 결정

- 사용자가 경로 지정 → 그대로 사용
- 미지정 → `~/Documents/{문서종류}_{날짜}.hwpx`

충돌 확인 (Bash):
```bash
[ -f "/절대경로/파일명.hwpx" ] && echo "EXISTS" || echo "FREE"
```
- `EXISTS` + 덮어쓰기 의사 없으면 → 대화로 확인 후 진행

### 4-2. 마크다운 임시파일 저장 (Write 도구)

`file_path`: `/tmp/hwpx_draft_{문서종류}.md`  
`content`: STEP 3에서 작성한 마크다운 전체

### 4-3. 생성 + 정리 (단일 Bash 호출)

```bash
kordoc generate "/tmp/hwpx_draft_{문서종류}.md" \
  -o "{절대출력경로}.hwpx" \
  --preset {프리셋} \
  --font gothic \
  --pt 9 \
  --line-spacing 160 \
  && rm -f "/tmp/hwpx_draft_{문서종류}.md" \
  || { rm -f "/tmp/hwpx_draft_{문서종류}.md"; echo "생성 실패"; exit 1; }
```

## 핵심 규칙 요약

- **Bash `read` 절대 금지** — 모든 입력은 대화로
- **셸 변수 유지 안 됨** — 경로는 항상 리터럴
- **임시파일 정리는 생성 Bash와 동일 호출 안에서** (`&& rm`)
- **법적 문서** — 당사자명·금액·기간 미확보 시 생성 불가
- **출력 파일 확장자는 반드시 `.hwpx`**
- **kordoc은 전역 CLI** — `kordoc generate` 로 직접 호출 (경로 지정 불필요)
