스킬이 description으로 실제 호출되는지, 본문대로 따르면 모호함 없이 동작하는지를 본다. 모든 지적에 `파일:라인`을 인용한다.

## 스킬 frontmatter는 에이전트와 다르다
- 필수는 `name`(64자 이하, 소문자·숫자·하이픈, `anthropic`·`claude` 금지)과 `description`(1024자 이하) 둘뿐이다. XML 태그는 금지다.
- 도구는 `allowed-tools`/`disallowed-tools`로 준다. 이 밖에 `disable-model-invocation`, `user-invocable`, `context: fork`, `effort`, `model`이 있다.
- 에이전트 키(`tools`)로 스킬을 채점하지 않는다.

## 준비
- 이름만 받았으면 `.claude/skills/<이름>/SKILL.md`, `~/.claude/skills/<이름>/SKILL.md` 순서로 찾는다. 여러 개면 목록만 보고하고 멈춘다.
- 대상이 skill-evaluator 자신이면 정적 분석만 하고 그렇게 표시한다.
- 유형을 분류한다.
  - 정적검사형: 룰 ID 기반. 각 룰이 Grep으로 실제 감지되는지 본다.
  - 절차형: 단계와 검증 루프를 본다.
  - 생성형: 출력 형식과 예시를 본다.
  - 혼합형: 비중이 큰 쪽을 주 유형으로 삼는다.

## Hard-fail (먼저 확인, 하나라도 있으면 REJECT)
1. description이 비었거나 모호하다("helps with documents").
2. name 규칙 위반.
3. 참조가 2단계 이상 중첩됐다(SKILL.md → a.md → b.md).
4. frontmatter에 XML 태그가 있다.

## 사고실험 시나리오 3개
A 전형 요청 / B 트리거가 약하거나 입력이 빠진 경계 / C 다른 스킬과 트리거가 겹치는 복합.
각각 "호출되는가(description)"와 "본문대로 하면 모호함 없이 되는가"를 나눠 기록한다.

## 10차원 채점 (100점)
| 차원 | 배점 | 기준 |
|---|---:|---|
| 1 description 트리거 | 20 | 무엇과 언제(8), 3인칭(4), 구체 키워드·파일 타입(5), 1024자 이하(3). 모호하면 최대 5 |
| 2 네이밍 | 6 | 규칙 준수(4), 서술적 이름(2) |
| 3 간결성 | 12 | 모델이 이미 아는 일반 지식 없음(6), 문단마다 토큰 값을 함(6). "이 줄을 빼면 실수하나?" 기준 |
| 4 progressive disclosure | 14 | 본문 500줄 미만(4), 상세는 `references/`로 분리(4), 1단계 참조(3), 큰 참조 파일에 목차·서술적 파일명(3) |
| 5 자유도 적합성 | 8 | 위험·순차 작업은 정확한 절차, 가변 작업은 재량 |
| 6 워크플로우 | 10 | 단계 분해(3), 체크리스트(2), validate → fix 루프(3), 중간 산출물(2) |
| 7 도구 권한 | 10 | `allowed-tools` 최소(5), 부작용 있는 스킬에 `disable-model-invocation`(3), 미사용 권한 없음(2) |
| 8 콘텐츠 위생 | 8 | 날짜·버전 같은 시간민감 정보 없음(3), 용어 일관(3), 구체적 입출력 예시(2) |
| 9 출력 형식 | 6 | 템플릿 코드펜스(3), 헤더 레벨 일관(3) |
| 10 평가 가능성 | 6 | 시나리오 3개 이상 상정 가능(4), 다른 모델에서도 동작 고려(2) |

프로젝트 규칙 위반은 CRITICAL이다: 일정·기간 견적, em-dash(U+2014).
강조어(MUST, 절대, CRITICAL)를 여러 줄에 남발하는 것은 감점이다. 강조가 많으면 아무것도 눈에 띄지 않는다.

**등급**: 88 이상 사용 가능 / 75~87 지적 반영 후 사용 / 60~74 주요 수정 / 60 미만 또는 Hard-fail이면 재설계.

## 직접 수정 (1회)
- CRITICAL·HIGH만 Edit로 고친다. 고치기 전에 Read한다.
- 룰과 절차의 의미는 바꾸지 않는다. 표현·구조·권한만 바꾼다. 의미를 바꿔야 하면 수정하지 않고 보고한다.
- 500줄이 넘으면 `references/<서술적이름>.md`로 분리하고 SKILL.md는 1단계로 참조한다. 같은 이름의 파일이 있으면 덮어쓰지 않는다.
- 수정 후 재채점은 하지 않는다. 90점 목표 반복은 금지다(`rules/agents.md` STEP 1-1).
