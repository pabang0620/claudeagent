## 1. 안전 (매번)
- 열린 파일과 같은 경로로 `Presentations.Open` 후 `.Close()` 절대 금지. 비교는 스크래치패드 복사본을 열고 `FullName`이 다른지 확인 (R028).
- 열린 창에 `.Save()`·`.Close()` 금지, 저장은 아비님. 이름에서 장군어니를 뺀 파일도 아비님이 열어 두고 요청했으면 같음 (R029)(R084). 큰 작업 전에는 한 번 저장(백업)을 권한다 (M04).
- **PowerPoint 프로그램 `Quit()` 금지** (렌더 전에 열린 창이 0개였을 때만 예외). 2026-10-20 렌더 스크립트가 Quit해서 아비님 PPT가 꺼진 사고가 있었다.
- 이름에 `장군어니` = 아비님과 같이 작업하는 파일 (R083). 산출물 안에 어니·장군어니 흔적 금지 (R085).
- 아비님이 같이 안 보는 혼자 작업은 숨긴 인스턴스에서, 결과는 `어니부기_vX.Y.Z`(첫 v0.1.1) 새 파일 (M05)(R086).
- 업무폴더(`D:\01_2026\...`) 기존 파일 수정·삭제·덮어쓰기는 승인 후 (R087). 새 산출물이 기존 동명 파일과 겹치면 덮어쓰지 말고 묻는다.
- 도형·슬라이드 삭제는 요청 범위 안에서만, 하고 나서 보고 (R030).
- 같은 도형 동시 편집·Ctrl+Z는 섞일 수 있으니 큰 작업 전 알린다 (R007). 붙여넣기는 클립보드를 쓰므로 미리 알린다 (R019).
- 어니가 연 임시 파일·복사본·창은 끝나면 닫는다. 아비님 창은 절대 닫지 않는다 (M06).
- PowerShell을 `timeout`으로 끊으면 Windows 쪽 powershell.exe가 계속 돌며 열린 PPT를 고칠 수 있다. 끊은 뒤에는 `Get-CimInstance Win32_Process`로 그 스크립트를 찾아 종료한다.
- 글 바꾸기를 반복문으로 돌릴 때 바꿀 글이 찾을 글을 포함하면 끝나지 않는다(2026-10-20 같은 문장 13,595번 삽입 사고). 반복 횟수 상한을 두고, 오래 걸리면 Windows 쪽 프로세스부터 찾아 끈다.

## 2. 작업 방식 (속도)
- `GetActiveObject('PowerPoint.Application')`로 붙고, 대상은 ActivePresentation 또는 FullName으로 찾은 창 (R004)(R005).
- 일하기 전에 열린 파일을 다시 읽는다. 설명·보고도 지금 파일 기준(아비님이 그사이 고쳤을 수 있음) (N14).
- 바꿀 값·서식을 먼저 다 정하고 **표 하나당 스크립트 한 번** (R026). 새 표는 내용·서식을 한 번에 정의해 python-pptx 임시 pptx로 완성 → 복사·붙여넣기 (R017).
- **COM으로 칸마다 서식(채움·글꼴·테두리)을 넣지 않는다.** 290칸을 칠하다 5분을 넘겨 끊긴 적이 있다. 새 표·새 장·큰 도형 묶음은 python-pptx 임시 pptx로 만든 뒤 넣고, COM은 글 바꾸기·위치·크기·행 높이·열 너비·번호 박스 이동 같은 작은 일에만 쓴다. 오래 걸릴 작업은 처음부터 백그라운드로 돌리고 진행 중이라고 알린다.
- 글만 바꿀 때는 `TextRange.Replace`로 서식을 살린다 (R010). 새 글은 바로 위 칸 서식에 맞춘다 (M02). 새 내용은 기존 모양을 복제한다 (M07).
- 파일 전체 글꼴 변경은 `Presentation.Fonts.Replace`. 마스터·레이아웃도 바뀌니 맞는지 먼저 확인 (R020)(R022).
- 표 여백은 처음 한 번만 넣고 크기·높이만 계산 (R015).
- 표 높이는 바로 갱신되지 않는다. 넘침은 칸마다 `BoundHeight + 위·아래 여백`으로 계산한다 (R012). 행 높이는 늘 때만 저절로 바뀌므로 고친 행·머리글 행은 직접 지정한다 (N03)(R077).
- 표 행을 지우면 그 아래 주석·번호 박스를 같은 높이만큼 올린다 (N05).
- ID·코드 번호를 바꾸면 본문·참고 줄의 옛 값도 함께 바꾸고, 남은 건수 0을 확인한다 (N07).
- 코드·개수가 바뀌면 영향 장을 모두 맞춘다: 장 칩·기능설명·통계 표·카드(4장)·개요(3장) (N11).
- 장 순서는 관련된 것끼리 흐름대로 묶는다(개요 → 데이터 넣기 → 계산식·배점표 → 결과·계산 순서 → 설정 → 화면 표시). 묶음마다 PowerPoint 구역(`SectionProperties.AddBeforeSlide`)을 만들고, 장 이동은 `Slide.MoveTo`(SlideID로 찾아서).

## 3. 서식 (화면설계서)
- 구간: 개요(위 Group 25: 작업유형·제목·페이지 ID·버전·작성자) / 기능설명(오른쪽 Group 1019) / 기획(그 사이) (R032).
- 대상 아님: 표지·개정이력(1~2장) (R052), 3장 개요 페이지는 글꼴 규칙 제외(원래 글꼴·크기) (R051).

| 구간 | 글꼴 | 크기 |
|---|---|---|
| 개요 | 맑은 고딕 테마(`+mn-lt`/`+mn-ea`) (R033) | 8, 제목(Rectangle 7)만 10 굵게 (R034) |
| 기능설명 | 맑은 고딕 테마 (R033) | 7 (R035) |
| 기획 본문·표 | `Pretendard GOV`(이름 정확히), 굵은 강조는 GOV 계열 (R038)(R039) | 10, 표는 모자라면 9→8 (R040) |
| 표 위 제목 띠 | Pretendard GOV | 10 (R043) |
| ※ 주석·범례 칩 | Pretendard GOV | 8 (R042) |

- 강조(굵게·색)는 살리고 14 이상 큰 숫자는 그대로 (R041).
- 기획 글상자: 여백 사방 0.1cm + '도형을 텍스트 크기에 맞춤'(`TextFrame2.AutoSize=1`). 번호 박스·상태 칩 같은 고정 크기 도형은 제외 (R044)(R045).
- 표 칸 여백 사방 0.1cm(2.835pt) (R046).
- 기능설명 행은 글 높이에 딱 맞게, 빈 행은 모두 같은 최소 높이 (R036).
- 안내선(빨강): 위 74·왼 21·오 741·아래 508 (R064). 기획 내용은 위·왼·오른쪽 끝을 딱 맞추고 아래는 508 안 (R065)(R066). 값은 작업 전에 다시 읽는다 (R067).
- 다른 도형은 함부로 옮기지 않는다 (R048). 예외: 기획에 세로 공간이 남으면 글자를 줄이지 말고 아래 도형을 내려 10을 유지(테두리 안) (R037).
- 칸 글이 넘치거나 꺾일 때 순서(아비님 결정 2026-10-26): ① 열 너비 조정(여유 열을 줄이고 꺾이는 열을 늘림, 표 전체 너비 유지) ② 행 높이 줄이기 ③ 글자 9 → 8(6자리 코드가 꺾이면 그 칸만) ④ 그래도 안 되면 보고 (R050)(R047)(R049).
- 빨간 번호 박스 = 기능설명 번호 1:1. 설명하는 도형 모서리(보통 오른쪽 위·왼쪽 위)에 붙이고, 안내선 밖으로 나가지 않게 (R068)(R069)(R070).
- **겹침 금지**: 표가 늘어나면 아래 막대·표를 내린다. 막대·소제목 위로 12pt 이상 띄우고, 작업 뒤 도형끼리 일부만 겹치는 곳이 없는지 전 장 검사한다(완전히 안에 든 글상자는 제외).
- **한 글자 줄바꿈 금지**: 문단 마지막 줄이 1~4글자면 뜻을 유지한 채 표현을 줄이거나 줄을 반반 나눈다. 고친 뒤 COM `Paragraphs().Lines()`로 전 장 다시 검사해 0건을 확인한다.
- 구간·점수처럼 "/"로 나열한 값은 표로 나눈다(구간 1~N 열, 항목마다 기준 행·점수 행 2줄, No·묶음·항목은 세로 병합).

## 4. 페이지 ID·화면 ID·참고 표기
- 형식 `1단계-2단계-3단계-4단계`. 예: 페이지 ID `KR-SUB-MYPG-02`, 화면 ID `KR-SUB-MYPG-02-006` (R053).
  - 1단계 AL(공통)·KR(국문)·EN(영문)·MP(마켓플레이스)·ET(기타) (R054) / 2단계 MAN(메인)·SUB(서브)·ETC(기타) (R055) / 3단계 USER(사용자)·MYPG(마이페이지)·ADMN(관리자) (R056) / 4단계 01(페이지, 2자리)·001(화면, 3자리) (R058)
  - 국내·해외 공통 기능은 AL, 국문 전용은 KR (WAS-02: 포지션 AL, 상세장르 KR) (R057).
- 3장(개요)·4장(통계)을 뺀 모든 기획 장에 페이지 ID·화면 ID를 넣고 비워 두지 않는다. 지금 ID가 빈 장이 있으면 지어내지 말고 보고한다 (R061)(R076). 페이지 번호는 그 문서 안에서 01부터 매기고 초안의 번호를 가져오지 않는다.
- 같은 페이지 ID 안 화면 ID는 장 순서대로 빠짐·중복 없이. 장을 넣거나 빼면 뒤 번호를 다시 맞추고 보고 (R059). 새 장은 앞뒤 장 페이지 ID에 이어 매긴다 (R062).
- 어느 단계·페이지인지 자료로 모르면 슬라이드에 적지 말고 아비님께 묻는다 (R060)(R062).
- 다른 장과 관련된 기능설명은 그 항목 맨 끝 줄에 `> 참고 : 화면ID`. 장 번호("16장", "다음 장") 대신 화면 ID (R071).
  - 서식: 맑은 고딕 7, `> 참고 :` 글자색 #262626, 화면 ID는 텍스트1 색 + 노란 형광펜(ID 글자에만). 굵게·밑줄·링크 없음 (R072). 줄 하나에 ID 하나 (R073).
  - 같은 파일 안: `AL-SUB-USER-02-011` (R074).
  - 다른 파일 참조(`WAS-01_KR-SUB-USER-02-001`)는 넣지 않는다. 아비님이 요청할 때만(아비님 결정 2026-10-26) (R075).

## 5. 문구
- 아비님(PM)이 직접 쓴 것처럼 개조식(~함·~임·~필요). 어니·AI·"제가 판단"·대화체·작업 과정 금지 (R078).
- "확인 필요"·"협의 필요" 등 서로 협의가 필요한 듯한 문구는 기능설명·주석·표 어디에도 넣지 않는다. 마지막 '확인 필요 사항' 장·표도 만들지 않는다. 모든 것을 확인한 뒤에 PPT를 만든다(사용자 설계 방식). 정할 일은 아비님께 물어 결정을 받은 뒤 결정 내용만 쓴다 (R079)(R081)(R089).
  - 결정 권한을 넘기는 표현("자체 DB 설계 정책 우선", "내부 정책에 따름")은 쓸 수 있다 (R080).
- 자료에 없는 숫자·코드·이름은 지어내지 않는다. 꼭 넣어야 하면 "(가칭)" + 보고 (R088).
- 내부 파일 근거(파일명·버전·"○주차 기준") 금지. 필요하면 "첨부파일 : 파일명" 한 줄 (R082).
- IDC(개발사)가 질문 없이 개발하게: 테이블·컬럼·코드값·계산식·배치·예외·검사 문구·권한·기본값까지. 기존 테이블·코드 재사용, 하드코딩 대신 설정값 (M08).
- DB 기획 전에 웰콘 DB 정의서에서 기존 테이블부터 찾는다(ref 5) (M09).
