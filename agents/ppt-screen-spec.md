## 일하는 방식 1: 새 화면설계서 만들기

1. 계획을 먼저 보여 주고 승인을 받는다: 장 목록(장마다 한 메시지), 쓸 원본 장, 파일 이름·위치
2. 원본을 작업 폴더에 복사해 python-pptx로 만든다(`lib.py`). 장 틀 복제는 원본 장의 도형을 deepcopy, 원본 장은 sldIdLst에서 빼고 rel을 끊는다
3. `render.ps1`로 전 장 PNG를 뽑아 넘침·겹침을 확인하고 고친다. 확인한 장 번호를 보고에 적는다
4. 새 파일로 저장한다. 같은 이름 파일이 있으면 덮어쓰지 않고 묻는다

## 일하는 방식 2: 열린 PPT 실시간 수정

- PowerShell에서 `[Runtime.InteropServices.Marshal]::GetActiveObject('PowerPoint.Application')`로 붙는다. 대상은 `Presentations`에서 **이름(FullName)으로 찾은** 창
- 슬라이드는 번호로 다룬다(`Slides(n)`). 사용자가 같은 도형을 동시에 고치거나 Ctrl+Z를 누르면 섞일 수 있으니 큰 작업 전에는 알린다
- 글만 바꿀 때는 `TextRange.Replace(찾을 글, 바꿀 글)`로 서식을 살린다. 칸 전체를 새로 쓰면 첫 글자 서식을 따른다
- 구조가 크게 바뀌면(장 여러 개, 표 새로 짜기) 새 파일로 만든 뒤 `live.ps1`로 그 장만 바꿔 끼운다
- 한글이 들어간 .ps1은 **UTF-8 BOM**으로 저장한다(PowerShell 5.1). 문자열 안 `$r:` 같은 표기는 `${r}`
- 표 높이(`Shape.Height`, `Rows(r).Height`)는 글을 바꿔도 바로 갱신되지 않는다. 넘침은 칸마다 `TextRange.BoundHeight + 위·아래 여백`으로 계산한다
- 표 칸 여백은 COM에 표 전체 속성이 없어 칸 반복으로 넣는다. 여백은 처음 한 번만 넣고, 크기 후보마다 넣었다 빼지 않는다
- **새 표 만들기 = 한 번에**: 열린 장에서 빈 표를 만들고 칸마다 채우며 여러 번 고치지 않는다. 내용과 서식(글꼴·크기·굵기·색·바탕·여백 0.1cm·열 너비·병합)을 한 번에 정의해 `python -I`의 python-pptx로 스크래치패드 임시 pptx에 표를 완성 → 임시 파일을 COM으로 열어(FullName 다른지 확인) 표 `Copy()` → 대상 장 `Shapes.Paste()` → 위치·크기 지정 → 임시 파일만 닫기. 붙여넣기는 클립보드를 쓰므로 사용자가 복사 중일 수 있으면 미리 알린다
- **글꼴 일괄 변경 = 글꼴 바꾸기**: 파일 전체에서 글꼴 하나를 다른 글꼴로 바꿀 때는 칸·런을 돌지 말고 `Presentation.Fonts.Replace("원래 글꼴", "새 글꼴")`(홈 > 바꾸기 > 글꼴 바꾸기와 같음)을 쓴다. 굵기별 이름이 따로라 `Pretendard SemiBold` 등은 이름마다 한 번씩. 마스터·레이아웃까지 같이 바뀌므로 그게 맞는지 먼저 확인하고, 일부 구간만 바꿀 때만 칸 단위로 한다. 바꾼 뒤 꺾임·넘침 점검은 바뀐 장 몇 장만
- **기존 표 수정도 표 하나당 스크립트 한 번**: 바꿀 값·서식을 먼저 다 정해 두고 한 번에 적용한 뒤 캡처로 확인. 만들고→보고→또 고치는 반복을 줄인다
- 확인은 `Slide.Export(경로, 'PNG', 1600, 900)`로 캡처해서 본다

## 속도: 빠른 방법을 기본으로 (2026-10-20 실측)

- **COM으로 칸마다 서식(채움·글꼴·테두리)을 넣지 않는다.** 표 290칸을 칸마다 칠하다 5분을 넘겨 끊겼다
- 새 표·새 장·큰 도형 묶음은 **python-pptx로 임시 pptx에 만든 뒤** 넣는다(몇 초)
  - 도형·표 하나: 임시 파일을 COM으로 열어(경로가 다른지 FullName 확인) `Shapes.Item(이름).Copy()` → 열린 장 `Shapes.Paste()` → 위치 지정 → 임시 파일 `Close()`. 예시 `paste_table_example.py`·`.ps1`
  - 장 통째로: `live.ps1`(InsertFromFile로 같은 번호 장 교체)
  - 장 복제는 열린 PPT에서 `Slide.Duplicate()`
- COM은 작은 일에만: 글 바꾸기(`TextRange.Replace`), 위치·크기, 행 높이, 열 삭제·너비, 번호 박스 옮기기
- 행 높이 맞추기: 모든 행 `Height=1`로 줄인 뒤 가장 큰 높이를 읽어 전부 그 값으로(표 하나에 1초 안쪽)
- PowerShell을 `timeout`으로 끊으면 Windows 쪽 powershell.exe가 계속 돌며 열린 PPT를 고칠 수 있다. 끊은 뒤에는 `Get-CimInstance Win32_Process`로 그 스크립트 프로세스를 찾아 종료한다
- 오래 걸릴 작업은 처음부터 백그라운드로 돌리고, 사용자에게 진행 중이라고 알린다

- 글 바꾸기를 반복문으로 돌릴 때 바꿀 글이 찾을 글을 포함하면 끝나지 않는다(2026-10-20 같은 문장 13,595번 삽입 사고). 반복 횟수 상한을 두고, 오래 걸리면 Windows 쪽 프로세스부터 찾아 끈다

## 절대 금지

- **열린 파일과 같은 경로를 `Presentations.Open` 후 `.Close()` 하지 않는다.** 같은 창이 돌아와 사용자 창이 저장 없이 닫힌다. 비교·렌더는 파일을 **복사**한 뒤 복사본을 열고, 열자마자 `FullName`이 다른지 확인한다
- **PowerPoint 프로그램을 `Quit()` 하지 않는다**(렌더 전에 열린 창이 0개였을 때만 예외). 2026-10-20 렌더 스크립트가 Quit해서 사용자 PPT가 꺼진 사고가 있었다
- 열린 창에 `.Save()`·`.Close()` 하지 않는다. **저장은 사용자가 한다.** 도형·슬라이드 삭제는 요청 범위 안에서만 하고 보고한다

## 화면설계서 규칙

- 구간: **개요**(위쪽 Group: 작업유형·제목·페이지 ID·버전·작성자), **기능설명**(오른쪽 번호 표 Group 1019), **기획**(그 사이 본문·표)
- 개요·기능설명 글꼴은 **맑은 고딕**. 테마 글꼴로 넣는다: `Font.Name='+mn-lt'`, `Font.NameFarEast='+mn-ea'`
  - 개요: 크기 8, 단 제목만 10 + 굵게
  - 기능설명: 크기 7
- 기능설명 표 세로 정리: 각 행을 글 높이에 딱 맞게 줄이고, 빈 행은 모두 같은 최소 높이
- 기획: **Pretendard GOV 10** (글꼴 이름 정확히 `Pretendard GOV`, 2026-10-20 Pretendard에서 변경. 굵은 강조는 `Pretendard GOV SemiBold/ExtraBold` 등 같은 GOV 계열. 글꼴 파일은 `welcon/ppt-reference/font/`, 윈도우에는 PretendardGOV OTF가 설치돼 있음). 표는 자리가 모자라면 9 → 8까지. 원래 강조(굵게·색)는 살리고 큰 강조 숫자(14 이상)는 그대로. 주석·범례 칩은 8
- **겹침 금지**: 표가 늘어나면 아래 막대·표를 내린다. 막대·소제목 위로 12pt 이상 띄우고, 작업 뒤 도형끼리 일부만 겹치는 곳이 없는지 전 장 자동 검사한다(완전히 안에 든 글상자는 제외)
- 기획 구간에 세로 공간이 남으면 글자를 줄이지 말고 아래 도형을 그만큼 내린다. 맨 아래 도형이 테두리 선을 넘지 않는 범위에서만
- 표 칸 여백은 넘치지 않으면 **왼·오·위·아래 모두 0.1cm(2.835pt, 36000 EMU)** (사용자 에이전트 기준 2026-10-20, WAS-02 값보다 우선)
- 넘칠 때 순서: ① 행 높이 줄이기 → ② 글자 9 → 8 → ③ 그래도 넘치면 보고. 기획 구간은 테두리 선을 넘지 않게만 조정하고 다른 도형은 함부로 옮기지 않는다
- **표 크기 단계(WAS-02 실측, 2026-10-20)**: 표 글자 10 + 행 높이 최소 17.7pt(0.246in)에서 시작하고, 아래 선을 넘으면 10/14.8 → 9/14.8 → 9/14.0 → 9/13.2 → 8/12.5 순으로 낮춘다. 막대 높이 15.6pt, 막대 글자 8.5~10. 표를 옮길 때 위에 있는 막대 아래로 들어가지 않게 한다(막대가 표 영역 안에 들어가면 겹침 검사에서 빠지므로 따로 확인)
- **행 높이는 표마다 통일한다**(머리글 행 제외): 모든 행을 가장 높은 행(줄바꿈 있는 행)에 맞춘다. 표가 길어지면 아래 도형을 그만큼 내리고, 508을 넘으면 ① 열 너비 다시 나누기 ② 글자 9 → 8 ③ 표를 두 장으로 나누기 순서로 맞춘다
- 열 너비는 칸 글 길이를 재서 나눈다(PIL + 대체 글꼴 malgun.ttf/malgunbd.ttf로 글 폭 측정 → 필요한 폭 합이 표 너비 안이면 남는 폭을 비례 배분, 넘으면 긴 열만 줄바꿈 허용)
- **빨간 번호 박스 위치는 가리키는 구역이 시작하는 곳 바로 왼쪽**(사용자 지시 2026-10-20): 박스 오른쪽 끝 = 막대·표·상자의 왼쪽 끝, 박스 위 = 그 구역 위(-1pt). 맨 왼쪽 구역이면 안내선(21) 바깥으로 나가도 된다. 표의 특정 열을 가리키면 그 열이 시작하는 곳 왼쪽(머리글 높이). 열 너비를 바꾸면 박스도 다시 맞춘다
- 구간·점수처럼 "/"로 나열한 값은 표로 나눈다(구간 1~N 열, 항목마다 기준 행·점수 행 2줄, No·묶음·항목은 세로 병합)
- 6자리 코드 번호가 두 줄로 꺾이면 그 칸만 9 → 8
- 칸 글이 꺾일 때는 **열 너비 조정이 먼저**: 여유 많은 열을 줄이고 꺾이는 열을 늘린다. 표 전체 너비는 유지
- **장 순서는 관련된 것끼리 묶어 흐름대로**(사용자 지시 2026-10-20): 예) 개요 → 데이터 넣기(테이블·적재) → 계산식·배점표 → 결과·계산 순서 → 설정 → 화면 표시. 묶음마다 PowerPoint 구역(`SectionProperties.AddBeforeSlide`)을 만들어 왼쪽 목록에서 접고 펼 수 있게 한다. 장 이동은 `Slide.MoveTo`(SlideID로 찾아서)
- **말투**(사용자 지시 2026-10-20): 기획 구간(본문·표·막대)은 짧은 목록형 명사형으로 쓴다(예: "웰콘 관리자 페이지 이관", "배점 수정 시 즉시 재계산"). "~한다/~이다" 문장으로 끝내지 않는다. 오른쪽 기능설명은 존댓말 문장(~합니다/~입니다), 첫 줄은 굵은 제목
- **문구 주체**: 슬라이드 글은 PM이 직접 쓴 것처럼 쓴다. AI·"제가 판단"·대화체·작업 과정 설명을 넣지 않는다. 기획 구간은 기획자 개조식(~함, ~임, ~필요)도 허용
- **한 글자 줄바꿈 금지**: 문단 마지막 줄이 1~4글자면 뜻을 유지한 채 표현을 줄이거나 줄을 반반 나눈다. 고친 뒤 COM `Paragraphs().Lines()`로 전 장 다시 검사(0건 확인)
- **참고**(사용자 지시 2026-10-20): 기능설명 칸 안, 그 번호 설명 끝에 빈 줄 하나(엔터 2번) 띄우고 "참고 :" 다음 줄바꿈, 그 아래 한 줄에 하나씩 화면 ID만(설명 글 없이) 형광 노랑(`TextFrame2...Font.Highlight.RGB`)으로 쓴다. 여러 개면 항목마다 줄을 나눠 화면 ID가 줄 중간에서 끊기지 않게 한다. 본문 아래에 따로 참고 줄을 두지 않는다. 장 번호 대신 화면 ID로 가리킨다
- **ID 부여**(사용자 지시 2026-10-20): 표지·개정이력을 뺀 모든 장(개요 포함)에 채운다. 페이지 번호는 그 문서 안에서 01부터 매긴다(초안의 31·34 같은 번호를 가져오지 않는다). 같은 화면 묶음은 같은 페이지 ID, 화면 ID는 장 순서대로 001부터. ID를 바꾸면 참고·표에 적힌 ID도 함께 바꾼다
- 3장은 개요 페이지라 글꼴 규칙에서 뺀다(원래 글꼴·크기 유지). 표지·개정이력(1~2장)도 대상 아님
- **페이지 ID·화면 ID**: `1단계-2단계-3단계-4단계`로 이어 붙인다. 예: 페이지 ID `KR-SUB-MYPG-02`, 화면 ID `KR-SUB-MYPG-02-006`
  - 1단계: AL(공통), KR(국문), EN(영문), MP(마켓플레이스), ET(기타)
  - 2단계: MAN(메인), SUB(서브), ETC(기타)
  - 3단계: USER(사용자), MYPG(마이페이지), ADMN(관리자)
  - 4단계: 01(페이지 ID, 2자리), 001(페이지 안 화면 ID, 3자리)
  - 같은 페이지 ID 안 화면 ID는 장 순서대로 빠짐·중복 없이. 장을 넣거나 빼면 뒤 번호를 다시 맞추고 보고. 어느 단계인지 자료로 알 수 없으면 지어내지 말고 비워 두고 보고
- **안내선**: 빨강 = 마스터(`SlideMaster.Guides`), 주황 = 레이아웃(`CustomLayout.Guides`), 회색 = 슬라이드(`Presentation.Guides`). 화면설계서 빨강 안내선은 위 y=74, 왼쪽 x=21, 오른쪽 x=741, 아래 y=508(pt, 슬라이드 960×540). 기획 구간의 위·왼쪽·오른쪽 끝을 여기에 딱 맞추고 아래는 508을 넘지 않게. 작업 전에 값을 다시 읽어 확인
- **빨간 번호 박스**: 기능설명 표 번호와 1:1(기능설명에 없는 박스, 박스 없는 기능설명 번호가 없게). 위치는 아래 '빨간 번호 박스 위치' 규칙
- 산출물에 내부 근거(파일명·버전·"○주차 기준")를 넣지 않는다. 필요하면 "첨부파일 : 파일명" 한 줄만

## 파일 규칙

- 새 산출물은 새 파일로 만든다. 기존 파일 수정·삭제·덮어쓰기는 승인 후에만
- 자료에 없는 숫자·코드·이름은 지어내지 않는다. 설계 산출물에는 확실한 것만 넣고, 모르는 것은 보고로 돌린다
- 작성자 칸은 사용자가 알려 준 이름만 넣는다(모르면 비움)
