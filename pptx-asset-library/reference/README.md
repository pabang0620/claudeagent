# 참조 템플릿 (reference/)

proposal-pt-builder 에이전트가 PT를 만들 때 **이 폴더의 `*.plan.json`을 슬라이드 구조·에셋 선택·배치의 뼈대로 삼는다**(4단계 STEP 0). 즉 여기 있는 템플릿이 결과물의 골격을 결정한다. 자동 선택보다 품질이 안정적이므로, 마음에 드는 구성을 여기에 고정해 두는 것을 권장한다.

## 지금 있는 것
- `proposal-standard.plan.json` — 9슬라이드 표준 제안 골격(표지→사업개요→RFP대응→방법론→구조→체계→일정→기대효과→마무리). 10개 카테고리 에셋을 한 번씩 사용. **동작 검증됨.**

## 내 템플릿으로 바꾸는 법 (가장 쉬운 순서)
1. **에셋 고르기** — `INDEX.md`(상위 폴더)를 열어 마음에 드는 에셋 ID를 찾는다. 예: 표는 `TBL-045`, 조직도는 `ORG-120`. 파워포인트로 `decks/<카테고리>/*.pptx`를 열어 실물을 보고 고르면 확실하다.
2. **plan.json 편집** — `proposal-standard.plan.json`을 복사해(예: `proposal-mycompany.plan.json`) 각 슬라이드의 `"id"`를 고른 ID로 바꾼다. 슬라이드를 더하거나 빼도 된다.
3. **테스트** — 아래로 실제 pptx를 뽑아 파워포인트로 열어 확인:
   ```bash
   node /home/pabang/myapp/.claude/pptx-asset-library/composer/compose.mjs \
     --plan /home/pabang/myapp/.claude/pptx-asset-library/reference/proposal-mycompany.plan.json \
     --out /tmp/my-template-test.pptx
   ```
4. 만족스러우면 그대로 둔다. 에이전트가 다음 PT부터 이 골격을 따른다.

## plan.json 필드
- `slides[]` = 슬라이드(배열 순서 = 슬라이드 순서). 각 슬라이드 `assets[]` = 그 슬라이드에 얹을 에셋들(배열 순서 = z-순서).
- 에셋 필드:
  - `id` (필수) — 라이브러리 에셋 ID. INDEX.md에 있는 것만. 없는 ID는 오류.
  - `x`, `y` (선택) — 배치 위치, **인치** (슬라이드 13.33×7.5). 생략 시 원위치.
  - `text` (선택) — `{"현재문구": "새문구"}`. 현재문구는 그 에셋의 더미 텍스트(manifest.json의 `bindings` 참고).
  - `table` (선택) — 표 에셋용. `[["헤더1","헤더2"],["a","b"], ...]` 전체 셀 교체.
  - `chart` (선택) — 차트 에셋용. `{"categories":[...], "series":[{"label":"...","values":[...]}]}` 스타일 유지·데이터만 교체.

## 배치·응집 권장
- **색 테마 하나로 통일** — 헤더·조직도·표를 같은 계열(예: 네이비)로 골라 통일감을 준다.
- **배경(BGP)은 표지·간지에만.** 콘텐츠 슬라이드는 헤더 1 + 콘텐츠 1~2개로 여백을 둔다.
- 표준 위치: 섹션 헤더 `y=0.4`, 단일 콘텐츠 `x=0.7,y=1.6`, 2단 배치 좌 `x=0.5`·우 `x=7.0`.

## 팁
- 여러 템플릿(사업 유형별)을 둘 수 있다. 에이전트가 성격에 맞는 것을 고르거나 사용자에게 묻는다.
- 회사 로고·고정 문구가 있으면 표지/푸터 에셋에 `text`로 박아 두면 매번 반영된다.
