# 숏폼 제작 파이프라인

## 호출

```
/shortform <프로필> <주제>

/shortform kids "기린 목뼈"
/shortform science "양자얽힘"
/shortform kids            # 주제 없이 호출하면 주제 후보 발굴부터
```

프로필은 `/home/lee/project/.claude/shortform/profiles/<프로필>.md`로 해석한다. 파일이 없으면 `profiles/` 를 나열해 사용 가능한 프로필을 보여주고 멈춘다.

자연어로 호출된 경우("숏폼 만들어줘", "쇼츠 1화 뽑아줘" 등)도 같은 방식으로 프로필·주제를 해석한다. 메시지에서 프로필을 특정할 수 없으면 임의로 하나를 고르지 않고 `profiles/` 목록을 보여주며 먼저 확인한다.

## 이 파이프라인이 지키는 것 (배경)

1화를 실제로 만들면서 나온 문제 3가지가 이 구조의 근거다.

1. **길이 목표가 내용을 오염시켰다.** "60초"를 지시했더니 시간을 채우려고 내용이 불어났다. → 길이는 목표가 아니라 결과다. 상한만 있고 하한은 없다.
2. **대본을 쓴 에이전트를 아무도 검증하지 않았다.** → critic 단계를 파이프라인에 못박았다. 작성자와 반드시 다른 에이전트다.
3. **매번 처음부터 짜서 비쌌다.** → 자산 라이브러리 우선 사용.

이 3가지는 각 에이전트 정의에도 들어 있다. 여기서 순서만 다시 강제한다.

## 이중언어 산출 (확정 방침)

**이 채널은 한국어 채널과 영어 채널을 별도로 운영한다. 따라서 영상 1편의 기본 산출물은 mp4 2개다.**

- `out/episode-ko.mp4` (한국어판)
- `out/episode-en.mp4` (영어판)

"한국어 먼저 만들고 영어는 나중에"가 아니다. **한 편이 끝났다는 것은 두 언어 mp4가 모두 나왔다는 뜻이다.** 한쪽만 렌더하고 파이프라인을 종료하지 않는다.

| 층 | 언어별로 다른가 | 대상 |
|---|---|---|
| 대본·내레이션 | **언어별로 각각** | planner가 한/영 양쪽 작성 (영어는 직역이 아니라 재작성) |
| TTS 음성·립싱크·타임라인 | **언어별로 각각** | builder가 언어별로 실측해서 따로 계산 |
| 화면 텍스트 (자막·라벨·카드 이름) | **언어별로 각각** | 언어별 문자열 테이블에서 읽는다 |
| 이미지·캐릭터·소품·배경·씬 컴포넌트 | **공용 (언어 무관)** | 자산 라이브러리 그대로 재사용 |

**장면 구성과 순서는 두 언어가 동일하고, 각 장면의 길이만 다르다.** 한국어와 영어는 발화 길이가 달라서 같은 타임코드를 강제하면 한쪽이 잘리거나 어색하게 늘어진다. 상세는 `shortform-builder` 정의의 원칙 4를 따른다.

화면에 나오는 문자를 이미지 안에 구워 넣지 않는다. 코드로 그린다. 이미지에 글자가 박히면 언어 교체가 불가능해진다.

## 단계

진행 중 TodoWrite에 그대로 옮겨 쓰는 체크리스트:

```
[ ] 0. 프로필 확인 + 작업 폴더 결정
[ ] 1. planner: research + script v1 (한/영 양쪽 대본)
[ ] 2. critic: critique r1
[ ] 3. planner 재작성: script v2 (critic 통과/0건이면 생략)
[ ] 4. (조건부) critic r2 -> planner 재작성 v3
[ ] 5. 사용자 확인 (정지 지점, 한/영 대본 함께 확인)
[ ] 6. builder: 조립 + TTS + 렌더 + 검수
      [ ] 6-ko. 한국어 TTS -> 립싱크 -> ko 타임라인 실측 -> 렌더 -> 검수
      [ ] 6-en. 영어  TTS -> 립싱크 -> en 타임라인 실측 -> 렌더 -> 검수
[ ] 7. 최종 보고 (mp4 2개 경로 + 언어별 실측 길이)
```

| 단계 | 에이전트 | 산출물 | 진행 |
|---|---|---|---|
| 0 | (스킬 본체) | 작업 폴더 생성, 프로필 확인 | 자동 |
| 1 | `shortform-planner` | `01-research.md`, `02-script-v1.md` (**한국어·영어 내레이션 대조표 포함**) | 자동 |
| 2 | `shortform-critic` | `03-critique-r1.md` | 자동 |
| 3 | `shortform-planner` (재작성 모드) | `02-script-v2.md` | 자동 (critic이 1라운드에서 통과/0건이면 **생략**) |
| 4 | 2~3 반복 (조건부) | `-r2`, `-v3` | 자동, **최대 2라운드** |
| 5 | 사용자 확인 | 확정 대본 승인 (한/영 동시) | **정지. 승인 후 진행** |
| 6 | `shortform-builder` | 자산 조립(공용 1회) + **언어별로 각각** TTS·립싱크·타임라인 실측·렌더·검수 | 자동 |
| 7 | 보고 | `99-build-report.md` + 최종 요약 | 자동 |

6단계 산출물은 **mp4 2개**다: `out/episode-ko.mp4`, `out/episode-en.mp4`. 한쪽만 나온 상태로 7단계로 넘어가지 않는다. 자산 조립(1~2번, REGISTRY 대조·신규 자산 제작)은 언어 무관이므로 한 번만 한다.

각 단계 산출물은 다음 단계로 넘기기 전에 실제로 Read해서 `references/pipeline.md`에 적힌 완료 판정 기준을 만족하는지 확인한다. 기준 미달이면 다음 단계로 넘어가지 않고 무엇이 빠졌는지 명시해 재요청하거나 사용자에게 보고한다.

작업 폴더: `/home/lee/project/.claude/shortform/episodes/<프로필>-ep<NN>-<슬러그>/` (예: `kids-ep02-giraffe-neck`)
`<NN>`은 해당 프로필의 기존 에피소드 폴더를 Glob으로 세어 다음 번호를 쓴다. 폴더 구조·파일 포맷은 `episodes/README.md`가 SSOT이므로 그것을 따른다.
주제 없이 호출해 슬러그를 아직 정할 수 없으면 `<프로필>-ep<NN>-untitled/`로 만들고, 주제가 정해져도 폴더명은 바꾸지 않는다(상세: `references/pipeline.md` 0단계).
이미 있으면 **덮어쓰지 않는다.** 사용자에게 알리고 이어서 할지 새 폴더를 팔지 확인한다. 이어서 하기로 하면 폴더 안 파일 목록(Glob)으로 어디까지 진행됐는지 확인하고 그 다음 단계부터 재개한다. 처음부터 다시 돌리지 않는다.

### 2~4단계 루프 종료 기준

**판정 시점: critic이 끝나는 즉시, 재작성 전에** 아래 조건을 확인한다. 하나라도 해당하면 즉시 종료한다.

- critic이 "통과" 또는 삭제 판정 0건을 냈다 → **3단계(재작성)를 건너뛰고 바로 5단계로 간다.** 이미 통과한 대본을 다시 쓰는 건 낭비다
- 라운드 2를 마쳤다 (3라운드는 돌지 않는다)
- 직전 라운드 대비 삭제 판정이 줄지 않았다 (판정이 수렴하지 않는 상태 = 대본 방향 자체 문제). 이 조건은 비교할 이전 라운드가 있어야 성립하므로 라운드 2의 critic이 끝난 시점부터만 판단한다

3번째 조건에 걸리면 대본을 더 굴리지 말고 **사용자에게 상황을 보고한다.** 같은 지적이 반복되는 건 문장 문제가 아니라 주제 선정이나 프로필 톤 문제일 가능성이 크다.

라운드 상한을 2로 둔 이유: critic의 지적 유형은 대부분 1라운드에서 나오고, 2라운드는 재작성 과정에서 새로 들어간 필러를 잡는 용도다. 그 이상은 문장을 다듬는 취향 조정이 되어 값이 떨어진다.

## 사용자 확인 지점

**정지하고 승인을 받는 곳은 5단계 딱 한 곳이다** (렌더 직전 대본 확정). 렌더는 시간과 자원이 들고, 대본이 틀린 채로 렌더하면 전부 다시 해야 한다.

자동 진행 구간: 0~4단계(기획·대본·비평·재작성), 6~7단계(제작·렌더·검수). 이 구간에서는 중간중간 "계속할까요"를 묻지 않는다.

예외로 멈추는 경우:
- 프로필 파일이 없다
- 작업 폴더가 이미 있다
- planner가 주제 후보 3개를 모두 확실성 C로 탈락시켰다 (주제를 다시 받아야 한다)
- critic 루프가 수렴하지 않았다
- builder가 대본 자체의 문제를 발견했다 (상한 초과 등)

## 스폰 규칙

서브에이전트는 이 대화 이력을 상속하지 않는다. 스폰 프롬프트에 **매번 전량 명시**한다.

- 프로필 파일 절대경로
- 에피소드 작업 폴더 절대경로
- 읽어야 할 이전 단계 산출물 절대경로 (예: critic에는 `02-script-v1.md` 경로)
- 기대 출력 파일 절대경로

**critic은 반드시 planner와 별개로 스폰한다.** planner 세션 안에서 "자체 검증"으로 대체하면 이 파이프라인의 존재 이유가 사라진다. critic 스폰 프롬프트에 planner의 집필 의도나 변론을 넣지 않는다.

## 상세 참조

필요할 때만 읽는다.

- 단계별 스폰 프롬프트 템플릿과 산출물 형식: `references/pipeline.md`
- 새 프로필 추가 절차: `/home/lee/project/.claude/shortform/profiles/_TEMPLATE.md`
- 렌더 환경(PEP 668 venv, edge-tts 파이썬 API, ffmpeg): `shortform-builder` 에이전트 정의

## 하지 않는 것

- 길이를 채우기 위한 내용 추가 (전 단계 공통 금지)
- 작성자가 자기 대본을 검증하는 것
- **한 언어만 만들고 끝내는 것** (한국어판·영어판 mp4 2개가 기본 산출물)
- **두 언어의 타임코드를 강제로 같게 맞추는 것** (언어별 실측으로 따로 계산)
- **영어판을 한국어의 기계적 직역으로 채우는 것**
- 기존 파일 덮어쓰기
- 일정·소요시간 견적
