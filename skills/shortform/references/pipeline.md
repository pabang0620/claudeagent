# 단계별 상세 절차

SKILL.md에서 참조하는 상세 문서다. 스폰 프롬프트 템플릿과 산출물 형식을 담는다.

---

## 0단계: 준비

1. 프로필 경로 확인: `/home/lee/project/.claude/shortform/profiles/<프로필>.md`
   - 없으면 `profiles/` 목록을 보여주고 정지
2. 슬러그 결정: 주제를 소문자 하이픈으로 (예: "기린 목뼈" → `giraffe-neck`)
   - **주제가 없으면 이 시점에는 슬러그를 정할 수 없다.** 대신 기존 폴더와 겹치지 않는 번호로 `untitled-01`, `untitled-02`... 형식을 쓴다(Glob으로 `episodes/<프로필>-untitled-*` 확인 후 다음 번호). **주제가 1단계에서 정해진 뒤에도 폴더명은 바꾸지 않는다** (이동·삭제는 파괴적 작업 승인 규칙에 걸리므로 하지 않는다). 최종 보고에서 실제 선정 주제를 명확히 밝히면 폴더명이 주제를 담지 않아도 문제 없다
3. 작업 폴더: `/home/lee/project/.claude/shortform/episodes/<프로필>-<슬러그>/`
   - **이미 있으면 만들지 않고 사용자에게 알린다.** 이어서 할지 새 폴더를 팔지 확인한다
   - 이어서 하기로 하면 Glob으로 폴더 안 파일을 확인해 재개 지점을 정한다: `03-critique-r2.md`까지 있으면 다음은 3단계(재작성) / `02-script-v2.md`까지 있고 `03-critique-r2.md`가 없으면 다음은 2단계(critic 라운드2) / `01-research.md`만 있으면 다음은 2단계(critic 라운드1). 이미 끝난 단계는 다시 돌리지 않는다
4. 자산 라이브러리 존재 확인 (`assets/REGISTRY.md`). 없어도 진행한다. builder가 만든다

---

## 1단계: planner (기획 + 대본)

```
Agent(subagent_type="shortform-planner", prompt=...)
```

스폰 프롬프트에 반드시 포함:

```
프로필 파일: /home/lee/project/.claude/shortform/profiles/<프로필>.md   (먼저 Read할 것)
주제: <주제>   (없으면 "주제 미지정 - 후보 발굴부터")
작업 폴더: /home/lee/project/.claude/shortform/episodes/<폴더>/

산출물 (이 경로에 정확히):
  <작업폴더>/01-research.md    주제 후보 3개 + 선정 이유 + 사실 확인 표(확실성 등급 A/B/C)
  <작업폴더>/02-script-v1.md   타임코드별 (내레이션 / 화면이 말하는 것 / 장면 지시) 표 + 자산 목록(재사용·신규 구분)

완료 판정:
- 후보 3개 전부 기재, 탈락 사유 각 1줄
- 모든 주장에 등급이 붙어 있고, C 등급 주장이 대본에 없음
- 대본에 목표 길이 표기가 없고 추정 길이만 있음
- 자산 목록의 신규 항목마다 "왜 기존 것으로 안 되는지" 1줄
```

**주제 후보 3개가 모두 C 등급으로 탈락하면** 정지하고 사용자에게 보고한다.

## 2단계: critic (비평)

planner와 **별개 스폰**이다. 같은 세션에서 자체 검증으로 대체하지 않는다.

```
검증 대상 대본: /home/lee/project/.claude/shortform/episodes/<폴더>/02-script-v<N>.md
사실 확인 표:   /home/lee/project/.claude/shortform/episodes/<폴더>/01-research.md
프로필:         /home/lee/project/.claude/shortform/profiles/<프로필>.md   (TTS rate, 길이 상한 확인용)

산출물: <작업폴더>/03-critique-r<N>.md

요구:
- 문장 단위 판정표 (원문 / 판정 유지·삭제·압축 / 이유 / 압축안(참고))
- 화면 대조 결과 (화면과 내레이션 정보 중복 지점)
- 삭제·압축 반영 후 예상 길이 재계산
- 대본 파일은 수정하지 말 것
```

스폰 프롬프트에 planner의 집필 의도·변론을 넣지 않는다. 대본만 놓고 읽는 것이 이 단계의 값어치다.

## 3단계: planner 재작성

```
원본 대본: <작업폴더>/02-script-v<N>.md
비평 결과: <작업폴더>/03-critique-r<N>.md

산출물: <작업폴더>/02-script-v<N+1>.md   (기존 파일 덮어쓰기 금지)

규칙:
- 삭제 판정은 기본 반영. 유지하려면 사유 1줄 명시
- 압축안은 참고안. 프로필 톤에 맞춰 다시 써도 됨
- 삭제로 짧아진 길이를 메우려고 새 문장을 넣지 말 것
- 재작성 반영 요약(삭제 N건 반영 / M건 미반영 + 사유)을 파일 상단에 기재
```

---

## 4단계: 루프 판정

**critic(2단계)이 끝나는 즉시, 3단계(재작성)를 하기 전에** 판정한다. 재작성은 조건부다.

| 조건 | 처리 |
|---|---|
| critic이 "통과" 또는 삭제 0건 | **3단계(재작성) 생략**, 종료 → 5단계 (지금 스크립트 버전이 최종) |
| (재작성 후) 라운드 2를 마쳤다 | 종료 → 5단계 |
| (재작성 후) 삭제 판정 건수가 직전 라운드보다 줄지 않았다 | **정지, 사용자 보고** |
| 그 외 | 3단계 재작성 → 2단계로 (라운드 2 critic) |

1번째 조건은 재작성 전에 걸러지므로 불필요한 planner 호출을 막는다. 2·3번째 조건은 비교할 이전 라운드 판정이 있어야 하므로 라운드 2의 critic이 끝난 뒤에만 평가한다. 3번째 조건은 문장 문제가 아니라 주제·톤 문제를 뜻한다. 더 굴리지 말고 보고한다.

## 5단계: 사용자 확인 (유일한 정지 지점)

보고 내용:
- 최종 대본 (타임코드 표 그대로)
- 추정 길이
- 라운드별 삭제·압축 건수
- 새로 만들어야 하는 자산 목록
- 사실 확인 표에서 B 등급으로 처리한 항목이 있으면 그것

승인 후에만 6단계로 간다.

## 6단계: builder

```
확정 대본: <작업폴더>/02-script-v<최종>.md
프로필:    /home/lee/project/.claude/shortform/profiles/<프로필>.md
작업 폴더: <작업폴더>/
자산 라이브러리: /home/lee/project/.claude/shortform/assets/  (REGISTRY.md 먼저 Read)

순서:
1. REGISTRY 대조 → 재사용/신규 확정
2. 신규 자산 제작 → REGISTRY 등록
3. edge-tts 파이썬 API로 구간별 음성 + WordBoundary 타임스탬프
4. RMS 립싱크 JSON
5. 실측 길이로 타임코드 확정 (짧아져도 늘리지 않음)
6. 인트로·아웃트로 부착 → Remotion 렌더
7. 대표 프레임 추출 → Read로 육안 검수 → 결함 있으면 수정 후 재렌더

산출물: <작업폴더>/out/episode.mp4, <작업폴더>/99-build-report.md
```

builder를 스폰하기 전에 `episodes/README.md`와 `scripts/`(이미 있는 `tts.py`, `rms_mouth.py`)를 먼저 훑어 이미 이 프로젝트에 자리잡은 폴더 구조·스크립트와 이 문서의 안내가 어긋나는 지점이 있으면(예: 파일 형식, 폴더명 규칙) 임의로 어느 한쪽을 택하지 말고 스폰 프롬프트에 "기존 관례를 따르라"고 명시하거나 사용자에게 확인한다.

---

## 7단계: 최종 보고

- 최종 mp4 절대경로, 총 길이(실측)
- 재사용 자산 수 / 신규 자산 수 / REGISTRY 등록 여부
- 검수 체크리스트 항목별 통과 여부
- 렌더 횟수
- 다음 화를 위해 남긴 재사용 가능 자산

## 전 단계 공통 금지

- 길이를 채우기 위한 내용·장면 추가
- 작성자가 자기 대본을 검증하는 것
- 기존 파일 덮어쓰기 (버전 접미사를 붙인다)
- em-dash 사용
- 일정·소요시간 견적
