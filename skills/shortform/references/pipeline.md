# 단계별 상세 절차

SKILL.md에서 참조하는 상세 문서다. 스폰 프롬프트 템플릿과 산출물 형식을 담는다.

---

## 언어별 산출물 경로·파일명 규칙 (전 단계 공통)

한국어 채널과 영어 채널을 별도로 운영하므로 **영상 1편의 기본 산출물은 언어별 mp4 2개**다. 언어 코드는 `ko` / `en` 두 글자를 쓰고, 아래 자리에서 전부 같은 코드를 쓴다.

| 대상 | 경로·파일명 | 언어별인가 |
|---|---|---|
| 대본 (한/영 대조표 1개 파일) | `<작업폴더>/02-script-v<N>.md` | 파일은 1개, 표 안에 한국어·English 열 |
| 확정 대본 (실측 타임코드) | `<작업폴더>/02-script-final-ko.md`, `02-script-final-en.md` | **언어별** |
| TTS 입력 | `<작업폴더>/script-ko.json`, `script-en.json` | **언어별** |
| 구간 음성 | `<작업폴더>/public/audio/ko_<id>.mp3`, `en_<id>.mp3` | **언어별** |
| 어절 타임스탬프 | `<작업폴더>/public/audio/ko_words.json`, `en_words.json` | **언어별** |
| 립싱크 | `<작업폴더>/public/audio/ko_mouth.json`, `en_mouth.json` | **언어별** |
| 화면 문구 테이블 | `<작업폴더>/src/strings.ts` (`{ ko: {...}, en: {...} }` 한 파일) | 파일은 1개, 키별 언어 분기 |
| 최종 영상 | `<작업폴더>/out/episode-ko.mp4`, `out/episode-en.mp4` | **언어별** |
| 검수 프레임 | `<작업폴더>/out/frames-ko/`, `out/frames-en/` | **언어별** |
| 빌드 리포트 | `<작업폴더>/99-build-report.md` (언어별 절을 나눠 한 파일에) | 파일은 1개 |
| 이미지·캐릭터·소품·씬 컴포넌트 | `assets/` 라이브러리 그대로 | **공용 (언어 무관)** |

구간 id(`s1`, `s2`, ...)는 **두 언어가 동일하다.** 장면 구성과 순서가 같기 때문이다. 다른 것은 각 구간의 길이뿐이다.

재렌더로 버전이 올라가면 언어 코드 뒤에 붙인다: `episode-ko-v2.mp4`. 기존 파일을 덮어쓰지 않는다.

## 0단계: 준비

1. 프로필 경로 확인: `/home/lee/project/.claude/shortform/profiles/<프로필>.md`
   - 없으면 `profiles/` 목록을 보여주고 정지
2. 슬러그 결정: 주제를 소문자 하이픈으로 (예: "기린 목뼈" → `giraffe-neck`)
   - **주제가 없으면 이 시점에는 슬러그를 정할 수 없다.** 대신 기존 폴더와 겹치지 않는 번호로 `untitled-01`, `untitled-02`... 형식을 쓴다(Glob으로 `episodes/<프로필>-untitled-*` 확인 후 다음 번호). **주제가 1단계에서 정해진 뒤에도 폴더명은 바꾸지 않는다** (이동·삭제는 파괴적 작업 승인 규칙에 걸리므로 하지 않는다). 최종 보고에서 실제 선정 주제를 명확히 밝히면 폴더명이 주제를 담지 않아도 문제 없다
3. 작업 폴더: `/home/lee/project/.claude/shortform/episodes/<프로필>-<슬러그>/`
   - **이미 있으면 만들지 않고 사용자에게 알린다.** 이어서 할지 새 폴더를 팔지 확인한다
   - 이어서 하기로 하면 Glob으로 폴더 안 파일을 확인해 재개 지점을 정한다: `02-script-v<N>.md`(가장 최신 버전)까지 있으면 다음은 2단계(사용자 확인) / `01-research.md`만 있으면 다음은 1단계(대본 작성)를 마저 진행. 이미 끝난 단계는 다시 돌리지 않는다
4. 자산 라이브러리 존재 확인 (`assets/REGISTRY.md`). 없어도 진행한다. builder가 만든다

## 1단계: planner (기획 + 대본)

```
Agent(subagent_type="shortform-planner", prompt=...)
```

스폰 프롬프트에 반드시 포함:

```
프로필 파일: /home/lee/project/.claude/shortform/profiles/<프로필>.md   (먼저 Read할 것)
주제: <주제>   (없으면 "주제 미지정 - 후보 발굴부터")
작업 폴더: /home/lee/project/.claude/shortform/episodes/<폴더>/

학습된 지식만으로 작성한다. 검색하지 않는다.

산출물 (이 경로에 정확히):
  <작업폴더>/01-research.md    주제 후보 3개 + 선정 이유 + 사실 확인 표(확신 여부 - 핵심 사실/정성적 표현)
  <작업폴더>/02-script-v1.md   타임코드별 (한국어 내레이션 / English 내레이션 / 화면이 말하는 것 / 장면 지시) 표
                               + 언어별 화면 문구 표 + 영어판 의역 메모 + 자산 목록(재사용·신규 구분)

이 채널은 한국어 채널과 영어 채널을 별도로 운영한다. 대본은 처음부터 한/영 양쪽을 쓴다.
영어는 직역이 아니라 영어권 시청자에게 자연스러운 표현·리듬으로 재작성하되,
전달하는 사실과 장면 구성·순서는 한국어판과 동일하게 유지한다.

완료 판정:
- 후보 3개 전부 기재, 탈락 사유 각 1줄
- 모든 주장에 확신 여부가 표시되어 있고, 확신 없는 주장은 대본에 없거나 정성적으로 표현됨
- **모든 구간에 한국어와 English 내레이션이 둘 다 채워져 있음** (한쪽이 비면 미완)
- **화면에 뜨는 문자(자막·라벨·카드 이름)가 언어별로 정리되어 있음**
- 영어판이 직역이 아닌 근거(의역 메모)가 최소한 표현을 바꾼 구간마다 1줄
- 대본에 목표 길이 표기가 없고 추정 길이만 있음 (언어별로 각각 추정)
- 자산 목록의 신규 항목마다 "왜 기존 것으로 안 되는지" 1줄
```

**주제 후보 3개 모두에서 확신 있는 핵심 사실을 찾지 못하면** 정지하고 사용자에게 보고한다.

## 2단계: 사용자 확인 (정지 지점 - 대본 확정)

planner가 대본을 쓰면 별도 비평 단계 없이 곧바로 이 단계로 넘어간다. 정지 지점은 총 1곳이다: 이 단계(대본 확정). 4단계(배포)는 기술적 검증을 통과하면 별도 승인 없이 자동으로 진행된다(2026-08-09 변경).

보고 내용:
- 최종 대본 (타임코드 표 그대로, **한국어·English 두 열 모두**)
- 추정 길이 (**언어별로 각각**)
- 사실 확인 표에서 정성적 표현으로 처리한 항목이 있으면 그것
- 새로 만들어야 하는 자산 목록

**사용자가 수정을 요청하면** shortform-planner를 재작성 모드로 다시 스폰해 `02-script-v<N+1>.md`를 만들고, 다시 이 단계로 돌아와 확인받는다. 승인될 때까지 반복한다. 이 재작성은 planner의 "재작성 모드(사용자 피드백 반영)" 규칙을 따른다 - 수정 요청 없이 새 문장을 늘리지 않는다.

승인 후에만 3단계로 간다.

## 3단계: builder

```
확정 대본: <작업폴더>/02-script-v<최종>.md
프로필:    /home/lee/project/.claude/shortform/profiles/<프로필>.md
작업 폴더: <작업폴더>/
자산 라이브러리: /home/lee/project/.claude/shortform/assets/  (REGISTRY.md 먼저 Read)

순서:
[공용 - 한 번만]
1. REGISTRY 대조 → 재사용/신규 확정
2. 신규 자산 제작 → REGISTRY 등록  (이미지·캐릭터·소품·씬은 언어 무관 공용)
2-1. 화면 문구를 언어별 문자열 테이블(src/strings.ts, { ko, en })로 분리

[언어별 - ko, en 각각 반복]
3. script-<lang>.json 작성 → edge-tts 파이썬 API로 구간별 음성 + WordBoundary 타임스탬프
   (voice/rate/pitch는 프로필의 해당 언어 설정을 쓴다)
4. RMS 립싱크 JSON (<lang>_mouth.json)
5. **그 언어의 실측 길이로 그 언어의 타임코드를 따로 확정** (짧아져도 늘리지 않음)
   장면 구성·순서는 두 언어가 동일하고, 각 장면 길이만 해당 언어 실측에 맞춘다.
   한국어 타임코드를 영어에 그대로 쓰지 않는다.
6. 인트로·아웃트로 부착 → Remotion 렌더 (locale prop = <lang>)
7. 대표 프레임 추출 → Read로 기술적 검증(프레임 번호·클리핑·잔상·겹침·자막 이탈 등 관찰 사실 기록) → 결함 있으면 수정 후 재렌더
   (프레임 번호는 그 언어의 sceneStarts/sceneFrames로 계산. 언어마다 다르다)
   이 단계의 결론은 "검수 통과"가 아니라 "관찰 기록을 사용자에게 제시하고 확인을 기다린다"다 - 최종 합격 판정은 builder가 내리지 않는다(상세: `shortform-builder` 원칙 5).

산출물: <작업폴더>/out/episode-ko.mp4, <작업폴더>/out/episode-en.mp4,
       <작업폴더>/99-build-report.md (언어별 실측·검수 관찰 기록을 절로 나눠 기재)

한 언어만 렌더하고 끝내지 않는다. 두 mp4가 다 나와야 3단계 완료다. **3단계 완료 = "렌더+기술적 검증 완료"이지 "에피소드 배포 완료"가 아니다.**

8. **배포용 보관함으로 복사 - 기술적 검증 통과 시 자동** (2026-08-09 변경 - "out/ 경로는 안 본다, shorts/에 넣어달라"는 사용자 피드백 반영. 2026-08-08의 "승인 후에만" 원칙은 폐기)
   builder는 7번의 기술적 검증(원칙 5)을 마치면 별도 승인 질문 없이 곧바로 아래로 복사까지 완료하고, 관찰 기록과 함께 이미 반영된 상태임을 보고한다. 사용자는 `out/`이 아니라 `shorts/`에서 직접 확인하며, 문제가 있으면 그때 수정해 다시 `shorts/`에 덮어쓴다(사전 승인 질문 없이).
   ```
   /home/lee/project/shorts/ko/[N화] <한국어 제목>.mp4
   /home/lee/project/shorts/en/[Ep. N] <영어 제목>.mp4
   ```
   - `N`은 에피소드 폴더명(`<profile>-ep<NN>-<slug>/`의 `ep01` 등)에서 그대로 가져온다(`ep01` → `1화`/`Ep. 1`). 제목은 그 화의 `02-script-v1.md`의 "제목" 절(shortform-planner 원칙 6, 확정 제목)에서 한국어·영어 각각 그대로 가져오고 재작성하지 않는다
   - `<작업폴더>/out/`의 산출물이 정본이고 `shorts/`는 배포용 사본이다. 재렌더로 버전이 올라가면 `shorts/` 쪽도 같은 파일명으로 자동 덮어쓴다(검증을 통과할 때마다, 매번 별도 승인 없이)
   - `shorts/`는 `.gitignore` 처리되어 있어 git에는 안 올라간다 - 로컬 배포 보관함일 뿐이다
   - `out/`의 버전 이력은 직전 1개 버전만 회귀 비교용으로 남기고 그 이전 것은 정리한다(무기한 전부 보존하지 않는다, 상세: `shortform-builder` "산출물" 절)
```

builder를 스폰하기 전에 `episodes/README.md`와 `scripts/`(이미 있는 `tts.py`, `rms_mouth.py`)를 먼저 훑어 이미 이 프로젝트에 자리잡은 폴더 구조·스크립트와 이 문서의 안내가 어긋나는 지점이 있으면(예: 파일 형식, 폴더명 규칙) 임의로 어느 한쪽을 택하지 말고 스폰 프롬프트에 "기존 관례를 따르라"고 명시하거나 사용자에게 확인한다.

## 4단계: 최종 보고

- 최종 mp4 절대경로 **2개**(`episode-ko.mp4`, `episode-en.mp4`, `out/` 기준)와 **언어별 총 길이(실측)**
- 두 언어의 길이 차이 (장면 구성은 같고 길이만 다른 것이 정상이다)
- 재사용 자산 수 / 신규 자산 수 / REGISTRY 등록 여부 (공용 자산이므로 언어별로 세지 않는다)
- 검수 체크리스트 항목별 관찰 기록 (**언어별로 각각**, 자막 화면이탈은 언어마다 결과가 다르다 - "통과"로 요약하지 말고 무엇을 관찰했는지 적는다)
- 렌더 횟수 (언어별)
- 다음 화를 위해 남긴 재사용 가능 자산
- 보고 말미는 "이렇게 나왔습니다, 확인해주세요"로 끝난다. 기술적 검증까지 마쳤다면 이미 `shorts/ko/...`·`shorts/en/...`에 복사가 끝난 상태이므로 그 경로도 같은 보고에 포함한다(별도 승인 라운드를 기다리지 않는다, 2026-08-09 변경).

## 전 단계 공통 금지

- 길이를 채우기 위한 내용·장면 추가
- 작성자가 자기 대본을 검증하는 것
- 기존 파일 덮어쓰기 (버전 접미사를 붙인다)
- **한 언어만 만들고 파이프라인을 끝내는 것** (한국어판·영어판 둘 다가 기본 산출물이다)
- **한 언어의 타임코드를 다른 언어에 그대로 복사하는 것** (언어별로 실측해서 따로 계산한다)
- **영어판을 한국어의 기계적 직역으로 채우는 것** (재작성이다)
- 화면에 뜨는 문자를 이미지 안에 구워 넣는 것 (언어 교체가 불가능해진다)
- em-dash 사용
- 일정·소요시간 견적
