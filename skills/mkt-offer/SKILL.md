# mkt-offer: 상품 구성과 가격 제시

문구를 고치기 전에 상품부터 본다. 약한 상품에 좋은 문구를 붙이면 천천히 오르고, 강한 상품은 평범한 문구로도 바로 팔린다. "문구를 바꿔야 할 것 같다"는 요청의 상당수는 실제로 상품 구성 문제다.

## 먼저 읽을 것
- 사실 근거: 메모리 `user_profile_career`(실적·숫자), `project_kmong_outreach_hub`, `project_ebook_bijeongongja`(확정 가격)
- 크몽 문구 원칙: 메모리 `feedback_kmong_copy_principles` (연차 표기 금지, "혼자 했다" 금지, 카피라이팅 금지)
- 확정된 가격·사업 판단은 다시 판단하지 않는다(`feedback_dont_second_guess_business_decisions`). 바꿀 근거가 생겼으면 근거와 함께 제안만 한다

## 가치 공식으로 막힌 곳 찾기
가치 = (원하는 결과 x 될 거라는 믿음) / (기다리는 시간 x 들이는 수고)

| 레버 | 올리는 방법 (외주·전자책 기준) |
|---|---|
| 원하는 결과 | 겉 요청 뒤의 진짜 목표를 이름 붙여 적는다. "홈페이지 제작"이 아니라 "문의가 들어오는 홈페이지" |
| 믿음 | 실제 운영 중인 결과물 링크, 처리 건수, 고객사 이름(공개 동의된 것만), 진행 절차 공개 |
| 시간 | 첫 결과물이 나오는 시점을 앞당긴다(1차 시안 일정 명시) |
| 수고 | 고객이 할 일을 줄인다(기획서 대신 써줌, 운영법 문서 납품, 인수인계) |

네 레버를 1~10으로 매기고 **가장 낮은 하나만** 이번에 고친다. 가격을 내려달라는 요청은 대부분 분자를 키우거나 분모를 줄이라는 뜻이다.

## 상품의 여섯 구성요소
| # | 요소 | 비어 있으면 생기는 일 |
|---|---|---|
| 1 | 핵심 납품물 | 무엇을 받는지 모호해 견적 비교만 당한다 |
| 2 | 덤(보너스) | 핵심이 싸 보이지 않게 하는 장치가 없다 |
| 3 | 보장 | 처음 맡기는 고객이 망설인다 |
| 4 | 마감·수량 제한 | "생각해보고 연락드릴게요"로 끝난다 |
| 5 | 이름 | 이름 없는 서비스는 가격으로만 비교된다 |
| 6 | 가격·결제 방식 | 착수금·분할 구조가 없어 큰 건이 막힌다 |

## 외주(kingkle·크몽) 기본형
- **핵심**: 범위·납품물·일정이 고정된 상품. "웹 개발"이 아니라 이름 붙은 묶음(예: "AI 도입 진단", "자동화 구축 + 운영 인수인계")
- **범위 밖 목록을 서면으로**: 포함 / 제외 / 선택 옵션 세 칸. 범위 확장이 외주 상품을 망치는 1순위 원인
- **덤**: 납품 뒤 고객이 혼자 굴릴 수 있게 하는 것(운영 매뉴얼, 관리자 사용법 영상, 1인 사업자용 운영법 안내). 작업 중에 쓰는 덤보다 납품 후에 쓰는 덤이 가치가 크다
- **보장**: 외주는 환불형보다 마일스톤형이 맞다. "1차 시안 확인 후 진행 여부 결정, 중단 시 2단계 비용 없음" 또는 "약속 일정 초과 시 지연분 X% 차감"처럼 측정 가능한 조건만. "만족할 때까지"는 끝없는 비용이라 쓰지 않는다
- **수량 제한**: 실제 작업 가능 인원 기준으로만("이번 달 신규 착수 N건, 다음 착수 가능일 O월 O일"). 사실이 아니면 쓰지 않는다
- **결제**: 착수금 + 중도금 + 잔금, 또는 월 유지보수 정액
- **세금 표기**: 비사업자 프리랜서는 부가세 없음, 3.3% 원천징수 대상임을 견적에 분명히. 계산과 문서는 quote-builder 스킬

## 패키지 3단 (크몽 STANDARD/DELUXE/PREMIUM, 전자책 BASIC/STANDARD/PREMIUM)
- 가운데를 추천안으로 만든다. 대부분이 가운데를 고르게 설계하고, 위 단계는 가운데의 2~3배로 둬 가운데를 합리적으로 보이게 한다
- 단계 차이는 기능 개수보다 **범위·지원 수준·속도**로 낸다(수정 횟수, 납품 후 지원 기간, 우선 일정)
- 각 단계에 "누구에게 맞는지" 한 줄. 고객이 스스로 고르게 해 상담 부담을 줄인다
- 최저 단계를 너무 싸게 두지 않는다. 싼 단계는 가짜 수요와 수정 요구가 가장 많은 고객을 모은다

## 가격 정하는 순서
1. 바닥: 내 원가(작업 시간 x 시간 단가). 기준이 아니라 하한일 뿐이다
2. 비교 기준: 고객이 고를 수 있는 다음 대안(크몽 상위 판매글 가격, 정규직 채용 비용, 기성 SaaS 구독료). **경쟁 가격은 참고 자료이지 목표가 아니다**
3. 천장: 고객이 얻는 결과의 크기(절감 시간·늘어난 매출)
4. 가격은 2와 3 사이. 근거 없이 정했으면 일단 내놓고 반응으로 조정한다. 망설임 없이 계약되면 올릴 신호
- 신규 고객 확보용 할인은 하지 않는다. 할인으로 들어온 고객이 이탈·불만이 가장 많고, 가격이 싸다는 인상이 굳는다. 할인은 기존 고객 추가 계약이나 실제 시즌에만

## 가격 올릴 때
- 새 고객부터 적용하고 반응을 본다. 기존 고객은 유예 기간을 주고 이유(늘어난 가치)를 미리 알린다
- 영구 동결은 하지 않는다. 동결은 전환 기간이지 영구 예외가 아니다

## 하지 않는 것
- 가짜 마감(다시 0으로 돌아가는 카운트다운, 몇 주째 "마지막 2자리")
- 조건 없는 "100% 보장", 결과를 약속하는 보장("매출 2배")
- 비교 대상 없는 "OO만원 상당" 덤 부풀리기
- "혁신적인", "압도적인", "게임체인저", "비밀", "업계 최초"(근거 없으면) 같은 과장어
- 실적·고객사·수치를 만들어 넣기. 근거가 없으면 그 주장은 빼고 사용자에게 따로 묻는다

## 진단 순서 ("문의가 안 와요", "상품 고쳐줘")
1. 업종 확인: 외주 / 전자책 / 강의 / 구독
2. 지금 상품을 한 줄로 적는다: 이름, 가격, 받는 것, 보장, 마감
3. 가치 공식 네 레버 점수 → 가장 낮은 레버
4. 여섯 구성요소 중 빠진 것
5. 이번엔 하나만 고친다. 바꾼 요소 하나당 기대치는 상대 10~40% 정도로 말하고, 여러 개를 바꿔도 곱으로 계산한다. "몇 배"를 약속하지 않는다

## 결과물 형식
- 지금 상품 한 줄 / 레버 점수 / 빠진 요소
- 바꾼 상품안(이름·핵심·덤·보장·마감·가격 구조), 근거 한 줄씩
- 크몽이면 패키지 3단 표
