# readdy-cinematic

Lantern Rite 마케팅 영상 제작(2026-09-16/17)에서 실측으로 확정한 절차. Readdy의 "Interactive Cinematic"은 텍스트 프롬프트 + 선택적 첫 프레임/마지막 프레임 이미지를 받아 5s/10s/15s 길이, 768P/2K 화질의 영상을 생성하는 기능이다.

## 0. 오케스트레이터가 직접 하는 일 vs 위임

- **기획·프롬프트 작성·이미지 준비 지시·Playwright 제출은 오케스트레이터가 직접 한다.** 이건 판단(무슨 장면을 어떻게 찍을지)과 브라우저 조작(Playwright MCP)이지, 위임 대상인 "코드 작성"이 아니다.
- **새 이미지가 필요할 때만** game-asset-artist(또는 대상 프로젝트의 이미지 생성 에이전트)에게 위임한다. 기존 승인된 아트(캐릭터 시트, 던전 배경, 키아트 등)를 크롭/합성해서 쓸 수 있으면 재사용을 우선한다 - 새로 생성하는 것보다 빠르고 일관성이 보장된다.
- **엔진에 실제로 영상을 배선하는 작업**(VideoPlayer, 스킵 버튼, 씬 연결)은 대상 게임 프로젝트의 구현 에이전트에게 넘긴다.

## 1. 기획

무슨 영상이 몇 개 필요한지 먼저 목록화한다 (예: 로그인/타이틀, 캐릭터 선택, 전직 연출, 보스 등장, 던전 로딩 루프, 뽑기 연출, 콘텐츠 루프, 트레일러). 트레일러처럼 긴 영상이 필요하면 **15초짜리 클립을 체이닝**한다: 클립 N의 마지막 프레임 = 클립 N+1의 첫 프레임으로 잡으면 각 클립을 독립적으로 생성해도 이어붙였을 때 자연스럽다. 8클립 x 15초 = 2분 트레일러가 실측 사례.

## 2. 프레임 이미지 준비

- 이미 있는 승인된 아트(배경 원화, 캐릭터 시트, 보스 마지막 프레임 등)를 최대한 재사용한다. PIL로 크롭/리사이즈/합성해서 첫/마지막 프레임을 만든다(예: 16:9로 크롭, 캐릭터 앵커를 배경 위에 합성).
- 완전히 새로운 장면이 필요할 때만 이미지 생성 에이전트에게 위임한다.
- 트레일러 체이닝 시 겹치는 프레임(클립 N 마지막 = 클립 N+1 첫 프레임)은 파일을 그대로 복사해서 양쪽 폴더에 넣는다 - 별도로 다시 생성하지 않는다.

## 3. 프롬프트 작성 (Hard Rules - 실패 사례로 확정됨)

1. **항상 영어로 작성한다.** 한글+영어 혼용 금지 - 사용자가 "복붙용으로 어디부터 어디까지인지 모르겠다"고 지적한 실패 사례 있음.
2. **끝에 항상 `No text, no captions, no watermark.`를 붙인다.**
3. **카메라/피사체가 크게 움직이는 연출을 두려워하지 않는다.** 이 모델은 이동량이 커도 잘 만들어준다 - 사용자가 직접 확인한 특성.
4. **캐릭터 얼굴 잠금이 필요하면 명시적으로 잠가야 한다.** 저가형 모델일수록 아래 두 가지 실패 모드가 실측됨:
   - 이펙트 색상이 캐릭터 전체(얼굴/눈 포함)로 번짐 -> "do not recolor the eyes/face" 류 문구로 방지.
   - 얼굴을 고정해도 눈(공막/홍채/눈꺼풀)이 아예 사라지거나 뭉개짐 - 특히 얼굴이 프레임에서 작게 나올 때 디테일 손실이 심함. 대응: (a) 프롬프트에 눈의 각 부위(sclera, iris, pupil, eyelid, eyelashes)를 구체적으로 나열하고 "treat the eyes as the single most important detail to preserve" 같은 문구로 최우선순위 지정, (b) 레퍼런스 이미지를 크롭/줌해서 얼굴이 프레임에서 크게 나오도록, (c) 화질은 항상 2K로 요청(768P보다 디테일 보존이 나음).
5. 여러 샷을 이어붙이는 뽑기 연출/시퀀스형 영상은 프롬프트 안에 번호 매긴 시퀀스(1. ... 2. ... 3. ...)로 비트를 명시하면 결과가 안정적이다.

## 4. 사람이 보는 참고 폴더 (프로젝트별 위치, 예: `Downloads/레퍼/영상생성_.../<NN_이름>/`)

각 영상마다 폴더 하나, 안에:
- `첫프레임.png`, `마지막프레임.png`
- `프롬프트.txt` - 헤더(폴더 목적, "첫 프레임 칸:", "마지막 프레임 칸:") + 아래 구분자 사이에 순수 영어 프롬프트:
```
▼▼▼▼▼▼▼▼▼▼ 여기부터 복사 ▼▼▼▼▼▼▼▼▼▼
(영어 프롬프트 본문)
▲▲▲▲▲▲▲▲▲▲ 여기까지 복사 ▲▲▲▲▲▲▲▲▲▲
```
사용자가 직접 Readdy에 넣을 수도 있으므로 이 폴더는 항상 만들어 둔다.

## 5. Playwright 제출용 스테이징 (오케스트레이터가 직접 생성 요청까지 수행할 때)

`browser_file_upload`는 세션의 `.playwright-mcp/` 하위 경로만 허용한다. 따라서 별도 스테이징 디렉토리가 필요하다:

```
<project>/.playwright-mcp/readdy_upload/<key>/
  first.png   (= 첫프레임.png 복사)
  last.png    (= 마지막프레임.png 복사)
  prompt.txt  (= 위 구분자 사이의 순수 영어 텍스트만, 마커 제외)
```

그 다음 서브밋 스크립트를 생성한다:
```
python3 <이 스킬 경로>/helpers/make_submit.py <staging_dir> <length>
# 예: python3 helpers/make_submit.py .../readdy_upload/tr_05 15s
```
`<length>`는 Readdy 라디오 버튼 라벨과 정확히 일치해야 한다(`"10s"`, `"15s"` 등, exact match).

## 6. Playwright로 제출 (탭 1개 = 영상 1개, 병렬)

기본 동작: **제출만 하고 기다리지 않는다.** 생성에 각 30분가량 걸리므로, 필요한 영상 개수만큼 새 탭을 열어 각각 제출 요청만 넣고 다음 탭으로 넘어간다. 사용자가 "다 됐다"고 알려줄 때까지 폴링하지 않는다. (예외: 사용자가 명시적으로 "기다렸다가" 또는 "결과 확인해줘"라고 하면 그때만 대기/확인한다.)

절차 (영상마다 반복):
1. `browser_tabs` action:"new", url:"https://readdy.ai/project" - 새 탭 연다.
2. `browser_run_code_unsafe`에 `filename: "<staging_dir>/submit.js"` 로 실행한다. **code 파라미터에 파일 내용을 문자열로 읽어 eval하는 방식은 쓰지 말 것** - `filename` 파라미터가 있으므로 그걸 바로 쓴다 (직접 eval 시도했다가 구문 오류로 실패한 사례 있음).
3. 스크립트가 첫 프레임 업로드용 파일선택창(filechooser)에서 멈추고 툴 결과가 "Modal state: File chooser"로 돌아온다 - 이때 `browser_file_upload`로 `first.png` 경로를 넘겨 처리한다.
4. 이어서 마지막 프레임용 파일선택창이 뜨면 같은 방식으로 `browser_file_upload`에 `last.png`를 넘긴다. (두 파일 모두 이 방식으로 별도 처리해야 한다 - 스크립트 안에서 자동으로 완료되지 않는다.)
5. 두 번째 업로드 후 페이지가 자동으로 `/cinematic`으로 넘어가면 제출 완료. 애매하면 `browser_snapshot`으로 "Starting automatically in Ns" 또는 "Confirm script" 텍스트를 확인한다.
6. 다음 영상으로 넘어간다 (1번부터 반복, 새 탭에서).

**탭이 꼬였을 때**: "First / last frame" 스위치 대기가 타임아웃되거나 파일선택창이 안 뜨는 등 탭이 이상 동작하면, 그 탭에서 계속 디버깅하지 말고 **탭을 닫고 새 탭에서 처음부터 재시도**한다 - 같은 스크립트가 새 탭에서는 정상 동작하는 경우가 실측으로 확인됨(원인은 특정 탭 인스턴스의 일시적 문제였고 스크립트 로직 문제가 아니었음).

## 7. 완료 후 다운로드

사용자가 "다 됐다"고 알리면:
1. 열려 있는 각 탭에서 `browser_evaluate`로 `<video>` 태그의 `currentSrc`/`src`를 추출한다 (fal.media CDN URL 형태: `https://v3b.fal.media/files/b/...mp4`). 탭이 많고 어떤 영상인지 헷갈리면 `document.body.innerText`에서 그 영상 프롬프트의 고유 문구(예: "teal" vs "silver")로 매칭한다. 한 탭에 `<video>`가 2개 뜨면 **가장 마지막 URL이 최종 결과물**이다.
2. `helpers/download_video.sh <출력폴더> <파일이름> <URL>`로 다운로드 + 길이/해상도/루프이음매 검증까지 한 번에 수행한다. (`SCRATCH` 환경변수로 프레임 임시 저장 위치 지정 가능, 기본 `/tmp`.)
3. 다운로드가 끝난 탭은 닫아도 된다. **다운로드 전에는 절대 닫지 않는다.**

## 8. 트레일러 등 체이닝 영상의 최종 합치기

모든 클립이 다운로드되면 ffmpeg로 순서대로 합친다(코덱 일치 시 무손실 concat):
```bash
printf "file '%s'\n" clip01.mp4 clip02.mp4 ... > list.txt
ffmpeg -f concat -safe 0 -i list.txt -c copy trailer_final.mp4
```
코덱/해상도가 클립마다 다르면 `-c copy` 대신 재인코딩 필요 여부를 ffprobe로 먼저 확인한다.

## 9. 실제 게임 화면 배선

이 스킬은 영상 파일을 만드는 데까지만 담당한다. 완성된 mp4를 실제 화면에 넣는 작업(엔진 임포트, VideoPlayer 배선, 스킵 버튼, 오디오 덕킹 등)은 대상 프로젝트의 구현 에이전트에게 넘긴다(Lantern Rite는 unity2d-scene-architect, `rules/agents.md` 참고). 모든 연출 영상에는 우측 상단 스킵(">>") 아이콘을 넣는 것이 기본 요구사항이다(사용자 확정 요구사항 - 프로젝트별로 확인).
