# Deep Research 스킬

**주제만 있고 어디에 답이 있는지 모르는** 상태에서 출발해, 공신력 있는 기관 자료를 검색으로 발굴하고 원문까지 읽는다.

## 참조 파일 (필요할 때만 읽는다)

| 읽는 조건 | 파일 |
|---|---|
| WebFetch가 비었거나 PDF가 안 열릴 때 / 기관 사이트 구조를 뜰 때 / 언제 멈출지 판단할 때 | `/home/lee/project/.claude/agent-refs/web-crawling-ladder.md` (§1 승급사다리, §2 사이트맵, §4 포화판정) |

## 정체성 (혼동 금지)

| | 입력 | 하는 일 |
|---|---|---|
| **이 스킬** | **주제·질문** | 어디 있는지 모르는 근거 문서를 **검색으로 발굴** → 원문 정독 |
| **web-crawler 에이전트** | **대상**(회사명·URL·제품) | 그 대상의 사이트를 훑어 사실 **수확** |

가르는 질문: **"어느 사이트를 볼지 이미 아는가?"** 모른다 → 이 스킬. 안다 → web-crawler.
조사 중 특정 기업을 깊이 파야 해지면 직접 파지 말고 `추가 탐색 추천`에 적어 web-crawler로 넘긴다.

## STEP 0 - 착수 판정 (필수, 첫 번째로 실행)

### 0-1. 주제가 있는가

`$ARGUMENTS`와 대화 맥락에 조사 주제가 **전혀 없으면** 아래를 반환하고 종료한다:

```
❌ INSUFFICIENT_TOPIC
필요한 것: 조사 주제 (예: "국내 웹툰 시장 규모", "생성형 AI 도입률")
받은 것: [원 요청 그대로]
```

주제는 있는데 범위만 넓으면(예: "콘텐츠 산업 전체") **묻지 말고 가장 핵심 축 1개로 좁혀 진행**하고,
좁힌 근거와 제외한 축 목록을 결과에 적는다. `context: fork`로 실행되므로 질문이 사용자에게 닿지 않는다.

### 0-2. 정보요구 체크리스트를 먼저 쓴다

**무엇을 채우면 끝인지**를 3~7개 항목으로 확정한다. 이게 종료 조건이다. 주제형 조사 기본형:
```
[ ] 시장 규모  - 최신 연도 금액·건수와 산출 기관
[ ] 성장 추이  - 최소 3개 연도 시계열
[ ] 구성·비중  - 세부 분야별 분해
[ ] 정책·제도  - 관련 부처 계획·법령
[ ] 전망·리스크 - 기관 전망치와 그 전제
```

### 0-3. 노력 상한 결정

| 등급 | 신호어 | 상한 (WebSearch / 문서 열람 / Playwright) |
|---|---|---|
| 1단계 | "간단히", "빠르게", "대략", "훑어봐", 수치 1개만, "오늘 발표" | 2 / 4 / 0 |
| **2단계 (기본값)** | 신호어 없는 중립 요청 - "자료조사해줘", "근거 찾아줘" | 4 / 10 / 2 |
| 3단계 | "깊이있게", "철저히", "빠짐없이", "보고서 수준", 제안서·논문용 | 8 / 25 / 5 |

신호가 상충하면("빠르게"+"철저히") 낮은 쪽을 택하고 그 사실을 결과에 적는다. 묻지 않는다.
**등급은 상한일 뿐이고, 실제 종료는 포화 판정(STEP 3)이 정한다.**

### 0-4. 확정 출력

```
📊 주제: [좁힌 조사 축]
📋 채워야 할 항목: [체크리스트 3~7개]
🏛️ 탐색 기관: [기관명 목록]
🔎 노력 상한: [N]단계 - [근거 한 줄]
```

## STEP 1 - 발굴 (검색)

```
[주제] site:[기관도메인] filetype:pdf
[주제] [기관명] 보고서 [최신연도]
[주제] 실태조사 OR 백서 OR 동향분석
```

- 기관을 병렬로 훑되, **한 기관에서 자료가 잡히면 그 기관 사이트 구조를 먼저 뜬다** (STEP 2).
- 검색 결과의 스니펫 수치를 그대로 쓰지 않는다. **원문에 도달한 수치만 인용한다.**
- 2차 인용(기사가 보고서를 인용한 것)을 발견하면 **원 보고서를 찾아 대체**한다. 못 찾으면 "2차 인용"으로 표기.

## STEP 2 - 도달 (사이트맵 + 승급 사다리)

기관 도메인이 정해지면 블라인드 검색을 더 돌리지 말고 구조를 뜬다. 상세는 참조파일 §1·§2.

```
robots.txt → sitemap.xml → 자료실·발간물 목록 페이지 → 상세 → 첨부 PDF
```

원문에 도달하지 못하면 **싼 경로부터** 승급한다:

```
L1 WebFetch  →  L2 r.jina.ai  →  L3 Playwright snapshot
             →  L4 클릭·대기 + network_requests로 PDF 실제 URL 캡처 → 그 URL로 L1 재진입
             →  L5 웨이백 아카이브 (Playwright 전용, WebFetch로는 차단됨)
```

- 승급은 **관찰된 실패 신호**가 있을 때만 (본문 200자 미만 / "JavaScript 활성화" / 403·429 / 빈 snapshot).
- **한 URL은 한 바퀴가 끝이다.** L5까지 실패하면 `접근 불가` 확정. 재시도 금지.
- **robots.txt `Disallow` 경로는 접근하지 않는다.** 실측 예: `kocca.kr`은 `/*/FileDown.do`를 Disallow 한다.
  즉 KOCCA 첨부 PDF 직다운로드 경로는 대상이 아니므로, 게시물 상세 본문이나 공개 뷰어로 우회 없이 접근한다.
- Playwright를 썼으면 종료 전 `browser_close`.

## STEP 3 - 포화 판정 (매 라운드)

라운드마다 coverage / gain / saturation을 갱신한다 (참조파일 §4).

| 조건 | 처리 |
|---|---|
| coverage 100% | 즉시 종료. 남은 상한 쓰지 않는다 |
| gain 0이 연속 2라운드 | 즉시 종료. 남은 항목은 `확인 불가` 확정 |
| 노력 상한 도달 | 종료. 미완 항목과 다음에 볼 기관 인계 |

## STEP 4 - 교차 검증 (3단계 또는 수치가 의사결정에 쓰일 때)

- 기관별 수치가 다르면 **하나를 고르지 말고 나란히 제시**하고, 조사 연도·모집단·산출 방법론의 차이를 명시한다.
- 같은 수치가 여러 기관에 나오면 **원 출처가 하나인지** 확인한다 (재인용 체인은 교차검증이 아니다).
- 추정치와 실측치를 구분해 표기한다.

## 안티패턴 (반드시 회피)

- ❌ 주제 없이 추측해서 조사 시작 → `INSUFFICIENT_TOPIC` 반환
- ❌ 검색 스니펫 수치를 원문 확인 없이 인용
- ❌ 기관 도메인이 잡혔는데 robots·자료실 구조를 건너뛰고 검색만 반복
- ❌ robots 차단·로그인·페이월 **우회** 시도 → 기록하고 다른 기관으로
- ❌ 같은 URL 재시도, 무한 스크롤 루프
- ❌ 추측·환각으로 수치 채우기 → **출처 없는 수치 금지**
- ❌ 열리는지 확인 안 한 URL 기재
- ❌ 특정 기업 심층 조사로 범위 확장 (web-crawler 몫)
- ❌ PDF 원문·HTML 덩어리를 결과에 그대로 붙여넣기 → 아래 반환 예산 위반

## 결과 출력 형식

**반환 예산**: 전체 1,500단어 이내. 인용은 1건당 2문장 이내. 원문 덤프 금지 - 추출한 사실만 남긴다.

```markdown
## 📋 리서치 결과: [주제] ([N]단계, coverage N/N)

### 체크리스트 충족 현황
| 항목 | 상태 | 근거ID |
|------|------|--------|
| 시장 규모 | 확인됨 | E-contents2026-01 |
| 전망·리스크 | 확인 불가 (KOCCA·KISDI·통계청 3기관 확인, 미발간) | - |

### 핵심 수치 및 근거
| 근거ID | 내용 | 수치/사실 | 출처 | 연도 |
|--------|------|----------|------|------|
| E-... | ... | ... | ... | ... |

### 주요 보고서
**[보고서 제목]**
- 발행: [기관명] ([연도].[월])
- 링크: [URL]
- 접근 방법: [최종 도달 레벨 - 예: L1 WebFetch / L2 r.jina.ai / L4 Playwright→PDF URL캡처]
- 핵심 내용: [2~3줄]
- 활용 포인트: [구체적 슬라이드·문서 섹션 제안]

### 수치 충돌 (있으면)
| 항목 | 기관 A 값 | 기관 B 값 | 차이 원인 (연도·모집단·방법론) |

### 막힌 곳 (있으면)
[robots 차단 경로 / 로그인 벽 / 유료 + 스크린샷 경로 + 대신 쓴 기관]

### 추가 탐색 추천
[미탐색 기관 / web-crawler로 넘길 특정 기업 조사]
```

- **근거ID**는 `E-[주제슬러그]-[2자리]` 형식 (예: `E-contents2026-01`). Evidence 저장 여부와 무관하게 항상 부여.
- `확인 불가`는 **확인한 기관을 반드시 병기**한다. "못 찾았다"와 "찾아봤는데 없다"는 다른 정보다.

## 근거자료(Evidence) 파일 저장 - 조건부

다음 중 하나일 때만 실행한다:
- 사용자가 "근거자료로 저장", "evidence 파일로", "PT/문서에 쓸 수 있게 저장" 등을 명시적으로 요청
- 호출자가 proposal-pt-builder·doc-generator 연계 목적으로 호출

### 절차
1. 위 표의 **근거ID를 그대로 재사용**한다. 컬럼 매핑: `내용`+`수치/사실` → `핵심 내용/수치`, `연도` → `발행일`, 활용포인트는 행별로 반영.
2. 저장 경로가 요청에 있으면 그 경로. 없으면 **`추가 탐색 추천` 아래에 "저장 경로 미지정"이라고 적고 저장을 건너뛴다** (fork 실행이라 사용자에게 물을 수 없다).
3. 파일명 `evidence_<주제슬러그>.md`.
4. **동명 파일이 이미 있으면 덮어쓰지 않는다.** `_2`를 붙이고 그 사실을 결과에 보고한다.
5. Write로 저장 후 절대경로를 결과에 한 줄 보고.

### 스키마
```markdown
# Evidence: [주제]

| 근거ID | 핵심 내용/수치 | 출처 | 발행일 | 활용포인트 |
|--------|--------------|------|--------|----------|
| E-contents2026-01 | ... | 기관명·문서명·URL | YYYY-MM | ... |
```
- **발행일**: YYYY 또는 YYYY-MM, 불명확하면 "확인불가"
- **출처**: 기관/매체명 · 문서명 · URL 병기

## 품질 기준

- 공공기관·국책연구원 > 언론 > 블로그·커뮤니티 순으로 우선
