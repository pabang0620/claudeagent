# mkt-landing-copy: 페이지 문구와 전환 진단

## 먼저 읽을 것
- 메모리 `feedback_kmong_copy_principles`: 카피라이팅(감성 문구 창작) 금지, 실제 할 수 있는 것을 비개발자도 알아듣게. 연차 표기 금지("수년간"으로). "혼자 했다" 금지. 차별점은 "AI가 찍어내는 게 아니라 개발자가 직접 작업하고 기획자·디자이너가 붙는다"
- 메모리 `feedback_kmong_enterprise_needs_own_copy`: 채널마다 독자가 다르다. 다른 채널 문구를 복붙하지 않는다
- 메모리 `user_profile_career`: 쓸 수 있는 실적·숫자의 원본. 여기 없는 숫자는 쓰지 않는다
- 크몽 판매글은 상위권 판매글 실측을 먼저 하고 쓴다

## 채널별 첫 독자
| 채널 | 독자 | 판단하는 것 |
|---|---|---|
| 크몽 일반 마켓 | 소상공인·1인 창업자 | 나도 맡길 수 있나, 말이 통하나, 얼마인가 |
| 크몽 엔터프라이즈 | 크몽 매니저 | 중견기업 건에 추천해도 되나(규모 실적, 절차, 인수인계) |
| kingkle.co.kr | 검색·지인 소개로 온 사업자 | 진짜 회사인가, 비슷한 걸 해봤나, 어떻게 연락하나 |
| 전자책 랜딩 | 비전공 취업 준비생 | 나 같은 사람도 되나, 뭘 얻나, 돈 값 하나 |

## 상황 진단부터 (한 줄로 적고 시작)
- **A. 빈 상태·상투어 덩어리**: 사실에서 논지를 새로 세운다. 각도는 자유, 사실은 고정
- **B. 사용자 목소리가 있는 초안**: 그 논지와 어휘를 지킨다. 묻힌 핵심, 모호한 줄, AI티, 구조만 고친다
- **C. 부분 수정**: 요청한 줄과 그 주변 최소한만. 나머지는 그대로 돌려준다
사용자가 "stuff"처럼 쓰면 "솔루션"으로 올리지 않는다. 어휘 선택이 곧 목소리다.

## 줄마다 거는 세 질문
1. 읽는 사람이 장면을 떠올릴 수 있나
2. 참·거짓을 따질 수 있는 주장인가 ("최고의 품질"은 장식)
3. 경쟁사가 똑같이 쓸 수 있는 문장인가 (그렇다면 탈락)
셋 다 통과면 유지, 둘이면 약한 쪽을 다듬고, 하나 이하면 사실에서 다시 쓴다. 근거가 없는 주장은 페이지에 자리표시를 남기지 말고 사용자에게 따로 "이 주장엔 OO 근거가 필요하다"고 묻는다.

## 쓰는 방식
- 페이지를 한 번에 쓰지 않는다. 헤드라인, 서브, CTA, 섹션별 제목·본문으로 나눠 단위마다 후보 2~3개 → 최선 하나 → 가장 큰 흠 하나 고치고 고정
- 펀치 있는 줄은 페이지에 한두 개(보통 헤드라인과 한 섹션). 나머지는 평이하고 구체적인 서술문
- 고친 줄마다 "더 낫다고 말할 이유가 있나" 확인. 이유 없이 바뀐 줄은 되돌린다

## 전환 진단 순서 (영향 큰 순)
1. **5초 안에 무엇인지 알 수 있나**: 무엇을 해주는지, 누구에게, 왜 여기인지
2. **헤드라인**: 구체적인가, 유입 경로(검색어·광고·SNS 글)와 말이 맞나
3. **CTA**: 주 행동이 하나인가, 스크롤 없이 보이나, 버튼이 "제출"이 아니라 받는 것을 말하나("무료 진단 신청", "견적 받기", "맛보기 28쪽 받기")
4. **훑어보기**: 제목만 읽어도 흐름이 잡히나
5. **신뢰 근거**: 운영 중인 결과물 링크, 고객사(공개 동의분), 처리 규모 숫자를 CTA 근처와 주장 바로 뒤에
6. **반론 처리**: 가격, "내 상황에도 되나", "중간에 연락 끊기면", "납품 후 관리는" → FAQ·절차·보장으로
7. **마찰**: 문의 폼 항목 수(항목 하나마다 전환이 떨어진다), 모바일 화면, 다음 단계 안내 부재

## 섹션 뼈대 (소개·판매 페이지)
| 섹션 | 역할 |
|---|---|
| 히어로 | 지금의 불편 → 바뀐 모습 → 행동. "이제 OO할 수 있다"로 바꿔 읽어 말이 되는지 확인 |
| 신뢰 근거 | 고객사, 운영 중 서비스, 숫자 |
| 문제 | 고객이 쓰는 말로 상황 묘사 |
| 해결·결과 | 기능 말고 결과 3~5개 |
| 진행 절차 | 3~4단계로 복잡함을 덜어준다 |
| 반론 처리 | FAQ, 보장, 비교 |
| 마지막 CTA | 가치 요약 + 같은 CTA 반복 + 위험 줄이는 한 줄 |

## 문구 규칙
- 쉬운 말: "활용" 대신 "쓰다", "최적화" 대신 실제로 줄어든 숫자
- 구체적: "업무 시간 절감" 대신 "주간 보고 4시간 → 15분"(실측된 것만)
- 능동형, 단정형. "다소", "매우", "정말" 빼기
- 느낌표 쓰지 않는다
- AI티 금지 목록은 mkt-humanize를 따른다(특히 "단순히 A가 아니라 B입니다", "결과는? ~", 부정 나열, 끝에 덧붙이는 꼬리 구절, em-dash)

## 결과물 형식
- 부분 수정(C): 바뀐 줄만, 이유 한 줄씩
- 전체 작성: 섹션별 문구 → 주요 선택의 이유 → 헤드라인·CTA 대안 2~3개(근거 포함) → 필요하면 title·meta description
- 진단 요청: 바로 고칠 것 / 크게 고칠 것 / 시험해볼 가설 / 대안 문구
